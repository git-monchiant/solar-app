# SLA ติดตั้ง: เริ่มจากวันนัด จบที่วันติดตั้งจริง

วันที่: 2026-08-20
สถานะ: done

## ปัญหา

SLA `INSTALLATION` ("ติดตั้ง ทดสอบระบบ และส่งมอบงาน") วัดงานของทีม Solar
แต่ทั้งจุดเริ่มและจุดจบไม่ได้ชี้ไปที่งานนั้น

| | เดิม | ปัญหา |
| --- | --- | --- |
| เริ่ม | `deposit_at` — ยืนยันเงินมัดจำ | ลูกค้าที่ขอนัดติดตั้งไปอีกหลายสัปดาห์ทำให้นาฬิกาของทีมเดินทิ้งโดยไม่มีใครทำอะไรได้ — **26 จาก 38 ใบที่ยังเปิดอยู่ขึ้นเป็นเกินกำหนดด้วยเหตุนี้** |
| จบ | `install_completed_at` — เวลาที่กดปุ่ม "ติดตั้งเสร็จ" | เป็น audit timestamp ไม่ใช่วันที่ทำงานจริง บน Development **ทุกใบที่มีทั้งสองค่าไม่ตรงกัน** |

`install_actual_date` คือวันที่ทีมกรอกว่าติดตั้งจริง และคอมเมนต์ใน
`src/app/api/(lead)/leads/[id]/route.ts` ระบุเองว่าเป็น display source of truth
แต่ไม่เคยถูกใช้ทั้งใน SLA และใน Timeline

## กติกาใหม่ (policy version 3)

- **เริ่ม** ที่ช่วงเวลานัดติดตั้ง: `install_date` + เวลาเริ่มของ `install_time_slot`
  (ตอนนี้ยังไม่มีใบไหนกรอก slot จึงเป็นเที่ยงคืนตามเวลาไทย)
  ใบที่ไม่เคยนัดวันเลยยังใช้ `deposit_at` เหมือนเดิม
- **จบ** ที่ `install_actual_date` — ถ้าปุ่มถูกกดวันเดียวกันก็ใช้เวลาที่กดจริง
  ถ้าคนละวันให้ปิดที่สิ้นวันนั้น เพราะรู้แค่ระดับวัน และการปิดที่ 00:00
  จะกลายเป็นว่างานเสร็จก่อนทีมไปถึง
  ใบที่ไม่ได้กรอกวันติดตั้งจริงยังใช้เวลาที่กดปุ่มเป็นหลักฐานเดียว
- ถ้าวันที่ปิดงานอยู่**ก่อน**ช่วงนัดของตัวเอง แปลว่าตารางถูกแก้ย้อนหลัง
  จะถอยไปใช้ anchor เดิมแทนการรายงานเวลาติดลบ — กติกาเดียวกับที่
  `SITE_SURVEY` ใช้อยู่ตั้งแต่ migration 155

รูปแบบทั้งหมดลอกมาจาก `SITE_SURVEY` ซึ่งแก้ปัญหาเดียวกันนี้ไปแล้ว
และ anchor ถูก freeze หลังปิดงานเช่นกัน เพื่อไม่ให้การแก้วันนัดย้อนหลัง
ไปเปลี่ยนคำตัดสินที่ออกไปแล้ว

## การแสดงผลที่ต้องแก้ตามมา

พอ SLA ปิดที่วันติดตั้งจริง ขั้น Install มีสามค่าเวลาที่พูดถึง "ติดตั้งเสร็จ"
คนละอย่างกัน และเผลอแสดงพร้อมกันจนขัดแย้งกันเอง

| ค่า | Lead 691 | คืออะไร |
| --- | --- | --- |
| `install_actual_date` | 10 ก.ค. | วันที่ทีมบอกว่าติดตั้งเสร็จจริง |
| SLA `completed_at` | 10 ก.ค. 23:59 | จุดปิดนาฬิกา = สิ้นวันของวันข้างบน |
| `install_completed_at` | 11 ก.ค. 13:17 | เวลาที่กดปุ่ม "ติดตั้งเสร็จ" ในระบบ |

แก้สามจุด:

1. แถว "ติดตั้งเสร็จสิ้น" ที่สร้างจาก `install_completed_at` ไม่แสดงแล้ว
   เมื่อมี `install_actual_date` — ไม่งั้นจะมีวันเสร็จสองวันวางติดกัน
   ใบที่ไม่เคยกรอกวันติดตั้งจริงยังได้แถวนี้เป็นหลักฐานเดียวเหมือนเดิม
2. แถว SLA พิมพ์เฉพาะวันเมื่อเวลาเป็น 23:59 หรือ 00:00 ซึ่งเป็นเครื่องหมายว่า
   ค่านั้นรู้แค่ระดับวัน การพิมพ์ "23:59" ทำให้ดูเหมือนเป็นเวลาที่บันทึกไว้จริง
3. แถวในกลุ่ม "ประวัติการแก้ไขนัด" เติมคำว่า "บันทึก" หน้าเวลา เพราะชื่อแถว
   มีวันที่นัดอยู่ในตัวแล้ว — "นัดติดตั้ง 9 ก.ค. · บันทึก 6 ก.ค. 10:36"
   อ่านออกทันทีว่าวันไหนคือวันไหน
