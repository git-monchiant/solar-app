## 1. Pipeline ติดป้าย "เลยนัดแล้ว" ผิด

Lead 1038 ปรีชา (กรีนวัลเล่) นัดวันที่ 26 ส.ค. ซึ่งคือวันนี้ ตรวจพร้อมกันสองหน้าเมื่อ 16:14 น.

| หน้า | ข้อความ | สี |
| --- | --- | --- |
| Today | `นัดลูกค้า 26 ส.ค.` | เทา |
| Pipeline | `นัดลูกค้า 26 ส.ค. · เลยนัดแล้ว` | ส้ม |

`/api/leads` ไม่เคยส่ง `is_followup_overdue` มา `LeadCard` จึงตกไปใช้สูตรสำรองฝั่ง
browser ที่เทียบกับ **เที่ยงวัน** ผลคือหลังเที่ยงของทุกวัน นัดของวันนั้นกลายเป็น
"เลยนัด" ทันที และสูตรสำรองยังไม่ได้เช็คอีกสองข้อที่ฝั่ง SQL เช็คไว้

| ข้อ | กติกาฝั่ง SQL (Today) | สูตรสำรอง (Pipeline เดิม) |
| --- | --- | --- |
| 1 | ต้องเลย **วัน** ที่นัดจริง ๆ | เทียบกับเที่ยงวัน |
| 2 | ไม่นับ status `install` / `lost` | ไม่เช็ค |
| 3 | ถ้าตามไปแล้วตั้งแต่วันนัด ไม่ถือว่าค้าง | ไม่เช็ค |

ผลกระทบวันที่ตรวจ: Lead ที่นัดวันนี้ **28 ราย** และ Lead ที่ยกเลิกไปแล้วอีก **110 ราย**

### ที่แก้

- ย้ายนิพจน์ไป `src/lib/lead-followup-sql.ts` เป็นที่เดียวของทั้งระบบ
  พร้อม `LAST_FOLLOW_UP_APPLY` ให้ query ที่ไม่มี `act` join แบบ `/api/today` ใช้ได้
- `/api/today` เรียกผ่าน helper — ก้อน SQL เดิม ผลลัพธ์เดิม
- `/api/leads` เพิ่มคอลัมน์ `is_followup_overdue` ทุกหน้าที่ใช้ `LeadCard` ได้ตามไปด้วย

## 3. รอบปรับเพิ่ม — จัดแถวให้เหมือน Today และเติมตัวกรองย่อย

ผู้ใช้เทียบสองหน้าแล้วชี้ว่า Pipeline ยังต่างจาก Today อยู่สองจุด

### ย้ายปุ่มเรียงลงมาอยู่แถวเดียวกับชิป

เดิมปุ่มเรียงอยู่ใน `tabsRight` ของ `ListPageHeader` ซึ่งวางต่อท้ายแถบแท็บ
Pipeline มี 13 แท็บ ปุ่มเรียงจึงไปเบียดจนแท็บท้าย ๆ ถูกตัด ขณะที่แถวชิปด้านล่าง
ว่างครึ่งขวา ย้ายลงมาชิดขวาของแถวชิปแทน

ผลพลอยได้: `tabsRight` เป็น `hidden md:flex` แปลว่าบนมือถือเดิม **เรียงไม่ได้เลย**
ย้ายมาอยู่ในแถวที่ `flex-wrap` แล้วใช้ได้ทุกขนาดจอ

### เติมปุ่ม "ตัวกรองย่อย"

รอบแรกตั้งใจไม่ยกมาเพราะคิดว่าแท็บสถานะของ Pipeline แทนการกรองขั้นตอนได้อยู่แล้ว
ซึ่งไม่จริง — แท็บคือ **สถานะของ Lead** (รอสำรวจ, รอติดตั้ง) ส่วนขั้นตอน SLA คือ
**งานที่ค้างอยู่** คนละแกนกัน ในแท็บ ทั้งหมด (547) ยิ่งไม่มีอะไรช่วยซอยเลย

- แยก popover ไป `src/components/sla/SlaSubFilter.tsx` เก็บ state เปิด/ปิดกับ
  click-outside ไว้ในตัวเอง ทั้งสองหน้าส่งมาแค่จำนวนตัวกรองที่เปิดกับ `<select>` ข้างใน
- Today ตัด `slaSubOpen`, `slaSubRef` และ effect click-outside ออกได้ ไม่ต้องสั่งปิด
  popover เองแล้วเพราะพอ `slaStatusMode` เป็น false ปุ่มจะ unmount ไปเอง
- Pipeline มีสอง select: ขั้นตอน SLA กับ ผู้รับผิดชอบ (มี "ยังไม่มอบหมาย")
  ไม่มี Sales/Solar แยกกันเหมือน Today เพราะ `/api/leads` ส่ง owner มาตัวเดียว
  (ข้อนี้เปลี่ยนอีกรอบในหัวข้อ 4 — ผู้ใช้ขอให้เหมือน Today ไปเลย)

ตัวกรองย่อยมีผลกับ **ตัวเลขบนชิปด้วย** ไม่ใช่แค่รายการที่แสดง ตัวเลขจึงยังบอกความจริง
(Today ทำแบบนี้อยู่แล้วผ่าน `filteredSlaItems`) แต่ Lead ที่ไม่มี SLA ปล่อยผ่าน
ไม่งั้นชิป "ไม่มีงาน SLA" จะกลายเป็น 0 ทันทีที่เลือกขั้นตอน

### สิ่งที่ตั้งใจไม่จำข้ามรอบ

## 4. ทำตัวกรองย่อยให้เหมือน Today ทุกอย่าง

ผู้ใช้ถามว่า "ตัวกรองย่อยถ้ามีให้เหมือนกับ today เลย จะดีไหม" — ดีกว่าจริง เพราะ
select เดียวที่รวมทุกทีมตอบคำถามที่คนถามจริง ๆ ไม่ได้ "Solar ยังไม่มอบหมาย" กับ
"Sales ยังไม่มอบหมาย" เป็นงานคนละกองและคนละคนตาม แต่ของเดิมยุบเป็นตัวเลือกเดียว

| | ก่อน | หลัง |
| --- | --- | --- |
| select | ขั้นตอน + ผู้รับผิดชอบรวมทุกทีม | ขั้นตอน + Sales + Solar (เหมือน Today) |
| เทียบด้วย | ชื่อ (ชื่อซ้ำกันชนกันได้) | `owner_user_id` |
| เลือกพร้อมกัน | – | Sales กับ Solar เลือกได้ทีละทีม เหมือน Today |
| ใครเห็น | ทุกคน | `admin`/`sales_sup` เห็นของ Sales · `admin`/`solar_sup` เห็นของ Solar |

- `/api/leads` เพิ่ม `sla.owner_user_id as sla_owner_user_id` จะได้กรองด้วย id
  ตรงกับ Today ไม่ใช่เทียบชื่อ

### สองจุดที่ยังต่างจาก Today โดยตั้งใจ

1. **ไม่ยัดรายชื่อทีม Solar ทั้งทีมเข้ามาในตัวเลือก** — Today ทำเพราะหน้านั้น
   มอบหมายงาน Solar ได้ ต้องเลือกคนที่ยังไม่มีงานได้ ส่วน Pipeline มอบหมายไม่ได้
   คนที่ไม่มีงาน SLA จึงเป็นตัวเลือกที่กดแล้วว่างเปล่า
2. **ล้างค่าเมื่อ role ไม่ผ่านเกณฑ์ ด้วยการคิดสดแทน `useEffect`** — Today ใช้
   effect เรียก setState ซึ่ง `react-hooks/set-state-in-effect` ห้ามไว้ (Pipeline
   ติด lint ทันที) เลยคิดค่าที่ใช้จริงตอน render แทน ได้ผลเดียวกันและไม่มีเฟรม
   ที่ยังกรองด้วยค่าเก่า

## 5. เก็บสัดส่วนบน Lead Card

### กล่อง SLA แคบลง 26rem → 22rem

วัดของจริงแล้วกล่องกว้าง 416 px แต่บรรทัดที่ยาวที่สุดที่เป็นไปได้คือ
`ขั้นตอน: จัดส่ง Proposal พร้อม ROI และทางเลือกการเงิน` = 293 px
บวก padding 32 px ก็ต้องการแค่ 325 px ที่เหลือเป็นที่ว่างเปล่า

ตั้งเป็น 22rem (352 px) เหลือที่ให้บรรทัดยาวสุด 318 px — เกินพอ 25 px
คืนความกว้างให้เนื้อการ์ด 64 px · มีผลเฉพาะจอ `2xl` (≥1536) ที่วางกล่องไว้ข้าง ๆ
จอแคบกว่านั้นกล่องอยู่ใต้การ์ดเต็มความกว้างเหมือนเดิม

ตรวจแล้วบรรทัด "ขั้นตอน" 70 บรรทัดในหน้า Today และ 16 บรรทัดที่เป็น Proposal
(ตัวยาวที่สุด) ไม่มีบรรทัดไหนตกบรรทัด

### ตัวเลข "เกิน N วัน" ใต้ไอคอนขั้นตอน ใหญ่ขึ้น

เดิม `text-[9px]` เป็นค่าดิบ ไม่ได้อยู่ในสเกลของโปรเจกต์ที่ `text-xxs` = 16 px
บนเดสก์ท็อป ตัวเลขจึงเล็กกว่าป้ายขั้นตอนเหนือมันเกือบครึ่ง

เปลี่ยนเป็น `text-[11px] lg:text-[13px]` — ใหญ่ขึ้น 22-44% แต่ยังอยู่ใต้ป้าย 16 px
ที่ไม่ให้ใหญ่กว่านี้เพราะช่องขั้นตอนกว้างแค่ 36/44/48 px ตามจอ ถ้าอยากใหญ่กว่านี้
ต้องขยายช่อง (`w-9 lg:w-11 xl:w-12`) ด้วย ซึ่งจะดันความกว้าง tracker ทั้งแถว

| จอ | ฟอนต์ | กว้างข้อความ | กว้างช่อง | เหลือ |
| --- | --- | --- | --- | --- |
| 768 | 11 px | 29 | 36 | 7 |
| 1024 | 13 px | 34 | 44 | 10 |
| 1280+ | 13 px | 34 | 48 | 14 |

ไม่มีช่องไหนล้นไปทับช่องข้าง ๆ · page overflow 0 · console error 0

> **ชื่อปุ่มเปลี่ยนแล้ว** — ปุ่ม "ตัวกรองย่อย" ที่เอกสารนี้อ้างถึง ตอนนี้ใช้ชื่อ "ตัวกรอง" เฉย ๆ ทั้งหน้า Today และ Pipeline (26 ส.ค.)
