## บันทึกการทำ

### กลุ่ม 1 + 2 (28 ก.ย. 69)

- **ตั้งค่า O&M** — `Header` + แถบแท็บใต้หัว (คลาสแถวแท็บของ ListPageHeader) · เลขค้างตัดสินยังสีส้มตามเดิม
- **เช็คลิสต์** — `ListPageHeader` (ค้นหาในเครื่อง · แท็บ วันนี้/ยังไม่ปิดงาน/ปิดแล้ว · ตัวเลขนับหลังค้นหา) · งานเป็นการ์ดเปลือก LeadCard จัดกลุ่มตามวัน
  ไม่ใช้ JobCard ตรง ๆ เพราะ JobCard กินข้อมูลรายบ้าน (สิทธิ์/ผลโทร) ส่วนหน้านี้เป็นรายใบงานของช่าง
- **ลูกค้า** — ยกโครงหน้าบ้าน: ListPageHeader + ตัวกรองเป็นแท็บ (ไม่มีตัวเลข เพราะ API คืนยอดเฉพาะแท็บที่เลือก — ตัวเลขอยู่ tabsLeft)
  ตาราง/การ์ดกดทั้งแถว ปุ่มแก้ไข → ลูกศร · ท้ายตารางเลขหน้า + เลือกจำนวนต่อหน้า · ไม่มีแถวเครื่องมือ (หน้าบ้านมีไว้วาง dropdown โครงการ)
  **แก้บั๊กระหว่างทาง:** ปุ่ม "ลบถาวร/ซ่อนลูกค้า" เดิมกดแล้วลบทันทีไม่ถาม → ยืนยันด้วย dialog ก่อน
- **dialog** — houses 3 · line-oa 2 · inbox 1 เปลี่ยนเป็น `useDialog` (มี title + variant) · ตรวจแล้วไม่เหลือ confirm()/alert() ในโมดูล O&M
- **ปฏิทิน** — Header + แท็บ + toolbar (‹ › วันนี้ · เดือน · N งาน · ปุ่มสลับ) อยู่ใน Header แบบ /calendar · state ของ toolbar ยกขึ้นระดับหน้า
  desktop เพิ่มมุมมอง "รายการ" (ลิสต์เดียวกับมือถือ แถววันนี้ไฮไลต์) · แผงงานของวันที่เลือกไม่โผล่ในมุมมองรายการ (ซ้ำ)
- **เก็บตก:** ชื่อทีมขึ้น "ทีม ทีม A" (ชื่อในฐานมีคำว่าทีมอยู่แล้ว) — เพิ่ม `teamLabel()` ใน service-view ใช้ใน JobCard · JobDetail · เช็คลิสต์
- ตรวจ: tsc/eslint ผ่าน (line-oa มี error เดิม 2 จุดบรรทัด 444 ไม่เกี่ยวกับที่แก้) · ถ่ายจอ 1440/390 ไม่มี console error

### กลุ่ม 3 (28 ก.ย. 69)

- **ข้อ 6 แท็บ** — ปุ่มแท็บยกจากหน้า lead (คลาส · ไอคอน · มือถือโชว์ชื่อเฉพาะแท็บที่เลือก) · กดราง STEPS = กลับแท็บ Workflow
  - `components/om/HouseSystemCard.tsx` — **ย้าย**ชนิด Detail + การ์ดระบบ + ที่มาข้อมูลออกจากหน้าบ้าน (ไม่ได้ก๊อป) ใช้ร่วม modal บ้าน + แท็บ Equipment
  - `components/om/HouseTabs.tsx` — House Info (บ้าน · ลูกค้า · สิทธิ์) · Equipment · Photos · เปลือกการ์ดยกจากแท็บ info ของ lead
  - **แสดงอย่างเดียว** — ปุ่ม "แก้ไขข้อมูลบ้าน ›" เปิดแท็บใหม่ `/om/houses?house=<id>` (หน้าบ้านเปิด modal ให้เอง) กันกติกาแก้/ตัดสิทธิ์/ซ่อน/ลบมีสองที่
  - Photos ไม่มี API ใหม่ — ใบงานทุกใบจากไทม์ไลน์ของบ้าน แล้วอ่าน `/api/om/jobs/<id>/report` ทีละใบ · lightbox เดียวทั้งบ้าน (ลำดับตรงกับที่วาด)
- **ข้อ 7 Note** — modal ยกจาก AddActivityModal โหมด note · API ใหม่ `POST /api/om/houses/[id]/note` เขียน action `note` ลง `om_booking_history`
  (ไม่มีตาราง/migration ใหม่ · ช่อง action ไม่มี CHECK) · ผูกใบงานล่าสุดถ้ามี · ตรวจใบงานต้องเป็นของบ้านนั้น · ≤300 ตัวอักษร
  - **Follow-up ไม่ทำ** — ของ O&M คือ "นัดโทรใหม่" ในขั้นติดตาม (ผลโทร = เลื่อน) อยู่แล้ว · ปุ่มแยกที่หัวหน้าจะเขียนผลโทรซ้อนตอนงานอยู่ขั้นอื่น
- **ข้อ 8 Reschedule** — แถบนัดยกจากขั้นย่อย "นัด" ของ Install (ม่วง = นัดแล้ว · เขียว = ยืนยันแล้ว) · ปุ่มโผล่เฉพาะ pending/confirmed
  - `components/om/OmRescheduler.tsx` — หน้าตา/ลำดับของ AppointmentRescheduler แต่ช่วงเวลา+ความจุจาก `om_slot_config` (ตัวฝั่งขายนับคิวจากปฏิทิน lead ใช้ไม่ได้)
    ช่องเต็มยังกดได้แต่เลขแดง (แบบลากในปฏิทิน) · ไม่นับใบยกเลิก/ไม่อยู่บ้าน · บันทึกผ่าน PATCH เดิม (ลงประวัติ "เลื่อนนัด" + เหตุผล)
  - ⚠ **เจอระหว่างทาง:** กติกาเลื่อนนัดในหน้าตั้งค่า (`reschedule.max_times` · `reset_to_pending` · `unassign_team` · `min_hours_before`) **ยังไม่มี API ไหนบังคับใช้เลย**
    เลื่อนจากหน้านี้จึงทำตัวเหมือนลากในปฏิทิน (ของเดิม) — ต้องให้ผู้ใช้เคาะว่าจะบังคับกับการเลื่อนโดยแอดมินด้วยไหม
- **เก็บตก** — หัวกล่องในใบตรวจ (แผน 20260928-03) บนมือถือชื่อไทยลงบรรทัดใหม่ (เดิมบีบจนตัดคำ)
- ตรวจ (solardb_v3): tsc/eslint ผ่าน · API note: ว่าง/ไม่ล็อกอิน/ใบงานผิดบ้าน/ยาวเกิน/ไม่มีบ้าน ตอบ error ถูก · บันทึกผ่าน UI ภาษาไทยขึ้น Activity Log ทันที
  · เลื่อนนัดผ่าน UI กับใบทดสอบ #100 (สร้างชั่วคราว) → scheduled_at เปลี่ยน + ประวัติ reschedule มีเหตุผล · **ลบใบทดสอบ + ประวัติ + โน้ตทดสอบแล้ว**
  · modal หน้าบ้านหลังย้ายการ์ดระบบ + `?house=` เปิดตรงหลัง · ไม่มี console error

### ผู้ใช้เคาะ 28 ก.ย. 69 ("ทำตามแนะนำ") — 1 ก · 2 ค · 3 ค · 4 ข

**🐞 บั๊กที่เจอก่อนเริ่ม — รูปหน้างานไม่เคยแสดงเลย (แก้แล้ว)**
- `/api/om/jobs/[id]/photos/[file]` ตรวจสิทธิ์ด้วย header `x-user-id` (ไม่มี middleware/cookie) แต่ `<img src>` แนบ header ไม่ได้ ⇒ **403 ทุกรูป**
  พิสูจน์กับรูปจริงใบ #99: ไม่มี header = 403 · มี header = 200 image/png
- แก้ฝั่งหน้าเว็บ: `lib/hooks/useOmPhotoUrls.ts` ดึงรูปด้วย fetch ที่แนบ header → blob URL · ใช้ในช่องรูปของใบตรวจ + แท็บ Photos
  **ไม่ได้เปิดช่องให้ดูรูปโดยไม่ตรวจสิทธิ์** (ไม่ใช้ `?user_id=` แบบใบส่งมอบฝั่งขาย)

**ข้อ 4 ข — กติกาเลื่อนนัดใช้กับปุ่ม Reschedule**
- API ใหม่ `/api/om/bookings/[id]/reschedule` — GET บอกล่วงหน้าว่าจะเกิดอะไร · POST เลื่อนจริง
  - ผลที่ตามมาตามหน้าตั้งค่า: นัดแล้ว → **รอยืนยันนัด** (`reset_to_pending`) · **ปลดทีม + คิว** (`unassign_team`) · **แจ้งลูกค้าทาง LINE** ทุกบัญชีที่ผูกบ้าน (`notify_line`)
  - เพดาน (`max_times` · `min_hours_before`) **ไม่บล็อกทีมงาน แค่เตือน** และจดคำเตือนลง `to_json` ของประวัติ
  - ปิดแจ้งเตือน "ใกล้ถึงวันนัด" ของวันเดิม (ตัวตั้งเวลาเตือนวันใหม่เอง) · กันวันที่ผ่านมาแล้ว/เวลาเดิม/งานที่เริ่มแล้ว
  - LINE ส่งหลัง commit ไม่ทำให้การเลื่อนล้ม · เก็บลงประวัติแชตกติกาเดียวกับหน้าแชต (LINE เปิดแต่ส่งไม่ออก = ไม่จด)
- ฟอร์มเลื่อนนัดโชว์กล่อง "เมื่อยืนยันเลื่อนนัด" (ผลที่จะเกิด + คำเตือน) ก่อนกด · toast บอกผลแจ้ง LINE ตามจริง
  · เลือกวันย้อนหลังไม่ได้ · ช่วงเวลาที่เริ่มไปแล้วของวันนี้กดไม่ได้
- **การลากในปฏิทินคงเดิม** (PATCH เดิม ไม่มีผลตามมา) — ใส่กติกาที่นั่นแล้วลากย้ายช่องครั้งไหนทีมหลุดทุกครั้ง
- ตรวจ (solardb_v3 · ใบทดสอบ #101 นัดแล้ว ทีม A บ้านผูก LINE 1 บัญชี · LINE ปิดอยู่ในเครื่อง dev จึงไม่ส่งจริง):
  เลื่อนผ่านหน้าจอ → pending · ทีมหลุด · นับ 1 · ประวัติมี from/to ครบ · ข้อความ LINE ถูกจด (pushed=false) · toast "LINE ยังไม่เปิดใช้"
  · เลื่อนครั้งที่ 3 ได้แต่เตือน "เกินที่ตั้งไว้ 2 ครั้ง" · วันย้อนหลัง/เวลาเดิม/ว่าง/งานเริ่มแล้ว/ไม่มีใบ ตอบ error ถูก · **ลบใบทดสอบ + ประวัติ + ข้อความแล้ว**
  · ⚠ ยังไม่ได้ทดสอบกับ LINE ที่เปิดจริง (ต้องตั้ง `OM_LINE_ENABLED` + token บนเครื่องที่มี channel ทดสอบ)

**ข้อ 1 ก — ใบบริการ PDF**
- `GET /api/om/jobs/[id]/doc` — puppeteer พิมพ์ A4 สูตรเดียวกับใบส่งมอบฝั่งขาย **แต่ไม่มีหน้า/API ข้อมูลสาธารณะ**
  (ของฝั่งขาย `/api/install-doc/[id]/data` เปิดได้โดยไม่ล็อกอิน — ใบนี้มีลายเซ็น + รูปบ้าน จึงไม่ทำแบบนั้น)
  route ตรวจสิทธิ์ อ่านข้อมูลเอง แล้วตอบคำขอของ puppeteer ผ่าน origin ภายใน: HTML · ฟอนต์ DB Heavent จาก public/fonts · รูปจากที่เก็บ
  คำขออื่นถูกตัดทั้งหมด (เอกสารไม่ออกไปโหลดอะไรข้างนอก) · รูปขอได้เฉพาะไฟล์ในรายการของใบงานนั้น
- `lib/om/job-report.ts` — ย้ายการอ่านใบ (เลือกใบตรวจ + ข้อมูลใบงาน) ออกจาก API ใบตรวจ ใช้ร่วมกับ PDF ⇒ ข้อมูลตรงกับหน้าจอเสมอ
- `lib/om/service-doc.ts` — HTML ของใบ: หัวบริษัท · เลขเอกสาร · CUSTOMER INFORMATION · หมวดตามใบในฐาน (ติ๊ก SVG) · พบงานซ่อม
