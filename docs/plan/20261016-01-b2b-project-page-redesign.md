# หน้าโครงการ B2B — ปรับ flow ให้อ่านง่าย ทันสมัย

สถานะ: **in-progress** — ผู้ใช้เลือก A + C เฉพาะ B2B (16 ต.ค. 69) · โค้ดเสร็จแล้ว เหลือทดสอบกับ DB จริง (ดู "ผลการทำ" ท้ายไฟล์)
mockup: [docs/mockup/20261016-01-b2b-project-page-redesign/](../mockup/20261016-01-b2b-project-page-redesign/index.html) มีแบบ A / B / C และแบบมือถือ สลับดูได้ในหน้าเดียว

## ที่มา

ผู้ใช้ถามเมื่อ 16 ต.ค. ว่า "ลอง design flow ของ Project ให้ดูง่ายทันสมัย มีแนวคิดอย่างไรบ้าง ยังไม่ต้องแก้โค้ด" แล้วขอ mockup ให้เลือก
หน้า `/b2b/projects/[id]` ตอนนี้ยกโครงมาจากหน้าลีด B2C คือมีรางขั้นด้านซ้าย การ์ดขั้น (`ProjectStepCard`) เรียงลงมา 9 ใบ และ Activity Log ด้านขวา

## ปัญหาที่เห็น (หน้าจริง PRJ2610-001 ขั้น 04)

1. งานที่ต้องทำอยู่ครึ่งล่างจอ เพราะการ์ดขั้นที่เสร็จแล้ว 3 ใบกินพื้นที่ราว 40% ปุ่ม "ได้งาน" เลยไปตกขอบล่าง
2. ความคืบหน้าโชว์ซ้ำ 3 ที่ คือรางซ้าย การ์ด และป้ายใน header ส่วนรางซ้ายใช้ตัวหนังสือ 10px อ่านไม่ออก
3. ปุ่ม "ได้งาน" เป็นสีจางแต่ไม่บอกว่ายังขาดอะไร (บอกแค่ใน tooltip) คำอธิบายไปอยู่ในกล่องเส้นประ
4. ตัวเลขหลัก (kWp · ราคา · Margin) เป็นตัวเทาเล็กอยู่ใน header
5. 9 ขั้นเรียงเป็นเส้นตรงเส้นเดียว แต่งานจริงมี 2 ช่วง คือขาย 01–05 และดำเนินโครงการ 06–09 ช่วงหลังมีงานเดินคู่ขนานกัน (ขออนุญาต · งวดเงินที่ผูกกับเหตุการณ์หน้างาน)
6. ป้ายใน header ขึ้น "· ร่าง" ทั้งที่ขั้น 04 ยังไม่มีใบยืนยัน น่าจะดึงสถานะมาจากใบประมาณการของขั้น 02 (`subLabel` ใช้ "ใบที่ขยับล่าสุด") ต้องตรวจก่อนแก้

## แบบที่เสนอ

### A · แถบขั้นแนวนอน + การ์ด "ขั้นต่อไป" (แนะนำ)
- ใช้แถบขั้นแนวนอนแบ่ง 2 ช่วง (ขาย / ดำเนินโครงการ) แทนรางซ้ายและการ์ดขั้นที่เสร็จแล้ว ใต้แต่ละขั้นที่เสร็จมีวันที่เสร็จ
- กดขั้นที่ผ่านมาแล้วเนื้อหาขั้นนั้นจะแสดงแทนที่ มีปุ่ม "กลับขั้นปัจจุบัน" · ชี้ขั้นที่ล็อกแล้วจะบอกว่าปลดเมื่อไร (ใช้ `LOCKED_HINT` เดิม)
- การ์ด **"ขั้นต่อไป"** อยู่บนสุด เป็นเช็กลิสต์ว่ายังขาดอะไรก่อนไปขั้นถัดไป ปุ่มหลักวางในข้อที่ต้องทำตอนนี้ และบอก "อยู่ขั้นนี้กี่วัน"
- header แสดงตัวเลขหลักเป็นกล่อง (kWp · ราคาขาย · Margin) · ปุ่มแพ้งาน / ยกเลิก / ถอยไปสำรวจซ้ำ / ข้ามสำรวจ ย้ายไปไว้ในเมนู ⋯
- Activity Log จัดกลุ่มตามวัน มีไอคอนตามประเภท และมีตัวกรอง (ทั้งหมด / บันทึก / เปลี่ยนขั้น / เอกสาร)

### B · ไทม์ไลน์แบบย่อ (แก้น้อย)
- ขั้นที่เสร็จเหลือแถวละบรรทัดเดียว กดเพื่อกางดูได้ · ขั้นที่ยังล็อกรวมไว้บรรทัดเดียว · ตัดรางซ้ายออก
- ข้างปุ่มหลักบอกว่ายังขาดอะไร และมีป้าย "อยู่ขั้นนี้กี่วัน"
- หน้าตายังใกล้หน้าลีด B2C แต่ยังเรียงยาวแนวตั้ง และช่วง 06–09 ยังอ่านยาก

### C · ตารางงานคู่ขนาน (เนื้อหาของ A ในช่วง 06–09)
- คอลัมน์คือขั้น 06–09 · แถวคือ หน้างาน (milestone) / ขออนุญาต / งวดเงิน · ข้อที่ทำให้งวดถึงกำหนดมีป้าย "งวด N"
- ด้านล่างมีแถบเงิน: รับแล้ว / รอบัญชี / ยังไม่ถึง เทียบกับมูลค่าสัญญารวม VAT
- การ์ด "ขั้นต่อไป" บอกงานที่รอคนอื่นด้วย เช่น "รอบัญชียืนยันงวด 2"
- บนมือถือต้องเปลี่ยนเป็นรายการทีละแถว

### มือถือ (แบบ A)
- แถบขั้นย่อเหลือแถบความคืบหน้า "ขั้น 4/9" กดแล้วขึ้นแผ่นล่างที่รวมรายการทุกขั้น (ขั้นที่เสร็จแล้วกางดูได้)
- ปุ่มหลักของขั้นอยู่แถบท้ายจอแบบ `sticky bottom-0` ส่วนปุ่มรองอยู่ใน ⋯ · ตาราง BOQ เปลี่ยนเป็นการ์ด

## ข้อเสนอ

ใช้ **A เป็นโครงหลัก แล้วใส่ C เป็นเนื้อหาช่วง 06–09** ทั้งหมดใช้ข้อมูลเดิมจาก `GET /api/b2b/projects/[id]` ได้ ไม่ต้องแก้ API หรือ DB
- วันที่เสร็จแต่ละขั้นและ "อยู่ขั้นนี้กี่วัน" คิดได้จาก `activities` (`to_stage` + `created_at`)
- เงื่อนไขในเช็กลิสต์ใช้กติกาเดิม (`MILESTONES` ใน `execution.ts` · งวดเงิน · สถานะใบเสนอราคา) ไม่ต้องตั้งกติกาใหม่

## ต้องตัดสินใจ

1. เลือกแบบไหน: A + C / A อย่างเดียว / B
2. ถ้าเลือก A จะยกไปใช้หน้าลีด B2C ด้วยไหม เพราะตอนนี้สองหน้าหน้าตาเหมือนกัน (กติกา "ยกบล็อกเดิมมาใช้") ทางเลือกคือลองกับ B2B ก่อนแล้วค่อยตัดสินใจ
3. "อยู่ขั้นนี้กี่วัน" เกินกี่วันให้เปลี่ยนสีเตือน (เสนอเริ่มที่ 14 วัน ปรับรายขั้นได้ทีหลัง)
4. ป้าย "· ร่าง" ในข้อ 6 ของปัญหา แยกแก้ได้เลย ไม่ขึ้นกับว่าจะเลือกแบบไหน

## ลำดับงาน (ถ้าเลือก A + C)

1. เฟส 1 · โครงหน้า: header ใหม่ (กล่องตัวเลข + ⋯) · แถบขั้น · การ์ดขั้นต่อไปของขั้น 01–05 · ดูขั้นย้อนหลัง · Activity Log จัดกลุ่มตามวัน
2. เฟส 2 · ช่วง 06–09: ตารางงานคู่ขนาน + แถบเงิน + การ์ดขั้นต่อไปของ 06–09
3. เฟส 3 · มือถือ: แถบความคืบหน้า + แผ่นล่าง + แถบปุ่ม sticky
4. ตรวจ: `npx tsc --noEmit` · เปิดหน้าโครงการทุกขั้น (รวมแพ้งาน / ยกเลิก / ปิดโครงการ) · มือถือ 390px
