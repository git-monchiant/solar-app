  2. หน้ารายละเอียดงานบริการ — การ์ด 6 ขั้น · ใบเสนอราคา · ชำระเงิน · Follow-up · Timeline

## สรุป

ภาพรวม **กึ่งทางการ** ทุกกลุ่ม — ป้าย ปุ่ม หัวตาราง ส่วนใหญ่ (~70%) สั้นและใช้ได้ ไม่พบคำสะกดผิดแบบ ปฎิ / อนุญาติ
ปัญหาไปกองอยู่ที่คำอธิบาย คำแนะนำ ข้อความแจ้งเตือน และข้อความ error มี 5 แบบ เรียงตามความหนัก:

1. **ข้อความระบบหลุดถึงผู้ใช้** — ลูกค้าเห็น error อังกฤษดิบใน LINE · พนักงานเห็นรหัสสถานะดิบ (`payment`, `confirmed`) ·
   ชื่อตัวแปร / ไฟล์ (`REM_API_KEY`, `.env.local`, `has_solar=0`, `is_current`) · มี 44 จุดใน `src/app/api/om` ที่ส่ง `e.message` ตรงไปหน้าจอ
2. **คำภาษาพูดบนจอที่ใช้ทุกวัน** — หนักสุดคือแท็บ **"ไม่เอา"** และ **"เช็คเด้ง"** (~40 จุด) ที่เหลือ: ค้าง · ติ๊ก · เล่า · กวาด · ยิง · ชน · ถอด · โผล่ · เอากลับ · จด · คุย · ไม่รู้ · น่าจะใช่ · ทีหลัง · เลย
3. **คำแนะนำเขียนแบบโน้ตนักพัฒนา** — ใช้ `=` `→` แทนประโยค · คำถามชวนคุย "ลูกค้าเปลี่ยนใจ?" · อ้างปุ่มที่เอาออกไปแล้ว
4. **ไทย/อังกฤษปนไม่เป็นระบบ** — WORKFLOW / Follow-up / Note / Reschedule / ACTIVE / Revision / Master / LOADING… / Export CSV คู่กับหน้าต่างภาษาไทยของปุ่มเดียวกัน
5. **เรียกสิ่งเดียวกันหลายชื่อ** — ใบงาน / ใบตรวจ / ใบบริการ / เช็คลิสต์ · Sale / ทีมขาย / ฝ่ายขาย · Account / ฝ่ายบัญชี ·
   Solar Sup / Sale Sup ↔ Solar Manager / Sale Manager · แพ็กเกจ / แพ็คเกจ / Package

## ลำดับที่แนะนำถ้าจะแก้

1. ตัดสินใจ 8 ข้อด้านบน (โดยเฉพาะข้อ 1–4 ที่ใช้ร่วมกับฝั่งขาย) แล้วเติม glossary ให้เป็นฉบับจริง
2. **ฝั่งลูกค้าก่อน** (ตาราง 1) — เสนอถ้อยคำให้เลือก 3–4 ชุดก่อนแก้ ตรวจ PDF จริงว่าบรรทัดไม่ล้น
3. **ศัพท์ระบบหลุด** (ระดับสูงในตาราง 2–4) + error ดิบ 44 จุด — แก้เป็นข้อความกลาง
4. ไล่เปลี่ยนคำตาม glossary ทั้งโมดูล (ค้นด้วย grep ทีละคำ) — ป้ายที่บันทึกลงประวัติแล้ว (booking-log / rem-reconcile / customers houses) เปลี่ยนได้เฉพาะของใหม่ ของเก่าในฐานข้อมูลยังเป็นคำเดิม
5. ระดับต่ำทำทีหลังหรือรวมไปกับงานที่แตะไฟล์นั้น
