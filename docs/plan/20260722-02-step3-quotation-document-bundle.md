# Step 3 Quotation Document Bundle Plan

## Status

`backlog`

## เป้าหมาย

ต่อยอดระบบ Quotation ใน Step 03 ให้สร้าง “ชุดเอกสารเสนอขาย” ฉบับเดียว โดยเรียงรายงานสำรวจและข้อมูลประกอบไว้ด้านหน้า และแนบใบเสนอราคา 2 หน้าไว้ท้ายเอกสารเหมือนตัวอย่าง `รายงานสำรวจ-691-วรรณวิมล(1).pdf` การส่งอนุมัติ การส่งกลับแก้ไข การอนุมัติ Revision และการส่งลูกค้าให้ยึด Quotation เป็นแกนกลางทั้งหมด

แผนนี้เป็นงานต่อยอดจาก `20260722-01-quotation-system.md` และไม่สร้าง Approval workflow แยกสำหรับ Survey Report

## Confirmed Business Decisions

1. รายงานส่วนหน้าต้องคงโครงสร้างครบ 15 หน้าเสมอ แล้วจึงต่อท้ายด้วยใบเสนอราคา 2 หน้า รวมเป็นเอกสารมาตรฐาน 17 หน้า
2. ข้อมูลสินเชื่อ ตารางผ่อนชำระ ผลประหยัด และตัวเลขเปรียบเทียบทั้งหมดต้องคำนวณจากข้อมูลจริง ห้ามใช้ตัวเลขตัวอย่างหรือข้อความ placeholder ในเอกสารที่ส่งอนุมัติ
3. Sale Sup/Admin ที่กดอนุมัติเป็นผู้อนุมัติและรับรองความถูกต้องของเอกสารทั้งชุด ทั้งข้อมูล Survey ข้อเสนอ Package ราคา เงื่อนไขชำระเงิน และใบเสนอราคา

## ข้อสรุปจากเอกสารตัวอย่าง

- ไฟล์ตัวอย่างมีทั้งหมด 17 หน้า: รายงานหลัก 15 หน้า และใบเสนอราคา 2 หน้าอยู่ท้ายชุด
- เนื้อหาด้านหน้าครอบคลุมข้อมูลลูกค้า ภาพหน้างาน Load Assumption Package ที่แนะนำ รายการเพิ่ม Customer Journey ทางเลือกชำระเงิน/สินเชื่อ และเงื่อนไขทั่วไป
- หน้า 15 ทำหน้าที่เป็นใบคั่นภาคผนวก ก่อนต่อด้วยใบเสนอราคาฉบับจริง
- ข้อมูลราคาและเลขใบเสนอราคาปรากฏซ้ำหลายจุด จึงมีความเสี่ยงไม่ตรงกัน ตัวอย่างมีเลข `QT-260713` ในรายงาน แต่ใบเสนอราคาท้ายชุดเป็น `SM-QT-26-0057`
- ระบบใหม่ควรดึงเลขเอกสาร Package รายการ ราคา ส่วนลด เงินจอง VAT และงวดชำระจาก Quotation Revision เดียวกัน ห้ามกรอกซ้ำด้วยมือใน Report

## แนวคิดหลัก: Quotation Document Package

แต่ละ Quotation Option/Revision เป็นเจ้าของชุดเอกสารของตนเอง:

```text
Quotation Option + Revision
  -> Survey snapshot
  -> Commercial/report snapshot
  -> Quotation snapshot
  -> Approval event
  -> Combined approved PDF
```

- 1 Lead ยังสร้างได้สูงสุด 3 Quotation Options ตามระบบปัจจุบัน
- แต่ละ Option อาจมี Package และราคาต่างกัน จึงต้องสร้าง Combined PDF แยกกัน
- ข้อมูล Survey ที่เหมือนกันสามารถใช้เป็นต้นทางร่วมกันได้ แต่เมื่อกดส่งอนุมัติต้อง Snapshot ลงใน Revision นั้น
- สถานะของเอกสารทั้งชุดใช้สถานะ Quotation เดิม: `draft`, `pending_approval`, `changes_required`, `approved`
- Approved Revision ต้องแก้ทับไม่ได้ หากข้อมูล Survey, Package หรือราคาเปลี่ยน ให้สร้าง Revision ใหม่และขออนุมัติใหม่

## โครงสร้างเอกสารที่แนะนำ

### ส่วน A — รายงานสำรวจและข้อเสนอ

1. ปกเอกสาร: ลูกค้า สถานที่ วันที่สำรวจ ผู้สำรวจ และเลข Quotation
2. สารบัญ
3. ข้อมูลลูกค้าและโครงการ
4. รูปหน้างานและจุดติดตั้งอุปกรณ์
5. ผังติดตั้งหรือ Layout Sketch (ถ้ามี)
6. ข้อมูลไฟฟ้า สภาพหลังคา และ Load Assumption
7. Package ที่แนะนำ พร้อมเหตุผล
8. รายการเพิ่มจากสภาพหน้างาน
9. Customer Journey / ขั้นตอนถัดไป
10. ทางเลือกชำระเงินหรือสินเชื่อ เฉพาะข้อมูลที่ Sales เลือกให้ลูกค้ารายนั้น
11. หมายเหตุและเงื่อนไขทั่วไป

### ส่วน B — ภาคผนวกใบเสนอราคา

12. ใบคั่นภาคผนวก ระบุเลข Quotation, Revision, ยอดสุทธิ และวันหมดอายุ
13. ใบเสนอราคาปัจจุบัน 2 หน้า ซึ่งต้องอยู่ท้ายสุดเสมอ

รายงานด้านหน้าต้องมี 15 หน้าตาม Template มาตรฐานเสมอ และใบเสนอราคาต้องเป็นหน้า 16-17 อยู่ท้ายสุด หากข้อมูลหรือรูปมีจำนวนมากเกินพื้นที่ ต้องใช้กติกาจำกัดจำนวนรูป/ความยาวข้อความและแจ้ง Validation ให้ผู้จัดทำแก้ไข ห้ามปล่อยให้เนื้อหาไหลเพิ่มเป็นหน้าใหม่โดยอัตโนมัติ

## UX ใน Step 03

### การ์ด Quotation แต่ละชุด

เพิ่มสถานะความพร้อมของเอกสาร 3 กลุ่ม:

- `ข้อมูลสำรวจ`: พร้อม / ขาดข้อมูลสำคัญ
- `ข้อเสนอและราคา`: พร้อม / ยังไม่ครบ
- `เอกสารอนุมัติ`: ฉบับร่าง / รออนุมัติ / อนุมัติแล้ว / ส่งกลับแก้ไข

Actions ที่แนะนำ:

- `แก้ไขข้อมูลเสนอขาย`
- `ดูชุดเอกสาร PDF`
- `ส่งทั้งชุดขออนุมัติ`
- `อนุมัติทั้งชุด` หรือ `ส่งกลับแก้ไข`
- หลังอนุมัติ: `ดาวน์โหลดฉบับอนุมัติ`, `ส่งลูกค้า`, `สร้าง Revision`

### Document Composer

ภายใน Quotation Editor แบ่งเป็น Tab หรือ Accordion:

1. Package และราคา
2. ข้อมูลรายงานสำรวจ
3. รูปภาพและผังติดตั้ง
4. เหตุผลที่แนะนำ / รายการเพิ่ม
5. การชำระเงิน / สินเชื่อ
6. Preview เอกสารทั้งชุด

ระบบควรเติมข้อมูลจาก Survey step อัตโนมัติ แล้วให้ Sales แก้เฉพาะข้อความเชิงเสนอขายที่เป็นของ Quotation Revision โดยไม่แก้ข้อมูล Survey ต้นฉบับโดยไม่ตั้งใจ

## Approval Concept

### ผู้สร้างและผู้อนุมัติ

- Sales เจ้าของ Lead จัดทำและส่ง Quotation Document Package
- Sale Sup หรือ Admin ตรวจและอนุมัติทั้งชุดจาก Quotation เดิม
- ไม่เพิ่มปุ่ม Approve ที่ Survey step และไม่สร้าง Survey Approval อีกสถานะหนึ่ง
- การกดอนุมัติถือเป็นการรับรองความถูกต้องทั้ง Survey, Package, ราคา, เงื่อนไขชำระเงิน, ตารางสินเชื่อ และใบเสนอราคา ไม่ใช่อนุมัติเฉพาะส่วนลดหรือราคา

### สิ่งที่ผู้อนุมัติต้องเห็น

- PDF Preview ของชุดเอกสารจริงที่จะส่งลูกค้า
- Summary ด้านข้าง: Package, Add-on, ส่วนลด, เงินจอง, VAT, ยอดสุทธิ, งวดชำระ
- จุดเตือน Validation เช่น ขาดรูปหลัก ราคาใน Report ไม่ตรง Quotation หรือเลขเอกสารไม่ตรง
- Difference จาก Revision ก่อนหน้า โดยเฉพาะ Package ราคา ส่วนลด รายการเพิ่ม และข้อมูล Survey สำคัญ
- ช่องหมายเหตุเมื่ออนุมัติ และบังคับระบุเหตุผลเมื่อส่งกลับแก้ไข
- Checkbox ยืนยันก่อนอนุมัติว่าได้ตรวจสอบข้อมูล Survey ราคา เงื่อนไข และผลคำนวณสินเชื่อครบถ้วนแล้ว

### ผลของการอนุมัติ

- ล็อก Snapshot ทั้งรายงานและใบเสนอราคา
- ประทับชื่อ ตำแหน่ง ลายเซ็น และวันอนุมัติของผู้อนุมัติในใบเสนอราคาท้ายชุด
- เอา Watermark ออกจาก Combined PDF
- เก็บ Approved PDF artifact เพื่อให้เปิดครั้งใดก็ได้แล้วได้ไฟล์เดิม ไม่ regenerate จากข้อมูล Lead ที่อาจเปลี่ยนภายหลัง
- บันทึก Activity Log และ checksum/version ของไฟล์

## Data Model ที่ควรเพิ่ม

แนวทางที่แนะนำคือเพิ่ม Snapshot/Artifact ให้ผูกกับ `quotation_id` และ Revision เดิม:

- `quotation_document_snapshots`
  - `quotation_id`
  - `survey_snapshot_json`
  - `report_snapshot_json`
  - `generated_at`
- `quotation_document_artifacts`
  - `quotation_id`
  - `document_type` เช่น `draft_bundle`, `approved_bundle`
  - `file_url` หรือ binary storage reference
  - `file_hash`
  - `page_count`
  - `created_at`

หากต้องการลดตารางในระยะแรก สามารถเพิ่ม snapshot JSON และ approved file reference ใน `quotations` ได้ แต่การแยกตารางจะรองรับประวัติการ generate และ audit ได้ชัดกว่า

## PDF Generation Strategy

1. Render ส่วนรายงานจาก Template ใหม่ โดยใช้ Survey data + Quotation snapshot
2. ใช้ Quotation PDF generator ปัจจุบันสร้างใบเสนอราคา 2 หน้า
3. Merge ด้วย `pdf-lib` ให้รายงานอยู่หน้าแรกและ Quotation อยู่ท้ายสุด
4. ควบคุม Report template ให้ได้ 15 หน้าคงที่ และ merge กับ Quotation 2 หน้าเป็น 17 หน้า
5. ใส่เลขหน้า ชื่อไฟล์ และ metadata หลัง merge
6. ตรวจ page count ก่อนส่งอนุมัติ หากไม่เท่ากับ 17 หน้าให้ถือว่า generate ไม่สำเร็จ
7. Draft/Pending ใช้ Watermark ทั้งชุด
8. เมื่ออนุมัติแล้ว Generate หนสุดท้ายหนึ่งครั้ง เก็บเป็น immutable artifact

ชื่อไฟล์แนะนำ:

```text
SM-QT-26-0057_วรรณวิมล_Rev0.pdf
```

## Validation ก่อนส่งอนุมัติ

### Blocking

- Quotation ยังไม่มี Package หรือยอดคำนวณไม่สมบูรณ์
- ไม่มีข้อมูลลูกค้า/สถานที่ติดตั้งที่จำเป็น
- ไม่มีวันที่สำรวจหรือผู้สำรวจ
- เลข Quotation ในทุกส่วนไม่ตรงกับ Revision ปัจจุบัน
- ยอด Package/ส่วนลด/เงินจอง/VAT/ยอดสุทธิใน Report ไม่ตรงกับ Quotation snapshot
- รายงานไม่ได้ 15 หน้า หรือ Combined PDF ไม่ได้ 17 หน้า
- ตารางสินเชื่อหรือผลประหยัดยังมีข้อมูลตัวอย่าง/placeholder หรือคำนวณไม่ครบ
- แหล่งข้อมูลสินเชื่อ อัตราดอกเบี้ย ระยะเวลา และวันที่มีผลของข้อมูลไม่ครบ
- ไม่มีลายเซ็นผู้อนุมัติใน Profile ตอนกดอนุมัติ

### Warning แต่ยังส่งได้

- รูปหน้างานหลักบางหมวดไม่ครบ
- ไม่มี Layout Sketch
- Load Assumption ไม่ครบทุกช่อง
- ไม่มีทางเลือกสินเชื่อ เฉพาะกรณีที่ Quotation ระบุว่าไม่ใช้สินเชื่อ

## Financial Calculation Requirements

- สร้าง Financial/Loan Calculator เป็น service กลาง ไม่คำนวณแยกในหน้า PDF
- Inputs ขั้นต่ำ: ยอดสุทธิ เงินดาวน์/เงินจอง วงเงินกู้ อัตราดอกเบี้ยแต่ละช่วง อายุสัญญา ค่าไฟปัจจุบัน ขนาดระบบ ผลผลิตไฟประมาณการ และค่าไฟต่อหน่วย
- Outputs ขั้นต่ำ: ค่างวด วงเงินกู้ ยอดชำระรวม ดอกเบี้ยรวม เงินประหยัดต่อเดือน จุดคุ้มทุน และประมาณการประหยัดระยะยาว
- เก็บ input, output, สูตรเวอร์ชัน, แหล่งข้อมูลอัตราดอกเบี้ย และวันที่คำนวณลงใน Quotation snapshot
- ผลในหน้ารายงาน Preview, Approval summary และ Approved PDF ต้องมาจาก calculation snapshot เดียวกัน
- หากมีการเปลี่ยนอัตราดอกเบี้ยหรือ input สำคัญหลังส่งอนุมัติ ต้องสร้าง Revision และคำนวณใหม่

## Phase การพัฒนา

### Phase 1 — Business Mapping และ Template

- จับคู่ field ทุกส่วนในเอกสารตัวอย่างกับข้อมูลในระบบ
- ระบุ field ที่มีแล้ว, ต้องเพิ่ม, หรือควรตัดออก
- ระบุส่วนบังคับ/ไม่บังคับและเพดานจำนวนรูป/ความยาวข้อความของแต่ละหน้า
- ยืนยันสูตร แหล่งข้อมูล และผู้ดูแล Master อัตราดอกเบี้ย/สมมติฐานการผลิตไฟ
- สร้าง HTML mockup แบบคงที่ 15+2 หน้า ด้วย Lead ตัวอย่าง

### Phase 2 — Snapshot และ Validation

- เพิ่ม migration สำหรับ snapshot/artifact
- สร้าง service รวบรวม Survey + Quotation เป็น document model เดียว
- เพิ่ม validation และ consistency check ก่อนส่งอนุมัติ
- Snapshot เมื่อส่งอนุมัติ และรักษา snapshot เดิมเมื่อ Approved

### Phase 3 — Report และ PDF Merge

- สร้าง Report template ให้ใกล้เคียงเอกสารตัวอย่าง
- Reuse Quotation PDF generator ปัจจุบัน
- Merge รายงาน + ใบคั่น + ใบเสนอราคา
- รองรับรูปจำนวนต่างกัน page break และเลขหน้าที่ถูกต้อง

### Phase 4 — Step 03 UX และ Approval

- เพิ่ม Document Composer และ readiness status ในการ์ด Quotation
- เปลี่ยน Preview/Submit/Approve/Send ให้ทำกับ Combined PDF
- เพิ่ม Revision difference และเหตุผลส่งกลับ
- คง Approval queue ปัจจุบัน โดยให้เปิด Combined PDF

### Phase 5 — QA และ UAT

- ทดสอบ Quotation 1-3 ชุดใน Lead เดียวกัน
- ทดสอบรูปน้อย/มาก ข้อมูลครบ/ไม่ครบ และ Package ทุกประเภท
- ทดสอบ Draft, Pending, Changes Required, Approved และ Revision
- ตรวจว่า Approved artifact ไม่เปลี่ยนเมื่อแก้ Lead ภายหลัง
- UAT กับ Sales, Sale Sup และ Account ก่อนพิจารณา Production

## Acceptance Criteria

- Step 03 แสดงและจัดการเอกสารเป็นราย Quotation Option/Revision
- PDF ที่ส่งลูกค้ามี Report อยู่ด้านหน้าและ Quotation อยู่ท้ายสุด
- Combined PDF มี 17 หน้าเสมอ: Report 15 หน้าและ Quotation 2 หน้า
- เลข Quotation, Package และยอดเงินทุกส่วนมาจาก snapshot เดียวกันและตรงกัน 100%
- การอนุมัติหนึ่งครั้งครอบคลุมทั้ง Report และ Quotation
- ผู้อนุมัติต้องยืนยันการตรวจสอบและรับรอง Survey, ราคา, เงื่อนไข และผลคำนวณสินเชื่อทั้งชุด
- ตารางสินเชื่อและผลประหยัดคำนวณจากข้อมูลจริง พร้อมเก็บ input, output, สูตรเวอร์ชันและแหล่งข้อมูลไว้ตรวจย้อนหลัง
- ไม่มี Approval state แยกซ้ำซ้อนกับ Survey
- Approved PDF เป็นไฟล์ immutable และตรวจย้อนหลังได้
- การเปลี่ยนข้อมูลสำคัญหลังอนุมัติสร้าง Revision ใหม่เสมอ
- Legacy quotation เดิมยังเปิดดูได้โดยไม่เสียข้อมูล

## ประเด็นที่ยังต้องยืนยันก่อน Implementation

1. แหล่งข้อมูลอัตราดอกเบี้ยสินเชื่อ ผู้รับผิดชอบอัปเดต และรอบการทบทวนข้อมูล
2. สูตรประมาณการพลังงาน/เงินประหยัด ค่าไฟต่อหน่วย degradation และสมมติฐานที่ต้องใช้เป็นมาตรฐานบริษัท
3. Storage สำหรับ Approved PDF และระยะเวลาการเก็บรักษาเอกสาร/audit log
