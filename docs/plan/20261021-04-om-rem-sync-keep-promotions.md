# ดึงทะเบียน REM แล้วของแถมไม่หาย + เปิดดึงอัตโนมัติให้ใช้ได้จริง

วันที่: 21 ต.ค. 69 · สถานะ: in-progress · ผู้ใช้เลือก "ทำครบทั้ง 4 ข้อ"

## ที่มา

ผู้ใช้ถาม "การดึงข้อมูลจาก REM ติดอะไรไหม" → ทะเบียนค้างตั้งแต่ 9 ก.ย. (ของแถมค้าง 2 ก.ย.)
เพราะเครื่อง dev 3020 ไม่มี `REM_API_KEY` (ค้างจากแผน 20260925-03) · ผู้ใช้ส่ง key มาใส่ `.env.local` แล้ว
พอมี key จริง เจอบั๊กต่อกัน 3 ตัวที่ไม่เคยโผล่เพราะไม่เคยดึงได้:

1. **scope ยาวเกินคอลัมน์** — ตัวตั้งเวลาส่งรหัส 116 โครงการ (675 ตัว) เข้า `om_sync_log.scope` NVarChar(100)
   → mssql throw ใน `logSync` → รอบ REM ล้มเงียบ ไม่มีแถวบันทึก · เชื่อมกลับ/ของแถม/เตือนนัดหายตามไปด้วย
2. **เบอร์โทรเจ้าของประกาศ NVarChar(30)** ทั้งที่คอลัมน์ขยายเป็น 120 แล้ว — เจ้าของที่ยัด 3 เบอร์ (31–32 ตัว)
   ทำ transaction ทั้งโครงการล้ม "Transaction has been aborted" (RM · SK2) รอบหยุดตรงนั้น เหลือ 14 โครงการ
3. **ดึงทะเบียนแล้วลบของแถมทิ้ง** — `syncProject` ลบสัญญาทั้งโครงการแล้วใส่ใหม่ + ลบของแถม "ทุกแหล่ง"
   แล้วใส่คืนจากข้อมูลทั้งโครงการ (ซึ่ง REM ส่งไม่ครบ — รู้ตั้งแต่ 2 ก.ย.)
   - ของแถมรายหลัง (itf) กับ BookingInfo (v2 — แหล่งเดียวที่มีโซลาร์ครบ) ของ 7,248 สัญญาใน 66 โครงการหาย
   - `promo_synced_at` / `booking_checked_at` กลับเป็น NULL → ขั้นของแถมรายหลังต้องยิงใหม่ 7,233 สัญญา
   - `writePromos` (รายหลัง) ก็ลบทุกแหล่งเหมือนกัน → ยิงรายหลังหลัง BookingInfo = v2 หาย

ข้อมูลจริง (บ้าน · ระบบติดตั้ง · สิทธิ์ล้างแผง) ไม่โดนลบ — reconcile มีแต่เพิ่ม
ที่กระทบ: การ์ดหน้าบ้านไม่ขึ้น kW/ปี O&M จาก REM · บ้านโอนใหม่ที่แถมโซลาร์จะไม่ถูกเปิดเข้า O&M เอง
สุ่มยิง REM 6 สัญญา: ยังส่งของแถมครบทั้งรายหลังและ BookingInfo → กู้คืนได้

## แผน

1. ปิด `sync.rem_auto` + `sync.promo_auto` ชั่วคราว (กันรอบ 6 ชม. ถัดไปลบซ้ำ) — เตือนนัด/กวาดงานขายยังทำงาน ✅
2. แก้โค้ด
   - `logSync` ตัด scope ให้พอดี 100 ตัว ✅
   - `writeOwner` เบอร์โทร NVarChar(120) ตามคอลัมน์ ✅
   - `syncProject` อัปเดตสัญญาทีละรายการแทนลบทั้งโครงการ (ค่าที่ขั้นอื่นเติมไว้ยังอยู่)
     ลบเฉพาะสัญญาที่ REM ไม่ส่งมาแล้ว · ของแถมลบ/ใส่เฉพาะ itf ของสัญญาที่ยังไม่เคยยิงรายหลัง · v2 ไม่แตะ ✅
   - `writePromos` ลบเฉพาะ `source = 'itf'` ✅
3. ทดสอบกับ K9BK4 (5 สัญญา · v2 90 แถว · itf 47 แถว) — ดึงซ้ำแล้วของแถม/ตัวจำต้องเท่าเดิม ✅ (24 ต.ค.)
   - K9BK4 ดึงซ้ำผ่าน API บน 3020: itf 47 · v2 90 · เจ้าของ 7 · `promo_synced_at`/`booking_checked_at`/`promo_count` เท่าเดิมทุกสัญญา (checksum ตรง)
   - K2KH3 (4 สัญญายังไม่เคยยิงรายหลัง · v2 22): itf จากชุดทั้งโครงการลบแล้วใส่คืนได้เท่าเดิม · v2 ไม่แตะ · ตัวจำเท่าเดิม
   - ยิงรายหลัง 4 หลัง (`promo: true`) ทำงานปกติ — แต่ 4 หลังนั้นไม่มีแถว v2 จึงยังไม่ได้เห็นกับตาว่า v2 อยู่รอด (เงื่อนไขเดียวกับ K2KH3)
4. ดึง 14 โครงการที่เหลือ → ดึง BookingInfo คืน → ดึงของแถมรายหลังคืน → เชื่อมกลับ
5. เปิดอัตโนมัติกลับ + รีสตาร์ต 3020 (ตัวตั้งเวลาจับโมดูลไว้ตอนบูต ต้องรีสตาร์ตถึงใช้โค้ดใหม่)

## ไม่ทำในรอบนี้

- ปุ่ม "ดึง" (5 โครงการ) วนอยู่กับ 35 โครงการที่ REM ไม่มีข้อมูล (รหัส C) — ไม่เคยได้ไปโครงการจริง
- 3030 (worktree b2b) ใช้ฐานเดียวกันแต่ไม่มี key → จดแถว error ทุก 6 ชม. (ขยะ log)
- tick ของตัวตั้งเวลากลืน error เงียบ (`catch {}`) — บั๊กข้อ 1 ถึงไม่มีร่องรอยเลย
