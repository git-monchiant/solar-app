# Grid-Tie Document Timeline

## Status

backlog

## Goal

ปรับขั้นตอน `ขอขนานไฟ` ให้เป็น Timeline หลัก 6 ขั้นที่กระชับ แต่มี Checklist
เอกสารและหลักฐานเพียงพอสำหรับดำเนินงานจริงกับ MEA/PEA, กกพ. และงานขายไฟ
โดยระบบต้องบังคับเฉพาะเอกสารที่เกี่ยวข้องกับประเภทโครงการ ไม่บังคับ PPA กับงาน
ใช้ไฟเองที่ไม่มีการขายไฟ

## Scope Assumptions

- รองรับหน่วยงาน `MEA` และ `PEA`
- แยกประเภทโครงการตั้งแต่ต้น:
  - `self_consumption` — ใช้เอง ไม่ขายไฟ
  - `sell_excess` — ใช้เองและขายไฟส่วนเกิน
- รองรับเงื่อนไขตามขนาดระบบ เช่น ต่ำกว่า 200 kVA, ตั้งแต่ 200 kVA แต่ต่ำกว่า
  1,000 kVA และโครงการที่ต้องมีใบอนุญาตเพิ่มเติม
- รายการเอกสารจริงอาจต่างกันตามหน่วยงาน พื้นที่ ขนาดระบบ ประเภทผู้ยื่น และประกาศ
  ที่ใช้ในวันที่ยื่น จึงต้องให้ Admin แก้ไข Template Checklist ได้

## Shared Document Rules

- เอกสารหนึ่งไฟล์อ้างอิงได้หลาย Timeline โดยไม่ต้องอัปโหลดซ้ำ เช่น Single Line
  Diagram, สำเนาบัตรประชาชน และหนังสือรับรองวิศวกร
- ทุกเอกสารมี `document_type`, วันที่เอกสาร, วันหมดอายุ (ถ้ามี), เลขที่เอกสาร,
  ผู้อัปโหลด, เวลาอัปโหลด, เวอร์ชัน และสถานะตรวจสอบ
- สถานะเอกสาร: `ยังไม่มี`, `รอตรวจ`, `ผ่าน`, `ต้องแก้ไข`, `ไม่เกี่ยวข้อง`
- เมื่อแทนที่ไฟล์ให้เก็บไฟล์เดิมเป็นประวัติ ไม่ลบทิ้งทันที
- รองรับ PDF/JPG/PNG และหลายไฟล์ต่อประเภทเอกสาร
- Checklist แบ่งเป็น `บังคับ`, `ตามเงื่อนไข`, `แนะนำ` และบันทึกเหตุผลเมื่อทำ
  เครื่องหมาย `ไม่เกี่ยวข้อง`

## Timeline 1 — ยื่นคำขอ

### ข้อมูลหลัก

- การไฟฟ้า: MEA หรือ PEA
- ประเภทโครงการ: ใช้เองไม่ขายไฟ หรือขายไฟส่วนเกิน
- หมายเลข CA/บัญชีผู้ใช้ไฟ/หมายเลขมิเตอร์
- ขนาดระบบ kWp, kW และ kVA
- ผู้ยื่น: เจ้าของมิเตอร์หรือผู้รับมอบอำนาจ
- วันที่ยื่นและเลขที่คำขอ

### เอกสารเตรียมยื่น

เอกสารบังคับขั้นต่ำ:

- แบบคำขอเชื่อมต่อหรือแบบคำขอขายไฟที่ลงนามแล้ว
- Single Line Diagram ที่วิศวกรลงนามรับรอง
- ใบแจ้งค่าไฟล่าสุดหรือหลักฐานหมายเลข CA/มิเตอร์

เอกสารตามเงื่อนไข:

- บุคคลธรรมดา: บัตรประชาชนและทะเบียนบ้าน
- นิติบุคคล: หนังสือรับรองนิติบุคคลและเอกสารผู้มีอำนาจลงนาม
- ผู้รับมอบอำนาจ: หนังสือมอบอำนาจและบัตรประชาชนคู่สัญญา
- เอกสารสิทธิ์หรือหนังสือยินยอมใช้สถานที่ เมื่อผู้ยื่นไม่ใช่เจ้าของสถานที่
- Layout แผง, Inverter, MDB, Route Line และแบบติดตั้ง
- Datasheet/Certificate ของแผง, Inverter และอุปกรณ์ป้องกัน
- ใบอนุญาตวิศวกรและหนังสือรับรองการออกแบบ/ควบคุมงาน

### หลักฐานที่อัปโหลดหลังยื่น

- ใบรับคำขอ, Screenshot หรืออีเมลยืนยันการยื่น
- เอกสารชุดที่ยื่นจริงฉบับรวม

### Gate ไปขั้นถัดไป

- ระบุประเภทโครงการและการไฟฟ้าแล้ว
- เอกสารบังคับผ่าน Checklist
- มีวันที่ยื่นและเลขที่คำขอหรือหลักฐานรับคำขอ

## Timeline 2 — ตรวจเอกสารและเทคนิค

### ข้อมูลหลัก

- สถานะ: รอตรวจ, ขอข้อมูลเพิ่ม, กำลังแก้ไข, ผ่าน, ไม่ผ่าน
- วันที่ได้รับผลและหมายเหตุจากการไฟฟ้า
- ผู้รับผิดชอบและวันนัดติดตามครั้งถัดไป

### หลักฐานที่อัปโหลด

- หนังสือ/อีเมลแจ้งผลตรวจเอกสาร
- หนังสือขอแก้ไขหรือรายการข้อทักท้วง
- เอกสารแก้ไขแต่ละรอบ พร้อมหมายเลข Revision
- หนังสือหรือผลอนุมัติด้านเทคนิค/Capacity/จุดเชื่อมต่อ

### Checklist

- เอกสารผ่านการตรวจความครบถ้วน
- แบบและอุปกรณ์ผ่านการพิจารณาด้านเทคนิค
- ปิดข้อแก้ไขทุกข้อแล้ว
- ขนาดระบบและข้อมูลอุปกรณ์ในผลอนุมัติตรงกับหน้างาน

### Gate ไปขั้นถัดไป

- สถานะผลพิจารณาเป็น `ผ่าน`
- มีหลักฐานอนุมัติหรืออีเมลผลพิจารณา
- ไม่มีรายการแก้ไขค้าง

## Timeline 3 — กกพ. และสัญญา

### ข้อมูลหลัก

- วันที่ยื่นจดแจ้ง/เลขรับแจ้ง กกพ.
- วันที่ได้รับหนังสือรับแจ้ง
- วันที่ชำระค่าเชื่อมต่อและเลขที่ใบเสร็จ
- สำหรับขายไฟ: เลขที่ PPA, วันที่ลงนาม และ SCOD

### เอกสารบังคับตามประเภท

ทุกโครงการตามเกณฑ์ที่เกี่ยวข้อง:

- แบบ/หลักฐานการจดแจ้งยกเว้นต่อ กกพ.
- หนังสือรับแจ้งหรือเลขอ้างอิงจาก กกพ.

เฉพาะกรณีขายไฟ:

- ใบแจ้งค่าใช้จ่ายและใบเสร็จค่าเชื่อมต่อ
- สัญญาซื้อขายไฟฟ้า PPA ที่ลงนามครบถ้วน
- หนังสือ/เอกสารกำหนด SCOD

ตามขนาดและประเภทโครงการ:

- พค.2, อ.1/หนังสือรับรองอาคาร, รง.4 หรือใบอนุญาตอื่นที่กฎหมายกำหนด
- Self Declaration Report, แบบแปลนปัจจุบัน และรูปถ่ายมีวันที่ สำหรับกรณีที่
  เข้าเกณฑ์แจ้งเริ่มประกอบกิจการ

### Gate ไปขั้นถัดไป

- มีหนังสือรับแจ้ง/หลักฐาน กกพ. ตามเกณฑ์ของโครงการ
- ถ้า `sell_excess` ต้องมีใบเสร็จค่าเชื่อมต่อ, PPA และ SCOD
- ถ้า `self_consumption` ระบบต้องไม่บังคับ PPA หรือ SCOD

## Timeline 4 — ตรวจระบบ

### ข้อมูลหลัก

- วันที่แจ้งพร้อมตรวจและวันที่นัดตรวจ
- วันที่ตรวจจริง
- ผลตรวจ: รอตรวจ, ผ่าน, ไม่ผ่าน, นัดตรวจซ้ำ
- รายการข้อแก้ไข, ผู้รับผิดชอบ และกำหนดเสร็จ

### เอกสารก่อนตรวจ

- หนังสือแจ้งติดตั้งแล้วเสร็จ/แจ้งพร้อมให้ตรวจ
- As-built Single Line Diagram และ As-built Layout
- หนังสือรับรองการติดตั้ง/ควบคุมงานจากวิศวกร
- ผลทดสอบระบบและอุปกรณ์ป้องกัน เช่น Anti-islanding/Protection ตามที่หน่วยงานกำหนด
- รูปถ่ายหน้างาน: แผง, Inverter, MDB/ตู้ป้องกัน, จุดเชื่อมต่อ, ป้ายเตือน และมิเตอร์เดิม
- Datasheet/Certificate ที่เปลี่ยนจากชุดยื่นเดิม (ถ้ามี)

### หลักฐานหลังตรวจ

- ใบนัดหรือหนังสือยืนยันวันตรวจ
- ใบตรวจ/รายงานผลตรวจที่เจ้าหน้าที่ลงนาม
- รายการข้อบกพร่องและภาพหลังแก้ไข
- รายงานผลตรวจซ้ำจนผ่าน

### Gate ไปขั้นถัดไป

- ผลตรวจล่าสุดเป็น `ผ่าน`
- ไม่มีข้อแก้ไขค้าง
- มีรายงานผลตรวจหรือหลักฐานยืนยันจากการไฟฟ้า

## Timeline 5 — เปลี่ยนมิเตอร์

### ข้อมูลหลัก

- วันที่เปลี่ยนมิเตอร์
- เลขมิเตอร์เดิมและเลขมิเตอร์ใหม่
- ประเภทมิเตอร์และค่ามิเตอร์เริ่มต้น
- ผู้ดำเนินการ/เลขที่ใบงานของการไฟฟ้า

### หลักฐานที่อัปโหลด

- ใบงานหรือใบรับรองการเปลี่ยนมิเตอร์
- รูปมิเตอร์เดิมก่อนถอด
- รูปมิเตอร์ใหม่ที่เห็นหมายเลขและค่ามิเตอร์ชัดเจน
- รูปซีลมิเตอร์และจุดเชื่อมต่อหลังดำเนินการ

### Checklist

- เลขมิเตอร์ใหม่ตรงกับเอกสารการไฟฟ้า
- บันทึกค่ามิเตอร์เริ่มต้นแล้ว
- รูปถ่ายอ่านหมายเลขและค่ามิเตอร์ได้

### Gate ไปขั้นถัดไป

- มีวันที่เปลี่ยนมิเตอร์และเลขมิเตอร์ใหม่
- มีหลักฐานใบงานหรือรูปมิเตอร์ใหม่

## Timeline 6 — ขนานไฟสำเร็จ

### ข้อมูลหลัก

- วันที่ First Synchronization/เริ่มเชื่อมต่อระบบ
- ผลการทดสอบเชื่อมต่อ
- สำหรับขายไฟ: วันที่ COD และเลขอ้างอิง COD
- วันที่ส่งมอบเอกสารให้ลูกค้า

### หลักฐานที่อัปโหลด

- รายงาน/หนังสือยืนยัน First Synchronization หรืออนุญาตให้เชื่อมต่อ
- รายงานผลทดสอบระบบครั้งสุดท้าย
- สำหรับขายไฟ: หนังสือรับรอง COD หรือเอกสารยืนยันวันเริ่มขายไฟ
- ชุดเอกสารส่งมอบลูกค้า: หนังสือรับแจ้ง กกพ., PPA (ถ้ามี), รายงานตรวจ,
  หลักฐานเปลี่ยนมิเตอร์ และเอกสารอนุญาตเชื่อมต่อ
- หลักฐานลูกค้ารับมอบ เช่น ลายเซ็นหรือการส่งเอกสารทาง LINE/อีเมล

### Gate ปิดงาน

- ผลตรวจผ่าน
- เปลี่ยนมิเตอร์แล้ว หรือมีเหตุผลที่หน่วยงานยืนยันว่าไม่ต้องเปลี่ยน
- มีวันที่ First Synchronization/เริ่มเชื่อมต่อ
- ถ้า `sell_excess` ต้องมี COD
- เอกสารบังคับทั้งหมดผ่านการตรวจและส่งมอบลูกค้าแล้ว

## Recommended UI

- แสดง Timeline แถวเดียว:
  `ยื่นคำขอ → ตรวจเอกสาร → กกพ./สัญญา → ตรวจระบบ → เปลี่ยนมิเตอร์ → ขนานไฟสำเร็จ`
- แต่ละการ์ดแสดงเพียงสถานะ, วันที่ล่าสุด, จำนวน Checklist เช่น `5/6` และจำนวน
  งานที่ต้องแก้ไข
- กดการ์ดเพื่อขยาย `ข้อมูล`, `Checklist`, `เอกสาร`, `ประวัติ`
- ปุ่ม `ผ่านขั้นนี้` disabled จนกว่า Gate จะครบ พร้อมบอกรายการที่ขาด
- เอกสารตามเงื่อนไขแสดง/ซ่อนจากประเภทโครงการ, การไฟฟ้า, ประเภทผู้ยื่น และขนาดระบบ
- รองรับ `ส่งกลับแก้ไข` โดยไม่ลบประวัติ Timeline ที่ผ่านไปแล้ว

## Data Model Direction

- `grid_tie_cases` — ข้อมูลประเภทโครงการ หน่วยงาน ขนาดระบบ และสถานะรวม
- `grid_tie_milestones` — 6 Timeline พร้อมวันที่ สถานะ ผล และหมายเหตุ
- `grid_tie_requirements` — Template Checklist แยกตามเงื่อนไข
- `grid_tie_case_requirements` — Checklist จริงต่อโครงการและผลตรวจ
- `grid_tie_documents` — เอกสาร เวอร์ชัน ประเภท และ Milestone ที่เกี่ยวข้อง
- `grid_tie_corrections` — ข้อแก้ไข รอบการส่ง และสถานะปิดข้อ

ไม่ควรเพิ่มคอลัมน์เอกสารจำนวนมากลงใน `leads` เพราะรายการเอกสารมีหลายไฟล์,
หลายเวอร์ชัน และแตกต่างตามเงื่อนไข

## Acceptance Criteria

- ผู้ใช้เห็น Timeline หลักไม่เกิน 6 ขั้น
- ระบบไม่บังคับ PPA/COD กับงานใช้เองไม่ขายไฟ
- เอกสารหนึ่งไฟล์ใช้ซ้ำได้หลาย Checklist โดยไม่อัปโหลดซ้ำ
- ทุกขั้นแสดงสิ่งที่ขาดก่อนเลื่อนไปขั้นถัดไป
- รองรับผลไม่ผ่าน การแก้ไข และตรวจซ้ำโดยเก็บประวัติครบ
- ปิดงานไม่ได้จนผ่าน Gate ของประเภทโครงการนั้น
- Admin ปรับ Checklist Template ได้โดยไม่แก้โค้ด
