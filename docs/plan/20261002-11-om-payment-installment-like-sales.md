# ขั้นย่อย "ชำระเงิน" O&M — หน้าตาแบบงวดชำระเงินฝั่งขาย + เช็ค/บัตรเครดิตแบบฝั่งขายเต็ม

ที่มา: ผู้ใช้ขอ 2 ต.ค. 69 "ปรับให้เป็นตามรูป และไม่เอา สินเชื่อ" (ภาพขั้นย่อยงวดชำระเงินของขั้น Order ฝั่งขาย)
ต่อจาก [20261002-10](20261002-10-om-payment-like-order-step.md)

สถานะ: **เสร็จ 2 ต.ค. 69**

## ผู้ใช้เคาะ (2 ต.ค. 69)

| เรื่อง | เคาะ |
|---|---|
| งวดชำระ | **ล็อก 1 งวด 100%** — แถบ 1/2/3/4 งวดหน้าตาตามรูป แต่ 2–4 กดไม่ได้ (กติกาเดิม ชำระเต็มก่อนนัด) |
| เช็ค / บัตรเครดิต | **ทำแบบฝั่งขายเต็ม** — บัตรบวกค่าธรรมเนียม % · เช็ค = Account รับเช็คก่อน (ทำงานต่อได้) แล้วยืนยันเงินเข้าอีกรอบ |
| สินเชื่อ | ไม่เอา |
| ชำระหลังติดตั้ง | ไม่เอา (ชำระก่อนนัดเสมอ) |
| ส่ง LINE / ใบแจ้งชำระเงิน PDF | ยังไม่ต้องมี |

## หน้าตา (ขั้นย่อย "ชำระเงิน" ของ PaySteps)

ยกจาก Step 1 ของ OrderStep + PaymentSection:
- กล่องส้มใบที่ลูกค้าเลือก · ช่องยอดใหญ่ "จำนวนเงินตามใบเสนอราคา" + "ยอดตามใบเสนอราคา … · แก้ไขโดยเลือกใบเสนอราคาฉบับอื่น"
- "งวดการชำระเงิน" ปุ่ม 1/2/3/4 งวด (1 งวดเท่านั้น) + "ยอดรวมที่ต้องชำระ X บาท"
- แถวงวดที่ 1: % 100 · ยอด (ล็อก) · ☐ เช็ค ☐ บัตรเครดิต [+x%] · ปุ่ม "บันทึกรับชำระ" (กางแผงรับเงิน) / รอยืนยัน / รอรับเงิน / ชำระแล้ว
- แผงรับเงิน: แท็บ Thai QR / Bank Account / อื่นๆ (ตามค่าใน settings เดียวกับฝั่งขาย · เช็ค = กล่องเหลือง "ชำระด้วยเช็ค")
  · อัปโหลดสลิป/ภาพเช็ค/หลักฐาน สูงสุด 5 · ปุ่ม "ยืนยันการชำระเงิน 1" (Sale ส่งเข้าคิว)
  · Account/admin ยืนยันในแผงได้ด้วย: "ยืนยันรับเช็ค" → "ยืนยันการชำระเงิน 2" · "✗ ไม่อนุมัติ" (ทาง /api/om/payments/[id] เดิม)
- กล่องยอดรวม / ส่วนลด / ยอดชำระสุทธิ / +ค่าธรรมเนียมบัตรเครดิต / ยอดรวมที่ต้องชำระ
- ใต้ QR ไม่มีบรรทัดยอดเงิน (ผู้ใช้สั่งเอาออก 2 ต.ค. 69 · เหมือนฝั่งขาย) — ยอดอยู่ที่ "ยอดรวมที่ต้องชำระ" ด้านบน
- ไม่ทำ: Payment Link (ต้องใช้ pay token ของ lead) · ส่ง LINE · ใบแจ้งชำระเงิน · "การติดตามชำระเงิน" (ผูกวันติดตั้งของฝั่งขาย) · ตรวจสลิป OCR

## ข้อมูล / API

- `POST /api/om/payments` — รับ method qr / bank_transfer / other (ต้องมีรายละเอียด) / cheque + `cc_pct` (0, 1.5, 2, 2.5, 3)
  บัตร = payment_method `cc` · ค่าธรรมเนียมคิดที่ server เก็บ `cc_surcharge_pct/amount` · amount = ยอดใบ (ไม่รวมค่าธรรมเนียม แบบฝั่งขาย)
- `POST /api/om/payments/[id]` — เพิ่ม action `cheque_received` (Account/admin) · ยืนยันเงินของเช็คต้องรับเช็คก่อน
- รับเช็คแล้ว = ทำงานต่อได้ (โทรนัด) แบบฝั่งขาย → `OM_BOOKING_PAID_SQL` · `pay_state` · journey นับ cheque_received_at เป็นชำระแล้ว
  · เติมสิทธิ์ยังทำตอนยืนยันเงินเข้า (confirmed_at) เหมือนเดิม
- คิว Account (`/report/pending` · OmPendingPayments): เช็คยังไม่รับ = ปุ่ม "ยืนยันรับเช็ค" · รับแล้ว = "ยืนยันรับเงิน" · บัตรแสดงยอดรวมค่าธรรมเนียม
- ใบเสร็จ O&M (`receipt/data` stage om): บรรทัดค่าธรรมเนียมบัตรเครดิต + ยอดรวม
- ไม่มี migration (คอลัมน์ cheque_* / cc_surcharge_* มีในตาราง payments อยู่แล้ว)
