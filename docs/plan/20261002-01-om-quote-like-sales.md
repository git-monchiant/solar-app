## ยกจากฝั่งขาย (QuotationBuilder ของขั้น 03 Lead)

| ฝั่งขาย | O&M หลังแก้ |
|---|---|
| การ์ดว่างเส้นประม่วง "+ สร้างใบเสนอราคา" | เหมือนกัน (1 ใบต่อใบงาน จึงมีการ์ดเดียว ไม่มีชุด 2–3) |
| การ์ดใบ: ไอคอน + เลขใบ · ราง Sale → Solar Manager → Sale Manager (`ApprovalFlowStatus`) | ใช้ component ตัวเดียวกัน (export จาก QuotationBuilder) |
| กล่อง "แพ็กเกจหลัก" + รายการเสริม · ผู้จัดทำ · ยอดที่ต้องชำระตัวใหญ่ | เหมือนกัน (ไม่ใช้แพ็กเกจ = "งานบริการ O&M") |
| ปุ่มท้ายการ์ด: แก้ไข/ดู · ดู/ส่งกลับ/อนุมัติ · ดู/Revision | เหมือนกัน — ผู้อนุมัติกดที่การ์ดได้ด้วย (endpoint เดิม `/api/quotations/[id]/action` แยกทาง O&M อยู่แล้ว) |
| ปุ่มยาวไล่สี "▷ ส่งขออนุมัติใบเสนอราคา" / "รออนุมัติ…" / "▷ ส่งใบเสนอราคาให้ทีมขาย" | "▷ ส่งขออนุมัติ" / "รออนุมัติ…" / "▷ ส่งใบเสนอราคาให้ลูกค้าแล้ว" |
| ตัวแก้ใบเป็น popup เต็มจอ ซ้าย = รายการ · ขวา = การเงิน · ล่าง = ยกเลิก / บันทึกฉบับร่าง | ซ้าย = เลือก Package O&M ตามช่วง kW + รายการในใบ (แถวแบบฝั่งขาย) · ขวา = รวม/ส่วนลด %·บาท/ยอดสุทธิ · การชำระเงิน · โน้ต |
| popup ส่งกลับให้แก้ไข (ModalBase) | เหมือนกัน |

## คงไว้ (กติกา O&M ต่างจากฝั่งขาย)

- ข้อมูล/API เดิม: 1 ใบต่อใบงาน · Package O&M + รายการเพิ่ม (จำนวน × ราคา/หน่วย) + ส่วนลดเป็นบาท + เหตุผล (บังคับเมื่อมีส่วนลด) · ชำระเต็มก่อนนัด
  ช่องส่วนลด % แปลงเป็นบาทก่อนส่ง (ฝั่งขายก็คิดแบบนี้)
- ไม่มีแท็บเงื่อนไข/งวดชำระ/ดูตัวอย่าง (ข้อความท้ายใบ O&M มาจาก om_package_notes)
- ไม่มีปุ่มลบฉบับร่าง (ใบผูกกับใบงาน — ลูกค้าไม่เอาใช้ "ยกเลิกใบงาน" เดิม)
- ข้อความสิทธิ์ฟรี / รอ Sale ออกใบ / ใบงานยกเลิก / ออกใบของงานถัดไป เหมือนเดิม

## ทำอะไร

- `QuotationBuilder.tsx` — เติม `export` หน้า `ApprovalFlowStatus` อย่างเดียว (กัน conflict กับ main)
- `api/om/quotations/[id]` GET — เพิ่ม `revision_no`, `submitted_by_name`, `returned_by_name`, `returned_by_role` (SQL ชุดเดียวกับรายการใบฝั่งขาย)
- `OmQuotationPanel.tsx` — เขียนหน้าตาใหม่ตามตารางด้านบน
