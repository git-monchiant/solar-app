# Require Received Money Before Step 05

Status: done

## Goal

ปรับเงื่อนไขจาก Step 04 ไป Step 05 ให้ทุกงวดที่กำหนดชำระก่อนติดตั้ง
ต้องได้รับเงินจริงและมี `payments.confirmed_at` แล้วเท่านั้น การยืนยันรับเช็ค
(`cheque_received_at`) อย่างเดียวจะไม่ปลดล็อก Step 05 อีกต่อไป

## Business Rules

- งวดที่ไม่ได้ติ๊ก `จ่ายหลังติดตั้ง` ต้องมี `confirmed_at` ครบทุกงวดก่อนเข้า Step 05
- งวดที่ติ๊ก `จ่ายหลังติดตั้ง` ไม่ต้องชำระใน Step 04 และไปเก็บเงินใน Step 05
- แผน 1 งวดที่ไม่ติ๊กจ่ายหลังติดตั้ง ต้องรับเงินจริงก่อน
- แผน 1 งวดที่ติ๊กจ่ายหลังติดตั้ง ไป Step 05 ได้
- แผน 2-4 งวด ต้องรับเงินจริงครบทุกงวดที่ไม่ติ๊กจ่ายหลังติดตั้ง
- การรับเช็คยังคงบันทึกและแสดงสถานะรอรับเงินได้ แต่ไม่ถือเป็นเงินรับจริง

## Implementation

1. ใช้ `paidIdxSet` (`confirmed_at`) เป็นเกณฑ์ของงวดก่อนติดตั้ง
2. ปรับด่านออกจากหน้างวดชำระให้ตรวจทุกงวดก่อนติดตั้ง ไม่ใช่เพียงอย่างน้อยหนึ่งงวด
3. ปรับด่านบันทึกเข้า Step 05 ให้ใช้เงื่อนไขเดียวกัน
4. เพิ่มด่านฝั่ง API เมื่อเปลี่ยนสถานะเป็น `install` เพื่อไม่ให้ข้ามกติกาจากคำขอโดยตรง
5. ปรับข้อความช่วยเหลือและข้อความผิดพลาดไม่ให้สื่อว่ารับเช็คแล้วไปติดตั้งได้

## Verification

- TypeScript ผ่าน
- ESLint ของ `OrderStep.tsx` ไม่มี error ใหม่
- ตรวจกรณี 1-4 งวด ทั้งแบบมีและไม่มีงวดจ่ายหลังติดตั้ง

## Result

- ด่านออกจากงวดชำระและด่านเข้า Step 05 ตรวจ `confirmed_at` ครบทุกงวดก่อนติดตั้ง
- `cheque_received_at` ไม่ปลดล็อก Step 05 อีกต่อไป
- งวดที่ติ๊กจ่ายหลังติดตั้งยังไปเก็บเงินใน Step 05 ตามเดิม
- API ป้องกันการเปลี่ยนสถานะเป็น `install` หากยังขาดเงินจริงของงวดก่อนติดตั้ง
- `npx tsc --noEmit` ผ่าน
- ESLint ไฟล์ที่แก้ไม่มี error (มี warning เดิมใน `OrderStep.tsx` 5 รายการ)
