# SLA Step Visibility

Status: done

## Goal

ปรับหน้า `/sla` เดิมให้ผู้ใช้เห็นทันทีว่าแต่ละ Lead เกิน SLA ที่ขั้นตอนใด โดยไม่สร้าง Dashboard หรือหน้ารายงานใหม่

## Design

- คง Header, แท็บสถานะ, การ์ดสรุป และคิวงานตามความเร่งด่วนของหน้าเดิม
- เพิ่มข้อความ `เกิน SLA ที่ขั้นตอน “...”` ในเนื้อหาของ Lead card
- ปรับกล่องกำหนดเสร็จด้านขวาให้แสดงข้อมูลตามลำดับ: ระยะเวลาที่เกิน, ขั้นตอนที่เกิน และวันครบกำหนดเดิม
- เพิ่มตัวกรอง `ทุกขั้นตอนที่เกิน SLA` เหนือรายการ เพื่อค้นหาคอขวดที่ต้องการได้เร็วขึ้น
- แสดงทั้งจำนวนงาน SLA และจำนวน Lead แบบไม่ซ้ำในกล่องสรุปแต่ละสถานะ
- ใช้สีแดงร่วมกับข้อความกำกับเสมอ เพื่อไม่พึ่งสีเพียงอย่างเดียว

## Scope

- ออกแบบเฉพาะหน้า `/sla` เดิม
- ไม่เพิ่มหน้า Dashboard ใหม่
- ไม่เปลี่ยนกติกา SLA, due date หรือการคำนวณสถานะ
- ข้อมูลชื่อขั้นตอนและระยะเวลาที่เกินใน mockup เป็นตัวอย่างเพื่ออธิบายตำแหน่งการแสดงผล

## Acceptance Criteria

1. ผู้ใช้ระบุขั้นตอนที่เกิน SLA ของแต่ละ Lead ได้โดยไม่ต้องเปิดรายละเอียด
2. ผู้ใช้เห็นระยะเวลาที่เกินและ due date เดิมในบริเวณเดียวกัน
3. ผู้ใช้กรองรายการตามขั้นตอนที่เกิน SLA ได้
4. Desktop และ Mobile ไม่มีข้อความซ้อนหรือล้นแนวนอน
5. กล่องสรุปแยกความหมายระหว่างจำนวนงาน SLA กับจำนวน Lead แบบไม่ซ้ำอย่างชัดเจน

## Result

- หน้า `/sla` แสดงทั้งจำนวนงาน SLA และจำนวน Lead แบบไม่ซ้ำในกล่องสรุปทั้ง 3 สถานะ
- API ส่ง `leadCounts` แยกตามสถานะ และรวม `warning` กับ `critical` แบบไม่ซ้ำสำหรับกล่องใกล้กำหนด
- เพิ่มตัวกรองตาม SLA policy/ขั้นตอนเหนือคิวงาน
- Lead card ที่เกินกำหนดแสดงขั้นตอน, ระยะเวลาที่เกิน และ due date เดิมในกล่องเดียวกัน
- ตรวจ API ด้วยข้อมูล Development, Desktop 1440px และ Mobile 390px แล้วไม่พบ horizontal overflow หรือ console error
- ผ่าน `npm run test:sla`, TypeScript, ESLint, `git diff --check` และ production build
