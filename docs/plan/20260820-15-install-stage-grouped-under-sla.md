# ขั้น Install และ Warranty: SLA เป็นหัวข้อ เหตุการณ์ตามหลังหัวข้อของมัน

วันที่: 2026-08-20
สถานะ: done

## เป้าหมาย

ขั้น Install คือสองงานที่ต่อกัน — **นัดวันติดตั้ง** แล้วจึง **ติดตั้งจริง** —
แต่ Timeline แสดงเป็นรายการแบน 6 แถวเรียงตามเวลา ทำให้ต้องอ่านทุกแถวก่อน
จะรู้ว่าแถวไหนเป็นเรื่องของนัดหมาย แถวไหนเป็นเรื่องของงานติดตั้ง

ตอนนี้เหลือหัวข้อใหญ่สองหัวข้อ คือแถว SLA ทั้งสองของขั้นนี้ ส่วนเหตุการณ์
ที่เหลือซ้อนอยู่ใต้หัวข้อที่มันเป็นของ

```
• นัดวันติดตั้งและแจ้งเตรียมเอกสาร   [เสร็จใน SLA]
    SLA 3 วัน · เริ่ม 2 ก.ค. 18:03 · เสร็จ 3 ก.ค. 21:01 · รับผิดชอบ …
• บันทึกย้อนหลัง · ยืนยันนัดติดตั้ง 9 ก.ค. 2569 · 11 ก.ค. 09:51
    > ประวัติการแก้ไขนัด (3)
• ติดตั้ง ทดสอบระบบ และส่งมอบงาน   [เสร็จใน SLA]
    SLA 15 วัน · เริ่ม 9 ก.ค. 2569 · เสร็จ 10 ก.ค. 2569 · รับผิดชอบ …

  > การเดินสถานะ (1)      ← ท้ายขั้น เหลือเฉพาะการย้อนขั้น
```

แถวลูกอยู่ **ระดับเดียวกับหัวข้อ** ไม่ย่อหน้าเข้าไป เพราะหัวข้อแยกตัวเองออก
มาด้วย badge และบรรทัด SLA อยู่แล้ว การจัดกลุ่มที่นี่คือเรื่องของ **ลำดับ**
ไม่ใช่การซ้อนชั้น: milestone ตามหลัง SLA ที่มันเป็นของ แทนที่จะเรียงตามเวลาล้วน

## กติกาการจัดกลุ่ม

ขั้น Install แบ่งได้สะอาดด้วยชนิดของ activity:

| เหตุการณ์ | อยู่ใต้ |
| --- | --- |
| `appointment_*` ทุกชนิด และแถว "นัดวันติดตั้ง" ที่สร้างจากคอลัมน์ | นัดวันติดตั้งและแจ้งเตรียมเอกสาร |
| ที่เหลือทั้งหมด — เข้าสู่ขั้น, rollback, ติดตั้งจริง, ปิดงาน, ค่าใช้จ่ายเพิ่ม | ติดตั้ง ทดสอบระบบ และส่งมอบงาน |

เหตุการณ์ที่ไม่มีหัวข้อไหนรับไว้จะแสดงต่อท้ายกลุ่มตามเดิม ไม่หายไปจาก
Timeline — กติกานี้กันไม่ให้ activity ชนิดใหม่ในอนาคตเงียบหายไป

ใช้กับขั้น Install ขั้นเดียวก่อน (`GROUPED_SLA_SECTIONS`) ขั้นอื่นยังแบน
เพราะยังไม่ได้ตกลงว่าเหตุการณ์ไหนควรอยู่ใต้ SLA ตัวใด

## ลำดับหัวข้อยึดลำดับงาน ไม่ใช่นาฬิกา

หัวข้อ SLA ของขั้นที่จัดกลุ่มเรียงตามลำดับที่ระบุไว้ใน `GROUPED_SLA_SECTIONS`
คือ นัดวันติดตั้ง → ติดตั้ง ไม่ใช่เรียงตาม `started_at`

จำเป็น เพราะนาฬิกาสองเรือนนี้เริ่มคนละแบบ: SLA ติดตั้งเริ่มที่ **วันนัด**
ซึ่งเป็นวันล้วนจึงเท่ากับเที่ยงคืน ส่วน SLA นัดวันเริ่มที่ **เวลายืนยันมัดจำ**
ซึ่งเป็นเวลาจริงของวัน ใบที่นัดและติดตั้งวันเดียวกันจึงมีเที่ยงคืนมาก่อน
และหัวข้อ "ติดตั้ง" ขึ้นก่อน "นัดวันติดตั้ง" ทั้งที่งานเกิดตรงข้าม

## การเดินสถานะยุบเป็นกลุ่มพับ

"เข้าสู่ขั้นติดตั้ง" และ "ย้อนกลับไปขั้น Install" เป็นการเดินสถานะในระบบ
ไม่ใช่ขั้นตอนของงานหน้างาน พอวางเป็นแถวเต็มใต้หัวข้อ SLA จึงอ่านสะดุดสองชั้น
คือชนิดของเรื่องไม่ตรงกับหัวข้อ และเหตุการณ์ 11 ก.ค. โผล่หลังหัวข้อที่บอกว่า
งานจบไปแล้วตั้งแต่ 10 ก.ค.

ในขั้นที่จัดกลุ่ม **"เข้าสู่ขั้น X" ไม่แสดงเลย** ส่วนการ **ย้อนขั้น** ยุบเข้า
กลุ่มพับ "การเดินสถานะ"
ซึ่งเป็นรูปแบบเดียวกับ "ประวัติการแก้ไขนัด" ที่ใช้อยู่ในหน้าเดียวกัน
และวางไว้ **ท้ายขั้น** ไม่ใช่ใต้ SLA ตัวใดตัวหนึ่ง เพราะการย้อนขั้นเป็นเรื่อง
ของทั้งขั้น ไม่ใช่ขั้นตอนของงานติดตั้ง — วางไว้ใต้หัวข้อ "ติดตั้ง ทดสอบระบบ"
ทำให้อ่านเหมือนเป็นส่วนหนึ่งของงานนั้น

"เข้าสู่ขั้น X" ถูกตัดออกเพราะไม่ได้บอกอะไรที่แถว SLA ไม่ได้บอก และบอกผิด
จังหวะด้วย — Lead 691 เข้าสถานะ "กำลังติดตั้ง" วันที่ 10 ก.ค. ทั้งที่งานของขั้นนี้
เริ่มตั้งแต่ 2 ก.ค. และนัดเสร็จไปแล้ววันที่ 3 ก.ค. สถานะจึงเดินตามหลังงานจริง
เกือบสัปดาห์ ส่วนการย้อนขั้นเก็บไว้เพราะอธิบายว่าทำไม SLA ถึงออกมาแบบนั้น
Activity Log ยังบันทึกการเปลี่ยนสถานะไว้ครบทุกครั้งอยู่แล้ว
ลองทำเป็นบรรทัดสรุปบรรทัดเดียวก่อนแล้ว แต่ทิ้งชื่อผู้ทำและเหตุผลของ
การย้อนสถานะไป และทำให้ของชนิดเดียวกันมีสองหน้าตาในจอเดียว

ตัวเลข x/y ที่หัวขั้นไม่นับแถวที่ถูกยุบแล้ว

ขั้นที่ไม่ได้จัดกลุ่มยังแสดง `status_change` เป็นแถวปกติเหมือนเดิม
เช่นเดียวกับกรณีที่ขั้นนั้นยังไม่มี SLA ให้ยุบเข้าไป

## ขั้น Warranty / After Sales

ใช้กติกาเดียวกัน โดยหัวข้อเรียง **ติดตามหลังติดตั้ง → ปิด Lead**

ปล่อยตามนาฬิกาไม่ได้ เพราะ `CLOSE_LEAD` เริ่มนับตั้งแต่ติดตั้งเสร็จ ใบที่ยัง
ปิดไม่ได้จึงมี `started_at` เก่ากว่าทุกอย่างในขั้น แล้วลอยขึ้นไปอยู่บนสุด
ทั้งที่เป็นงานที่ยังค้างอยู่ท้ายกระบวนการ

เอกสารรับประกันและผลประเมินหลังการขายจัดอยู่ช่วง after-sales ส่วนการปิด Lead
คือสิ่งที่เหลือหลังจากนั้น จึงไม่มีเหตุการณ์ใดถูกจัดไว้ใต้มัน

ผลพลอยได้: แถว "ติดตั้งเสร็จและเข้าสู่การรับประกัน" ที่เคยขึ้นซ้ำสองครั้ง
(ปิดงาน → ถูกย้อนขั้น → ปิดใหม่) หายไปทั้งคู่ เพราะเป็น `status_change`
ชนิด "เข้าสู่ขั้น" ซึ่งกติกาข้างต้นตัดออกอยู่แล้ว

## ทำไมกลุ่มพับสองกลุ่มไม่รวมกัน

ขั้น Install มีกลุ่มพับสองอันซึ่งดูคล้ายกันแต่คนละเรื่อง และตั้งใจให้แยกกัน

| กลุ่ม | เก็บอะไร | เกาะกับ |
| --- | --- | --- |
| ประวัติการแก้ไขนัด | การนัดรอบเก่าที่ถูกแทนที่แล้ว | แถวนัดที่ยังมีผล |
| การเดินสถานะ | การย้อนขั้นของ Lead | ทั้งขั้น (ท้ายขั้น) |

การย้อนขั้นไม่ได้แก้การนัดอะไร ถ้ายัดรวมเข้าไปจะกลายเป็นรายงานว่ามีการแก้นัด
4 ครั้งทั้งที่แก้จริง 3 ครั้ง และถ้ายกประวัตินัดออกมาไว้ท้ายขั้นเพื่อให้เหลือ
ปุ่มเดียว ก็จะเสียความสัมพันธ์ที่ว่าประวัติอยู่ติดกับนัดที่มันแก้

## สิ่งที่แก้

`src/app/(app)/leads/[id]/page.tsx` เท่านั้น

- `Bullet` เพิ่มฟิลด์ `slaGroup` และ `statusFlow` และ `activityRows()` ติดค่านี้ให้ทุกแถวของ
  ขั้น Install ส่วนแถวที่สร้างจากคอลัมน์ (`นัดวันติดตั้ง`, `ติดตั้งจริง`,
  `ติดตั้งเสร็จสิ้น`) ระบุกลุ่มไว้ตอนสร้าง
- เพิ่ม `GROUPED_SLA_SECTIONS` ซึ่งเก็บทั้งว่าขั้นไหนจัดกลุ่ม และหัวข้อเรียงลำดับใด
- แยกการ render ของแถว milestone ออกเป็น `renderMilestone()` เพื่อให้เรียกได้
  ทั้งจากรายการแบนและจากในกลุ่ม แล้วให้ขั้นที่จัดกลุ่ม render แถว SLA เป็น
  หัวข้อพร้อม `<ul>` ลูกที่ย่อหน้าด้วยเส้นประ
