## 2. BOQ หลายตัวต่อโครงการ

- `b2b_boqs` เพิ่ม `project_id` + `option_label` (เช่น "998.64 kWp · Jinko 730") — 1 ตัวเลือก = 1 ชุดเลขที่ + Rev เดิม (โครงสร้าง Rev ที่มีอยู่แล้วใช้ต่อได้เลย)
- ทำ BOQ จากหน้าโครงการ (แท็บ BOQ / ปุ่มในขั้น 3200, 3400) — ชื่อโครงการ/ลูกค้า/ที่ตั้งดึงจากโครงการ ไม่พิมพ์ซ้ำ
- หน้า "รายการ BOQ" เดิมยังอยู่ (เห็นทุกโครงการ) — เพิ่มคอลัมน์ "โครงการ" กดไปหน้าโครงการได้
- ตอน "ได้งาน" เลือก BOQ Rev ที่ชนะ → `b2b_projects.won_boq_id` = **งบต้นทุนของโครงการ** ให้ Purchase ใช้สั่งของ
  (Purchase เห็นต้นทุน ไม่เห็นราคาขาย — กติกาเดิมจากแผน BOQ)
- BOQ ทดสอบ 4 ใบที่มีอยู่: ลบด้วย "สคริปต์ล้างข้อมูลเทส" ที่ผู้ใช้ขอไว้ (แผน BOQ) ก่อนเริ่มเฟส 1 — ไม่ต้องสร้างโครงการย้อนให้ (**เคาะ 15 ต.ค.**)

## 3. ใบเสนอราคา B2B + อนุมัติ 3 ชั้น

### ใบเสนอราคา

- ตารางใหม่ `b2b_quotations` — อ้าง BOQ หนึ่ง Rev (`boq_id`) · เลขที่ + Rev ของตัวเอง · ชนิด **ประมาณการ / ยืนยัน** (ตั้งจากขั้นที่สร้าง แก้ได้)
- เนื้อหาตาม sheet `SSE (2)`: รายการแบบเหมา (ชื่องาน + kWp + บรรทัด "- รวม…") · เงื่อนไขชำระเงินเป็นงวด (ค่าตั้งต้น 30/30/35/5 แก้ได้ ผลรวมต้อง 100%)
  · VAT · รับประกันอุปกรณ์/ติดตั้ง · ยืนยันราคา N วัน (ตั้งต้น 30) · หมายเหตุ/เงื่อนไข · O&M ที่รวมในราคา (จำนวนปี · ครั้งต่อปี · รายการ)
- ข้อความตั้งต้น (เงื่อนไข · หมายเหตุ · รับประกัน) เก็บเป็น master แก้ได้ แบบ `quotation_terms` ของ B2C — ใบที่ออกแล้วแช่ข้อความไว้ใน snapshot
- PDF ผังตาม `SSE (2)` 2 หน้า (ใบเสนอราคา + รายละเอียดรับประกัน/หมายเหตุ) — ใช้ตัวทำ PDF ชุดเดียวกับใบเสนอราคา B2C
- ช่องลงชื่อตามแม่แบบ: แถว 1 ลูกค้า (เว้นเซ็นมือ) | ผู้เสนอราคา (= ผู้ทำใบ) · แถว 2 ผู้ตรวจสอบ 1 | ผู้ตรวจสอบ 2 · แถว 3 ผู้ตรวจสอบ 3
  ทุกช่องป้ายว่า "ผู้ตรวจสอบ" เหมือนในแม่แบบ — ลำดับชั้นกำหนดจากตำแหน่งช่อง (ซ้าย → ขวา → แถวล่าง)

### ลำดับอนุมัติ (ยกกลไกจากใบเสนอราคา B2C ทั้งก้อน)

```
ร่าง ──ส่งอนุมัติ──→ รอผู้ตรวจสอบ 1 ──→ รอผู้ตรวจสอบ 2 ──→ รอผู้ตรวจสอบ 3 ──→ อนุมัติแล้ว ──ส่งลูกค้า──→ ส่งแล้ว รอตอบ
                          │                  │                │
                          └──── ส่งกลับแก้ (พร้อมเหตุผล) ────┘ → ร่าง → ส่งใหม่เริ่มชั้น 1
```

ยกจาก B2C (`api/(lead)/quotations/[id]/action` · `quotation-pdf`):
- ส่งอนุมัติ = **แช่ snapshot** ของใบ + สรุป BOQ Rev นั้น · แก้หลังส่ง = เปิด Rev ใหม่ อนุมัติของ Rev เดิมใช้ไม่ได้
- กดอนุมัติต้อง **ติ๊กยืนยันว่าตรวจแล้ว** (`certify`) · ทุกชั้นกด **ส่งกลับแก้** ได้พร้อมเหตุผล
- อนุมัติแล้ว **ลายเซ็น + ชื่อ + วันที่** ของชั้นนั้นขึ้นในช่องของตัวเองใน PDF ทันที · ระหว่างรอ PDF มี **ลายน้ำ** "รอผู้ตรวจสอบ 1 อนุมัติ" ฯลฯ
- แจ้งเตือน role ของชั้นถัดไป · badge "รออนุมัติ" · **admin กดแทนได้ทุกชั้น**

เพิ่มจาก B2C
- **ส่งอนุมัติไม่ได้ถ้า BOQ ยังมีบรรทัด "รอราคา"** (`pending_lines > 0`) — บรรทัดรอราคาคิดเป็น 0 ใบจะออกราคาต่ำกว่าจริง

## 4. งวดเงิน

- ตอน "ได้งาน" คัดลอกงวดจากใบที่ชนะลงตาราง `b2b_project_installments` (งวด · % · ยอด · เหตุการณ์ที่ทำให้ถึงกำหนด · สถานะ)

  - "ถึงกำหนด" ขึ้นเองเมื่อบันทึก milestone ที่ผูกไว้ (เซ็นสัญญา · แผงส่งครบ · ติดตั้งเสร็จ · ส่งมอบ)

- งวดที่ไม่ได้ผูกเหตุการณ์ (เงื่อนไขพิเศษของลูกค้า) กด "ถึงกำหนด" เองได้

## ปรับหน้าโครงการ (16 ต.ค. 69)

- ปุ่มสร้าง BOQ ในหน้าโครงการ: ชื่อ "+ BOQ ขนาดใหม่" → **"+ สร้าง BOQ"** (คำเดียวกับหน้ารายการ BOQ · ผู้ใช้เลือกจาก 4 แบบ) · หัวป๊อปอัป "เพิ่ม BOQ ตัวเลือกใหม่" → "สร้าง BOQ ใหม่"
- ขั้น 02 / 04 ที่ยังไม่มี BOQ: การ์ดขั้นมีปุ่มม่วง "+ สร้าง BOQ" อยู่แล้ว → ตาราง "BOQ ของโครงการ" ไม่โชว์ปุ่มซ้ำ (ข้อความว่าง "เริ่มจากปุ่มด้านบน") ·
  มี BOQ แล้ว / แท็บ BOQ → ปุ่มในตารางกลับมาเหมือนเดิม
- 16 ต.ค. 69 **ขั้น 3100 เปลี่ยนชื่อ "โอกาสขาย" → "โครงการใหม่"** (ผู้ใช้เลือกแบบ ก. จาก 4 แบบ — โอกาสขายอ่านแล้วไม่ชัดว่าเป็นขั้นอะไร) ·
  เปลี่ยนที่ B2B_FLOW + เมนู/คำอธิบายการ์ดขาย B2B + ป๊อปอัปสร้างโครงการ · ข้อมูลในฐานไม่แตะ (เก็บเป็นเลขขั้น)
