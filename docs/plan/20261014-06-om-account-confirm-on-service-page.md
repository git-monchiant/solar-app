# Account ยืนยันรับเงิน O&M ที่หน้างาน ขั้น 03 แบบฝั่งขาย

ที่มา: ผู้ใช้ถาม 14 ต.ค. 69 "กระบวนการ approve ยืนยันรับเงิน เหมือนกับงานขายไหม · แนบใบเสร็จจากระบบอื่นมีไหม"
→ ตอบว่ากติกาเหมือน แต่ O&M กดยืนยัน/ปฏิเสธในคิวเลย (ฝั่งขายพาไปหน้า lead) · ใบเสร็จตัวจริงแนบได้ที่หน้ารายรับ O&M
→ ผู้ใช้สั่ง "ทำให้เหมือนงานขายเลย" · เลือกทาง **เปิดหน้างาน O&M ขั้น 03** (ไม่เอาหน้าต่างบนหน้าคิว)

สถานะ: **เสร็จ 14 ต.ค. 69** — ผู้ใช้ลองกดจริงแล้ว (ยืนยันเงิน + แนบใบเสร็จที่ขั้น 03 ใบ SSR-OM-QT-26-0015 ด้วย Admin) · role account ล้วนยังไม่ได้ลองผ่านหน้าจอ

## เป้าหมาย

คิว "รอยืนยันรับเงิน" แถว O&M → ปุ่มเดียว "กดยืนยันรับเงิน" (เช็คที่ยังไม่รับ = "ยืนยันรับเช็ค") แบบแถวฝั่งขาย
→ เปิดหน้างาน `/om/services/[house]` ที่ขั้น 03 ชำระเงิน → Account ดูสลิป · ยืนยัน / ไม่อนุมัติ / เช็คเด้ง ในแผง
→ ยืนยันแล้วกล่องเดิมขึ้นใบเสร็จชั่วคราว + แนบใบเสร็จตัวจริงทันที (แบบ PaymentSection ฝั่งขาย)

## ทำ

1. **คิว** (`OmPendingPayments`): เอาปุ่ม ปฏิเสธ/ยืนยัน + กล่องเหตุผลออก · เหลือปุ่มเดียวคลาสเดียวกับแถวฝั่งขาย
   ชื่อลูกค้าเป็นลิงก์หน้างานให้ Account ด้วย (เดิม admin อย่างเดียว)
   ก่อนเปิดตั้ง localStorage แบบ `leadFocusStep_` ฝั่งขาย: `omFocusPay_<house>` = เลขใบงาน · `omPaySubStep_<booking>` = 1
2. **หน้างาน** (`JobDetail`): อ่าน `omFocusPay_` ครั้งเดียว → เปิดการ์ดขั้น 03 (กางไว้ · มือถือเลื่อนไปการ์ดนั้น)
   ใบงานไม่ตรงเลขที่ส่งมา (บ้านมีใบใหม่กว่า) = ไม่ทำอะไร
3. **แผงชำระเงิน** (`OmPaymentPanel`): แยกปุ่ม Account + กล่องเหตุผล เป็น `AccountActions` ใช้ 2 ที่
   ขั้นที่กำลังทำ (เดิม) + **ขั้น 03 ที่ปิดแล้ว** (รับเช็คแล้วรอเงินเข้า · แนบใหม่หลังเช็คเด้งตอนถึงหน้างาน) — เดิมไม่มีปุ่ม
4. **Account อ่านอย่างเดียว** (ไม่มี role ทีม O&M: admin · sales · sales_sup · solar · solar_sup — ค่ากลาง `OM_WORK_ROLES`)
   - หน้าจอ: ซ่อน Follow-up / Note (หัว + แถบล่างมือถือ) · ปุ่มเจ้าของงานเป็นข้อความ · avatar กดไม่ได้ (แก้ข้อมูลลูกค้า)
     · ขั้น 01 / 04 / 05 ที่กำลังทำ = ข้อความบอกว่ารอทีมไหน · ปุ่มเปิด/ยกเลิกใบงานซ่อม · ช่องบันทึกถึงฝ่ายขาย (ขั้น 02)
   - ยืนยันเงินแล้วไม่เด้งไปขั้น 04 (Account ยังต้องแนบใบเสร็จที่ขั้น 03)
   - ปุ่มกลับบนมือถือ → คิวรอยืนยันรับเงิน
   - API: เขียนได้เฉพาะคนที่**ตั้ง role** ทีม O&M ไว้ (`requireAnyRole` อ่าน role จาก DB ไม่ใช้ role ที่สวมอยู่
     — ไม่งั้นคำขอที่ไม่ส่ง header role จะโดนตัดหมด) ครอบ 12 ไฟล์ที่หน้านี้กดได้:
     follow · houses/[id]/note · bookings/[id] (PATCH) · reschedule · repair · cancel · quote-note
     · jobs/[id]/report (PUT) · jobs/[id]/photos · customers/[id] · customers/[id]/phones · customers/[id]/houses
5. คอมเมนต์ที่บอก "Account เข้าโมดูล O&M ไม่ได้ จึงยืนยันในคิว" แก้ให้ตรง (เมนูโมดูลยังไม่ให้ Account เหมือนเดิม)

## ไม่ทำ

- ไม่ให้ Account เห็นการ์ดโมดูล O&M / เมนู O&M — เข้าหน้างานจากคิวเท่านั้น แบบฝั่งขายเข้าหน้า lead จากคิว
- API ยืนยันเงิน (`/api/om/payments/[id]`) ไม่เปลี่ยน · หน้ารายรับ O&M แนบใบเสร็จได้เหมือนเดิม
- ไม่มี migration

## ข้อจำกัดที่รู้

- หน้างานเปิดตามบ้าน แสดงใบงานล่าสุดก่อน — เช็ครอเงินเข้าของใบที่ปิดไปแล้ว และบ้านมีใบใหม่แล้ว (ห่างหลายเดือน) จะไม่เจอแผงนั้น
  ทางออกตอนนี้: admin ยืนยันจากหน้างานใบนั้น · ถ้าเกิดจริงค่อยทำ `?booking=`

## ตรวจ

- `npx tsc --noEmit` · lint ไฟล์ที่แก้
- API: account-only ยิง POST follow / PATCH bookings → 403 · sales/solar ผ่านเหมือนเดิม · ยืนยันเงิน account ผ่าน
- curl `/report/pending` · `/om/services/<house>` ได้ 200

## ผลตรวจ (14 ต.ค. 69)

- `tsc --noEmit` ผ่าน · eslint ไฟล์ที่แก้ผ่าน
- API บน solardb_v3 (พอร์ต 3020) ส่งข้อมูลไม่ครบเพื่อไม่ให้บันทึกจริง:
  account อย่างเดียว (#75) ยิงทางเขียน 12 ทาง → 403 ครบ · Sale (#43) / ช่าง (#21) → 400/404 ตามเดิม (ผ่านด่านสิทธิ์)
- account (#75) อ่าน: follow / payments / quotations → 200 · หน้า `/om/services/18284` (±focus) · `/report/pending` · `/report/om` → 200
- ผู้ใช้ลองกดจริง: ขั้น 03 ยืนยันเงิน → แนบใบเสร็จตัวจริง → ปุ่มใบเสร็จชั่วคราวหายแบบฝั่งขาย (ใช้ Admin · role account ล้วนยังไม่ได้ลองผ่านหน้าจอ)
- ผู้ใช้หลาย role ที่มี account ปนกับ sales/solar (เช่น #57–60) สวม role account อยู่ = หน้าจออ่านอย่างเดียว
  แต่ API ผ่าน (เช็ค role ที่ตั้งไว้) — ตั้งใจ ไม่งั้นคำขอที่ไม่ส่ง role ที่สวมจะโดนตัด
