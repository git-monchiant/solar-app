# กันขั้นที่ปิดแล้วของใบงาน O&M ไม่ให้แก้ข้อมูลผิดลำดับ (ฝั่ง API)

ที่มา: รีวิว 28 ก.ย. 69 (ผู้ใช้ส่งรูปขั้น 01 ติดตามขึ้น DONE แต่ยังเป็นฟอร์มบันทึกการโทรที่กดได้) —
เทียบกับฝั่งขายที่ขั้นที่ปิดแล้วเป็นสรุปอ่านอย่างเดียว · ผู้ใช้สั่ง "ทำเลย" ข้อ 3 (กันที่ API) ก่อน 29 ก.ย. 69
สถานะ: **เสร็จ 29 ก.ย. 69** (เฉพาะส่วน API + ใบตรวจ · ส่วนหน้าจอยังรอเคาะ ดู "ยังไม่ทำในแผนนี้")

## ปัญหาที่เจอ (อ่านโค้ดแล้ว)

1. **บันทึกการโทรดันใบงานถอยหลังได้** — `POST /api/om/follow` หาใบงานค้างของบ้าน (รวมเข้างาน/รอปิด) แล้ว
   "ตกลงนัด" ตั้งสถานะเป็นรอยืนยันนัด · "ขอเลื่อน" ตั้งเป็นติดตาม โดยไม่เช็คลำดับสถานะ (canMove)
   ⇒ กดฟอร์มในขั้น 01 ของใบที่ช่างเข้างานแล้ว ใบงานถอยกลับได้ทันที ประวัติเห็นแค่ "บันทึกการโทร"
2. **เปลี่ยนทีม/คิว/วันนัดของใบที่จบแล้วได้** — `PATCH /api/om/bookings/[id]` ไม่เช็คสถานะ
   (ใบ #99 ถูกจ่ายทีม 23:37 หลังปิดงาน 21:07)
3. **ปิดงานจากขั้นที่ยังไม่ถึงได้** — ใบตรวจในขั้นเข้างานเปิดให้กดปิดงานแม้ใบยังรอยืนยันนัด/ยังไม่จ่ายทีม
   (หน้าเว็บเดินสถานะให้ทีละขั้นจนถึงปิดงาน)

## ทำอะไร

1. `POST /api/om/follow` — การโทรที่จะเปลี่ยนสถานะใบงานต้องผ่าน `canMove` (ลำดับสถานะกลาง) · ไม่ผ่าน = 409 พร้อมบอกให้ใช้ปุ่ม Reschedule
   (ผลโทรที่ไม่เปลี่ยนสถานะ — ไม่รับสาย/ปฏิเสธ/เบอร์ผิด — บันทึกได้เหมือนเดิม)
2. `PATCH /api/om/bookings/[id]`
   - ใบที่จบแล้ว (ปิดงาน/ยกเลิก/ไม่อยู่บ้าน) แก้ทีม/คิว/วันนัดไม่ได้ — ยกเว้นคำขอที่เปิดใบกลับมาตามลำดับสถานะ
   - เริ่มงาน (→ เข้างาน) ต้องจ่ายทีมแล้ว — ตรงกับปุ่ม "ช่างถึงหน้างานแล้ว" ที่โผล่เมื่อจ่ายทีมแล้วอยู่แล้ว
   - ปิดงาน (→ ปิดงาน) ต้องมีใบตรวจรับงานแล้ว — ทางปิดงานทางเดียวคือท้ายใบตรวจ
3. ใบตรวจ (`JobFormPanel`) — ปิดงานได้เฉพาะใบที่ยืนยันนัดแล้ว/เข้างาน/รอปิด (ช่างอยู่หน้างาน) ใบที่ยังไม่ถึงขั้นขึ้นข้อความบอก

## ยังไม่ทำในแผนนี้ (รอผู้ใช้เคาะ)

- ขั้นที่ปิดแล้วแสดงแบบฝั่งขาย (บรรทัดสรุป + กางดูอ่านอย่างเดียว) — ข้อ 1 ของรีวิว
- ขั้นที่ยังไม่ถึง: อ่านได้แต่กดไม่ได้ หรือ ล็อกแบบฝั่งขาย — ข้อ 2 ของรีวิว
- ปุ่มย้อนสถานะโดยแอดมิน (ถ้าต้องการแก้หลังปิดขั้น)

## บันทึกการทำ (29 ก.ย. 69)

- `api/om/follow` — ผลโทรที่เปลี่ยนสถานะต้องผ่าน `canMove` ไม่ผ่าน = 409 บอกขั้นปัจจุบัน
  (ถ้าใบอยู่รอยืนยันนัด/ยืนยันนัดแล้ว ต่อท้ายให้ใช้ปุ่ม Reschedule) · ผลโทรที่ไม่เปลี่ยนสถานะบันทึกได้ทุกขั้นเหมือนเดิม
- `api/om/bookings/[id]` (PATCH) — 3 ด่านก่อนเช็คลำดับสถานะเดิม: ใบจบแล้วแก้ทีม/คิว/วันนัดไม่ได้ (ยกเว้นคำขอที่เปิดใบกลับ) ·
  เข้างานต้องมีทีม (ดูทีมหลังคำขอนี้ด้วย ส่งทีมมาพร้อมกันได้) · ปิดงานต้องมีแถวใน `om_job_report`
- `JobFormPanel` — กดปิดงานท้ายใบตรวจ เช็คสถานะก่อนบันทึก ใบที่ยังไม่ยืนยันนัดขึ้นข้อความ ไม่ยิง API
- ผลทดสอบ (ใบทดสอบ #102 บ้าน 13446 ลบแล้ว · ใบ #99 ใช้ทดสอบแบบไม่เปลี่ยนข้อมูล):

  | กรณี | ผล |
  |---|---|
  | โทร "ตกลงนัด" ใบติดตาม → รอยืนยันนัด | 200 ✓ |
  | โทร "ขอเลื่อน" ใบยืนยันนัดแล้ว | 409 ✓ (บอกให้ใช้ Reschedule) |
  | โทร "ตกลงนัด" วันใหม่ ใบยืนยันนัดแล้ว → รอยืนยันนัด | 200 ✓ (ตามลำดับสถานะ) |
  | เริ่มงานโดยยังไม่จ่ายทีม | 400 ✓ |
  | จ่ายทีม แล้วเริ่มงาน | 200 ✓ |
  | โทร "ตกลงนัด" / "ขอเลื่อน" ระหว่างเข้างาน | 409 ✓ ทั้งคู่ |
  | โทร "ไม่รับสาย" ระหว่างเข้างาน | 200 ✓ สถานะไม่ขยับ |
  | ปิดงานโดยไม่มีใบตรวจ | 400 ✓ |
  | ยกเลิก → จ่ายทีม / ตั้งวันนัด ใบที่ยกเลิก | 400 ✓ ทั้งคู่ |
  | เปิดใบที่ยกเลิกกลับเป็นติดตาม | 200 ✓ |
  | จ่ายทีมใบ #99 ที่ปิดงานแล้ว | 400 ✓ ข้อมูลไม่เปลี่ยน |
  | กดปิดงานท้ายใบตรวจ ใบที่ยังติดตาม (หน้าจอ) | ขึ้นข้อความ ✓ สถานะไม่เปลี่ยน |

- ข้อมูลเดิมที่ผิดอยู่แล้ว (ใบ #99 จ่ายทีมหลังปิดงาน) ไม่ได้แก้ย้อน — ทีมที่ติดอยู่ตรงกับทีมที่ทำงานจริงหรือไม่ ต้องให้ผู้ใช้ดู
