# แจ้งเตือนผู้อนุมัติใบเสนอราคา B2B ในกระดิ่ง

สถานะ: **done** (15 ต.ค. 69) · ข้อ 2 ของลำดับงาน "ฟังก์ชันหลักก่อน" (แผน [20261015-10](20261015-10-b2b-survey-files.md))
· ค้างมาตั้งแต่แผน [20261015-07](20261015-07-b2b-project-flow.md) เฟส 2 ("กระดิ่งแจ้งเตือน — ผู้ใช้ให้ทำทีหลัง")

## ที่มา / ข้อจำกัดที่เจอตอนสำรวจ

- ใบเสนอราคา B2B ต้องผ่านผู้ตรวจสอบ 3 ชั้น — ก่อนหน้านี้รู้ได้จาก badge เมนู "อนุมัติ B2B" อย่างเดียว ใบค้างโดยไม่มีใครเห็นได้
- กระดิ่งกลาง (`components/layout/NotificationBell.tsx`) ดึง `/api/notifications` = UNION ตารางแจ้งเตือนใบเสนอราคา B2C + บัญชี
  - ใช้ตารางเดิมไม่ได้: `quotation_approval_notifications` ผูก FK กับ `quotations` (B2C) + ต้องมี `lead_id`
  - **ห้ามใส่ตาราง B2B ใน UNION**: API กลางต่อ `getDb()` ที่อาจเป็นฐาน v2 — ตาราง v3 ใน batch เดียวทำกระดิ่งพังทุกคน (เหตุผลเดียวกับที่ O&M แยกแจ้งเตือนไปไว้เมนูของตัวเอง)

## เคาะ (15 ต.ค. ผู้ใช้ "ตามเสนอ")

แยกตาราง + แยก API แล้วให้กระดิ่งดึงมารวมฝั่งหน้าจอ — ไม่แตะ query ของ API กลาง · แก้ไฟล์กลางฝั่งหน้าจอ 3 ไฟล์

## ทำอะไร

- ตาราง `b2b_notifications` (migration `20261015-2340_b2b_notifications.sql` รันบน solardb_v3 แล้ว) — ผู้รับ · kind · โครงการ · ใบ · ชั้น · หัวข้อ/ข้อความ · read_at · resolved_at
- `src/lib/b2b/notifications.ts`: `notifyB2bRole` (role + admin แบบ B2C · ไม่แจ้งคนกดเอง) · `notifyB2bUser` · `resolveB2bQuoteNotifications`
- เหตุการณ์ (ใน transaction ของ `/api/b2b/quotations/[id]/action`):

  | เหตุการณ์ | แจ้งใคร | หัวข้อ |
  |---|---|---|
  | ส่งอนุมัติ | ผู้ตรวจสอบ 1 (+ admin) | B2B รออนุมัติ ผู้ตรวจสอบ 1 · โครงการ |
  | ชั้น 1 / 2 อนุมัติ | ผู้ตรวจสอบชั้นถัดไป (+ admin) | B2B รออนุมัติ ผู้ตรวจสอบ N · โครงการ |
  | ชั้น 3 อนุมัติ | คนส่งใบ | B2B อนุมัติครบ 3 ชั้น · โครงการ (ส่งลูกค้าได้) |
  | ส่งกลับแก้ | คนส่งใบ | B2B ส่งกลับแก้ (ผู้ตรวจสอบ N) · โครงการ + เหตุผล |

  ชั้นที่มีคนกดแล้ว → แจ้งเตือนของคนอื่นในชั้นนั้น "ดำเนินการแล้ว" (ไม่นับยังไม่อ่าน) · ส่งใหม่หลังส่งกลับ → รอบเก่าปิดทั้งหมด
- API `/api/b2b/notifications` (ผู้ใช้ที่ล็อกอิน): GET `?summary=1` / รายการ 50 ล่าสุดในรูปเดียวกับแจ้งเตือนกลาง (`notification_source: "b2b"`)
  · ปลายทาง: ยังรอชั้นที่แจ้ง → `/b2b/approvals?quote=<id>` (คิวเลือกใบให้) · ไม่งั้นหน้าใบเสนอราคา · PATCH อ่านแล้ว/อ่านทั้งหมด (เฉพาะของตัวเอง)
  · ฐานที่ไม่ใช่ v3/ยังไม่รัน migration → ตอบว่าง (กระดิ่งเดิมไม่พัง)
- หน้าจอ: `NotificationBell.tsx` · `notifications/page.tsx` · `lib/notification-navigation.ts` — ดึง 2 แหล่งมารวม (เรียงตามเวลา · badge รวม)
  · ดึงส่วน B2B เฉพาะผู้ใช้ที่ **ได้รับ** role B2B/ผู้ตรวจสอบ/admin (ไม่ใช่ role ที่สวมอยู่ — ผู้ตรวจสอบที่สวม role อื่นไม่พลาด) ผู้ใช้ B2C ล้วนไม่ยิงเพิ่ม
  · หน้าอนุมัติ B2B รับ `?quote=` เลือกใบนั้นถ้ายังอยู่ในคิว
- สคริปต์ล้างข้อมูลเทสลบแจ้งเตือนของใบ/โครงการทดสอบก่อนลบใบ

## ทดสอบ

- ใบ A: ส่ง (admin 1) → ชั้น 1 (admin 5) → ชั้น 2 (admin 19) → ชั้น 3 (admin 5): แจ้งถูกคนทุกชั้น · คนกดไม่ได้แจ้งตัวเอง · ของคนอื่นในชั้นปิดเอง · ครบ 3 ชั้นแจ้งคนส่ง
- ใบ B: ส่ง → ส่งกลับ (เหตุผลถึงคนส่ง) → ส่งใหม่ (รอบเก่าปิด เหลือรอบใหม่ 1) · อ่านทีละรายการ/ทั้งหมด · อ่านของคนอื่นไม่ได้ · ไม่ล็อกอิน 401
- หน้าจอ: กระดิ่ง admin 5 ขึ้น 1 → กดแล้วเข้าคิวอนุมัติเลือกใบถูก · หน้าการแจ้งเตือนรวม B2B กับของเดิม ไม่มี error · ลบข้อมูลทดสอบแล้ว

## ข้อสังเกต

- แจ้ง admin ทุกคนตามแบบ B2C — ฐาน v3 ตอนนี้มี admin 7 คน จะได้แจ้งเตือน B2B ทุกชั้น (ถ้ารกค่อยตัด admin ออกภายหลัง)
- ยังไม่ทำ: แจ้งบัญชีเมื่อแนบหลักฐานรับเงินงวด B2B (ใช้ตารางเดียวกันได้) · เตือนซ้ำใบที่ค้างนาน (B2C มี approval_reminder)
