ที่มา: ผู้ใช้ขอ 7 ต.ค. 69 "เพิ่มหัวข้อในการ search ลูกค้าที่มาจากระบบขาย"
(ถามต่อจากการ์ดบ้าน 311/77 ที่ระบบกวาดงานขายเข้ามาเอง — `src/lib/om/sales-sweep.ts`)

สถานะ: **เสร็จ 7 ต.ค. 69**

## ผู้ใช้เลือก (7 ต.ค.)

- ใส่ **3 หน้า**: งานบริการ `/om/services` · บ้าน / ระบบติดตั้ง `/om/houses` · ลูกค้า `/om/customers`
- รูปแบบ = **Dropdown "ที่มา"** แบบช่อง "ช่องทาง" ของหน้า Pipeline (ไม่ใช่ติ๊ก)

## นิยาม — ที่เดียวใน `src/lib/om/house-origin.ts`

| ค่า | ป้าย | บ้าน | ลูกค้า |
|---|---|---|---|
| ว่าง | ทุกที่มา | ไม่กรอง | ไม่กรอง |
| `sales` | B2C (เดิม "จากงานขาย" · ผู้ใช้เปลี่ยนชื่อ 7 ต.ค.) | มีระบบติดตั้งที่ `om_installations.lead_id` ไม่ว่าง (ตัวกันซ้ำของ sales-sweep — ทั้งกวาดอัตโนมัติและแอดมินรับจากคิว) | ผูกอยู่ (`is_current = 1`) กับบ้านจากงานขายอย่างน้อย 1 หลัง |

- บ้านจากทะเบียนที่ภายหลังมีงานขายติดตั้ง (เช่น 311/77) นับเป็น "จากงานขาย" — ระบบโซลาร์ขายโดยทีมขาย
- ข้อมูลจริง solardb_v3 (7 ต.ค.): บ้านจากงานขาย 5 หลัง (lead 400 · 408 · 421 · 661 · 691) ที่เหลือมาจากทะเบียน/REM/ไฟล์นำเข้าทั้งหมด

## ตัวเลขต้องตรงกับที่เห็น (กติกา ui-rules)

- งานบริการ: ตัวเลขบนแท็บกรองตาม "ที่มา" ด้วย (แบบติ๊ก "งานของฉัน")
- บ้าน: ตัวเลขบนแท็บ + dropdown โครงการ มาจาก `/api/om/houses/groups` → ส่ง `origin` ไปด้วย
- ลูกค้า: แท็บไม่มีตัวเลขอยู่แล้ว · จำนวนคนที่ tabsLeft มาจาก total ของ API ตามตัวกรอง

## ไฟล์ที่แก้

- ใหม่ `src/lib/om/house-origin.ts` — ตัวเลือก + SQL นิยาม (ไม่ import อะไร ใช้ได้ทั้งหน้าจอและ API)
- API: `om/follow` · `om/houses` · `om/houses/groups` · `om/customers` รับ `origin=` (ไม่ส่ง = เหมือนเดิม)
- หน้า: `om/services` · `om/houses` · `om/customers` — Dropdown ต่อจากช่องโครงการ (หน้าลูกค้าไม่มีช่องโครงการ → เพิ่มแถวเครื่องมือแบบหน้าบ้าน)
- ไม่มี migration · ไม่แตะ `follow-sql.ts` (กรองตอนเลือกจาก #x)
