## 1. เช็คเด้งหลังรับเช็คแล้ว (หนัก)

ปัญหา: Account กด "ปฏิเสธ" เช็คที่รับไปแล้ว → API ลบแถวเงินทิ้ง ไม่ดูสถานะใบงาน
ใบงานที่โทรนัดไปแล้วเดินต่อจนปิดงานโดยไม่มีเงิน · Sale ได้แจ้งเตือน "แนบใหม่" แต่แนบไม่ได้ (API รับเฉพาะขั้นชำระเงิน)

ฝั่งขายทำ (`api/(payment)/payments/[id]` cheque_failed=bounced): เก็บแถวไว้ ล้าง `cheque_received_*` ตั้ง `cheque_status='bounced'` + เหตุผล

ทำ:
- `POST /api/om/payments/[id]` action ใหม่ `cheque_bounced` (ต้องมีเหตุผล · เฉพาะเช็คที่รับแล้วและยังไม่ยืนยันเงินเข้า)
  เขียนคอลัมน์ชุดเดียวกับฝั่งขาย · `reject` เช็คที่รับแล้ว = ปฏิเสธ ให้ใช้ "เช็คเด้ง" แทน (แถวต้องไม่หาย)
- ใบงาน: รอยืนยันนัด/นัดแล้ว → กลับขั้นชำระเงิน (หลุดจากปฏิทิน/แจ้งเตือนนัดเองเพราะกรองตามสถานะ)
  เข้างาน/รอปิด/ปิดงานแล้ว → คงสถานะ (งานเกิดไปแล้ว) แต่แนบหลักฐานชำระใหม่ได้จากการ์ดขั้น 03
- แถวที่เด้งไม่นับเป็นเงินที่ค้างอยู่: แนบซ้ำ · ล็อกเปลี่ยนชุด · ขั้นย่อย "รอยืนยัน" · คิว Account · ยอดรอยืนยันในรายงาน · ปุ่มยกเลิกใบงาน
  (ตัวช่วย SQL `OM_PAY_LIVE_SQL` ที่เดียว)
- `pay_state` ใหม่ `bounced` (ไม่มีแถวที่ยังใช้ได้ + มีแถวเด้ง) — บรรทัดสรุปขั้น 03 บอก "เช็คเด้ง — รอชำระใหม่"
- แจ้ง Sale ในกล่อง O&M "เช็คเด้ง — แนบหลักฐานชำระใหม่" · ลงประวัติใบงาน `pay_cheque_bounced`
- หน้าจอ: คิว Account (OmPendingPayments) และแผงขั้น 03 — เช็คที่รับแล้วปุ่มแดงเป็น "เช็คเด้ง" แทน "ปฏิเสธ"
  · แผงขั้น 03 แสดงแถวที่เด้ง (เหตุผล/ผู้บันทึก/เวลา) เหนือฟอร์มแนบใหม่

## 2. PATCH ใบงานข้ามการอนุมัติ/การจ่ายเงิน (กลาง)

ปัญหา: `PATCH /api/om/bookings/[id]` ตรวจแค่ canMove — `quote → payment` ข้ามการอนุมัติ · `payment → pending/confirmed` ข้ามการจ่ายเงิน

ทำ:
- `NEXT.quote` เหลือ `cancelled` — ออกจากขั้นเสนอราคาได้ทาง `/send` (เขียนสถานะเอง) เท่านั้น · ไม่มีหน้าจอไหนใช้ PATCH ย้าย quote→payment/follow
- PATCH `payment → pending/confirmed` ต้องผ่าน `OM_BOOKING_PAID_SQL` (กติกาเดียวกับ /api/om/follow)

## 3. บันทึกก่อนรายการแพ็กเกจโหลดเสร็จ ยอดผิด (กลาง)

ปัญหา: popup ทำใบคิดยอดจาก `pkgs.find()` — ยังโหลดไม่เสร็จ/โหลดพลาด แพ็กเกจเป็น null แต่ส่ง `om_package_id` ไป
ส่วนลดถูกตัดตามยอดที่ขาดแพ็กเกจ + รายละเอียดใต้แพ็กเกจหาย (เช่น 2,500+300 ลด 500 = 2,300 → บันทึกได้ 2,500)

ทำ: สถานะโหลดแพ็กเกจ `loading / ready / error` · ปุ่มบันทึก/ดูตัวอย่างกดได้เมื่อ ready
· โหลดพลาด = ปุ่ม "+ เพิ่มแพ็กเกจ" เป็น "โหลดแพ็กเกจไม่สำเร็จ — ลองใหม่"
· ใบเดิมที่แพ็กเกจถูกปิดใช้งานแล้ว = แถวเตือนพร้อมปุ่มลบ (เดิมไม่มีแถวให้ลบ บันทึกได้ 500)

## 4. ทำรายการไม่สำเร็จแล้วจอไม่ตรงฐาน (กลาง)

ปัญหา: `run()` โหลดใหม่เฉพาะตอนสำเร็จ — ส่งอนุมัติ 2 ชุด ชุด 1 ผ่าน ชุด 2 พัง จอยังโชว์ชุด 1 เป็นร่าง กดซ้ำติดชุด 1 ตลอด

ทำ: โหลดใหม่ทั้งตอนสำเร็จและไม่สำเร็จ · `load()` สำเร็จล้าง error เดิม (เดิมพลาดครั้งเดียวกล่องแดงบังทั้งแผงจนรีเฟรช)

## ไม่ทำ (ข้อเล็กจากรีวิว — รอผู้ใช้สั่ง)

ใบซ่อมยอด 0 ไปติดตอนส่งอนุมัติ · แก้เงื่อนไขแล้วเปลี่ยนแพ็กเกจ ขอบเขตงานเดิมค้าง · ยืนยันเงินเช็คไม่ตั้ง cleared
· ยอดสรุปคิว Account ไม่รวมค่าธรรมเนียมบัตร · บันทึกถึงฝ่ายขายพลาดเงียบ · เปลี่ยนชุดชนแนบสลิป · เลขใบซ้ำหลังลบร่าง
