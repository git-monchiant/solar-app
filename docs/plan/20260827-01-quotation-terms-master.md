## เป้าหมาย

ให้ Sale แก้เงื่อนไข/ข้อกำหนดของใบเสนอราคาได้จากหน้าจอ — แก้ถ้อยคำ เพิ่ม ลบ และเรียงลำดับ
ได้ทั้งหัวข้อและบรรทัด **เฉพาะใบนั้น** โดยที่ใบเสนอราคาที่อนุมัติไปแล้วต้องคงถ้อยคำเดิมไว้ตลอด

ทุกวันนี้แก้ได้แค่ 3 อย่าง — จำนวนวันยืนราคา, การตั้งค่า O&M และ textarea "เงื่อนไขเพิ่มเติม"
ที่ต่อท้ายได้อย่างเดียว ส่วนอีก 11 บรรทัดที่เหลือแก้ไม่ได้เลยนอกจากแก้โค้ดแล้ว deploy

## สถาปัตยกรรมที่เสนอ

### 1. โครงข้อมูล — ไม่มีตารางใหม่

เก็บชุดเงื่อนไขของใบไว้ใน `quotations.document_inputs_json` (คอลัมน์ `NVARCHAR(MAX)` เดิม)
ใต้คีย์ `terms` เก็บเป็น **ต้นไม้เต็มชุด** ไม่ใช่ diff — เพราะเมื่อลบ/เพิ่ม/เรียงลำดับได้อิสระ
การเก็บส่วนต่างจะเปราะและ merge ยาก

```json
{
  "terms": {
    "profile": "full_install",
    "seeded_from": "standard-v1",
    "sections": [
      {
        "key": "warranty",
        "title": "รายละเอียดการรับประกันสินค้า",
        "page": 1,
        "show_when": "always",
        "kind": "normal",
        "lines": [
          { "key": "w1", "body": "การรับประกัน แผงโซลาร์เซลล์ ...", "origin": "standard" },
          { "key": "w4", "body": "ยืนยันราคาภายใน {{valid_days}} วัน ...", "origin": "standard" },
          { "key": "c-a1b2", "body": "ลูกค้าเตรียมพื้นที่ ...", "origin": "custom" }
        ]
      }
    ],
    "removed": [
      { "key": "w3", "body": "การรับประกัน BATTERY ...", "section_key": "warranty" }
    ]
  }
}
```

- `key` ของบรรทัดมาตรฐานคงที่ตลอด ใช้เทียบกับชุดในโค้ดเพื่อรู้ว่า**แก้ถ้อยคำแล้วหรือยัง**
  (ไม่ต้องเก็บ flag `edited` — คำนวณจากการเทียบ)
- `origin: "custom"` = ผู้ใช้เพิ่มเอง ไม่มีคู่ในชุดมาตรฐาน
- `removed` เก็บข้อมาตรฐานที่ถูกลบไว้ ให้กด **"คืนข้อที่ลบ"** ได้ และใช้นับ "ต่างจากมาตรฐาน N จุด"
- ใบที่ยังไม่มีคีย์ `terms` (ใบเก่า/ใบที่ยังไม่เปิดแท็บ) → เรนเดอร์จากชุดมาตรฐานในโค้ดเหมือนเดิม
  **ไม่ต้อง backfill**

### 2. บรรทัดที่ล็อก

`locked: true` เป็นคุณสมบัติของบรรทัดใน**ชุดมาตรฐานในโค้ด** ไม่ได้เก็บใน JSON
ตอนโหลดขึ้นหน้าจอ ให้จับคู่ด้วย `key` แล้วบังคับ: ลบไม่ได้ · แก้ถ้อยคำไม่ได้ · เลื่อนลำดับได้
API ต้องบังคับซ้ำฝั่ง server ด้วย ไม่ใช่แค่ซ่อนปุ่มใน UI

รอบแรกล็อกไว้ 1 บรรทัด (ข้อ 2.3 "หากมีการเปลี่ยนแปลงจากที่ตกลง...") — เพิ่ม/ลดได้ในโค้ด

### 3. ตัวแทนค่า (placeholder) และปุ่มแทรก

เก็บในข้อความเป็น `{{key}}` แต่**หน้าจอไม่ให้พิมพ์เอง** — แสดงเป็นป้ายสีที่ลบได้ทั้งก้อน
แต่พิมพ์ทับข้างในไม่ได้ พร้อมแถบปุ่ม "แทรกค่า" และบรรทัดพรีวิว**ที่ใช้ค่าจริงของใบนั้น**
(ดีกว่าแผนเดิมที่ต้องเลือกใบตัวอย่างมาลองแทนค่า)

| key | ป้ายที่ผู้ใช้เห็น | มาจาก |
|---|---|---|
| `valid_days` | จำนวนวันยืนราคา | `quotations.valid_days` |
| `om_years` | จำนวนปี O&M | `document_inputs.om.coverage_years` |
| `om_visits` | จำนวนครั้ง/ปี (รวม) | ความถี่ร่วมของบริการที่เปิด (null ถ้าไม่เท่ากัน) |
| `install_warranty_years` | จำนวนปีรับประกันงานติดตั้ง | ค่าตั้งใหม่ (เดิม hardcode "2 ปี" ในข้อ 2.5) |
| `service_visits` | จำนวนครั้ง/ปี (ของบริการนี้) | เฉพาะใน section `kind='om_services'` |
| `service_years` | จำนวนปี (ของบริการนี้) | เฉพาะใน section `kind='om_services'` |

หน้าจอต้องเตือนเมื่อผู้ใช้แทรก `service_*` นอก section `om_services`

### 4. เครื่องไล่เลขข้อ

ไล่เลขตอนเรนเดอร์ ไม่เก็บลงฐานข้อมูล:

- นับเฉพาะ section ที่ผ่านเงื่อนไข `show_when` แล้ว → 1, 2, 3, ...
- นับ line ในแต่ละ section → `<เลข section>.<ลำดับ>`
- ผลที่ได้จะทำให้พฤติกรรม "ปิด O&M แล้วเงื่อนไขเพิ่มเติมเด้งจากข้อ 4 เป็น 3" เกิดขึ้นเอง
  โดยไม่ต้องเขียนเงื่อนไขพิเศษ

### 5. การแช่แข็ง (ตอบข้อ "ไม่ย้อนหลัง")

เพิ่มคีย์ `legal` เข้าไปใน `document_snapshot_json` ที่ freeze ตอน submit อยู่แล้ว
([action route:208](<../../src/app/api/(lead)/quotations/[id]/action/route.ts>))
เก็บเป็น**ข้อความที่เรนเดอร์เสร็จสมบูรณ์แล้ว** (ไล่เลข + แทนค่า placeholder เรียบร้อย)

- ไม่ต้องเพิ่มคอลัมน์ → **ไม่มี migration**
- bump `QUOTATION_DOCUMENT_VERSION` จาก 4 เป็น 5
- PDF อ่านจาก snapshot ก่อนเสมอ ถ้าไม่มี (ใบ draft / ใบเก่าก่อนเฟส 0) จึงคำนวณสด

## ความเสี่ยง

1. **PDF ตัดหน้าด้วย heuristic นับแถว** — เงื่อนไขที่ยาวได้อิสระจะทับเลขหน้า และ PDF
   บังคับต้องได้ 17 หน้าพอดี ไม่งั้น generate ไม่ผ่านทั้งใบ
   *รับมือ*: เฟส 1 คงพฤติกรรมเดิมไว้ทั้งหมด (ข้อความเท่าเดิม จำนวนบรรทัดเท่าเดิม)
   เฟส 2 เพิ่มแถบโควตาบรรทัดต่อหน้า + เตือนก่อนบันทึก
2. **แปลงชุดมาตรฐานผิด** — ถอดเลขข้อหรือแปลง placeholder พลาดแม้ตัวอักษรเดียว
   *รับมือ*: เทสเทียบ PDF ก่อน/หลังตามข้างบน ต้องตรงทุกตัวอักษรก่อน merge
3. **Sale ลบข้อกฎหมายทิ้ง** — เพราะตอนนี้ลบได้จริง ไม่ใช่แค่ปิด
   *รับมือ*: `locked` บังคับทั้งฝั่ง UI และ server · แถบ "คืนข้อที่ลบ" ให้กดคืนได้ตลอด ·
   ผู้อนุมัติเห็น "ต่างจากมาตรฐาน N จุด" ในใบก่อนกดอนุมัติ
4. **ใบที่ค้างสถานะ draft ตอนแก้ชุดมาตรฐานในโค้ด** — ใบที่เปิดแท็บแล้ว (มีคีย์ `terms`)
   จะไม่รับข้อความใหม่ ส่วนใบที่ยังไม่เคยเปิดจะรับ
   *รับมือ*: ตั้งใจให้เป็นแบบนี้ แต่ต้องเขียนบอกใน UI ให้ชัด และปุ่ม
   "คืนค่าชุดมาตรฐานทั้งหมด" ดึงของใหม่มาให้ได้เสมอ
