# ขั้นที่ปิดแล้ว/ยังไม่ถึง ของหน้ารายละเอียดงานบริการ — แบบฝั่งขาย

ที่มา: รีวิว 28 ก.ย. 69 (ขั้น 01 ติดตามขึ้น DONE แต่ยังเป็นฟอร์มบันทึกการโทรที่กดได้) ต่อจาก [20260929-01](20260929-01-om-step-guards.md)
ผู้ใช้เคาะ 29 ก.ย. 69: "1. แบบฝั่งขาย 2. แบบฝั่งขาย 3. ข้ามไปก่อน"
- ข้อ 1 ขั้นที่ปิดแล้ว = บรรทัดสรุป + ปุ่มเอกสาร กดกางดูอ่านอย่างเดียว (StepLayout โหมด done ของฝั่งขาย)
- ข้อ 2 ขั้นที่ยังไม่ถึง = ล็อกแบบฝั่งขาย (ราง STEPS กดไม่ได้ · การ์ดไม่มีเนื้อใน)
- ข้อ 3 ปุ่มย้อนสถานะโดยแอดมิน — ข้ามไปก่อน

สถานะ: **เสร็จ 29 ก.ย. 69** (ของเดิมก่อนแก้อยู่ที่ commit 257eddd เผื่อสั่งกลับ)

## คงไว้ (ตกลงไว้แล้วในแผน 20260928-04)

- ราง STEPS ดูทีละขั้น ไม่เปลี่ยนเป็นกองการ์ด ⇒ ใช้แบบโหมด focus ของฝั่งขาย: เปิดขั้นที่ปิดแล้วเมื่อไร กางสรุปให้เลย

## จุดที่ต้องขยับ ไม่งั้นงานเดินต่อไม่ได้ (เจอตอนไล่โค้ด)

1. **โทรตกลงวันนัดหลังรับเงิน** — เดิมให้กลับไปบันทึกการโทรที่ขั้น 01 (ซึ่งตอนนั้นปิดขั้นไปแล้ว)
   ⇒ ใบที่ Account ยืนยันรับเงินแล้วถือว่า **อยู่ขั้นนัดหมาย** (สถานะในฐานยังเป็น payment จนตกลงนัด)
   ฟอร์มโทรตกลงวันนัดอยู่การ์ดนัดหมาย แบบขั้นย่อย "นัด" ของ Install ฝั่งขาย
   · ตำแหน่งนี้ใช้ตัวช่วยเดียว (`jobAt`) ทั้งรางหน้ารายละเอียดและแถบในการ์ดหน้ารายการ
2. **บ้านสิทธิ์หมด** — ต้องออกใบเสนอราคา (ขั้น 02) ตั้งแต่ยังอยู่ขั้นติดตาม ⇒ ขั้น 02 เปิดคู่กับขั้น 01 เฉพาะกรณีนี้
3. **ข้อมูลจะตัดสิทธิ์กี่ครั้ง** ที่เดิมอยู่ในการ์ดปิดงานตอนยังไม่ถึง ⇒ ย้ายไปบอกในการ์ดเข้างาน

## ทำอะไร

- `service-view.ts` — `jobAt()` ตำแหน่งงานบนราง (flowIndex + ชำระครบแล้ว = นัดหมาย) · `JobCard` ใช้ตัวเดียวกัน
- `JobTimelineTab.tsx` — แยกการจัดประวัติตามใบงาน/ขั้น (`bookingStages`) และตัววาดเหตุการณ์ในขั้น (`StageEvents`) ออกมาใช้ร่วม
  ⇒ สรุปขั้นที่ปิดแล้ว = เหตุการณ์ของขั้นนั้นชุดเดียวกับแท็บ Timeline (ป้ายไม่เพี้ยนสองที่)
- `JobDetail.tsx`
  - สถานะขั้น: active · done · skipped · **locked** (แทน upcoming)
  - ราง: ขั้นที่ล็อกกดไม่ได้ (คลาสเดียวกับฝั่งขาย) · การ์ดล็อก = หัวอย่างเดียว
  - การ์ดที่ปิดแล้ว: หัวเปลี่ยนเป็นชื่อ "…แล้ว" + ✓ DONE/PAID · เนื้อในเป็น `StepLayout` โหมด done (บรรทัดสรุป + ปุ่มเอกสาร · กางดู)
    | ขั้น | บรรทัดสรุป | กางดู |
    |---|---|---|
    | 01 ติดตาม | โทรกี่ครั้ง · ผลล่าสุด | เหตุการณ์ขั้นติดตาม (การโทร · เปิดใบงาน) |
    | 02 เสนอราคา | เลขใบ · สถานะ · ยอด + ปุ่มใบเสนอราคา | แผงใบเสนอราคา (ตอนปิดขั้นแล้วไม่มีปุ่มแก้อยู่แล้ว) |
    | 03 ชำระเงิน | ชำระแล้ว · ยอด | แผงชำระเงิน (สลิป · ผู้ยืนยัน) |
    | 04 นัดหมาย | วันนัด · ทีม | เหตุการณ์ขั้นนัดหมาย (ยืนยัน · จ่ายทีม · ประวัติเลื่อนนัด) |
    | 05 เข้างาน | ผลตรวจ · เลขใบบริการ + ปุ่มใบบริการ | ใบตรวจ (ล็อกอ่านอย่างเดียวอยู่แล้ว) |
    | 06 ปิดงาน | วันปิด · ตัดสิทธิ์ไหม + ปุ่มใบบริการ | เหตุการณ์ปิดงาน + เปิดใบงานซ่อม (งานถัดไป ไม่ใช่แก้ใบนี้) |
  - ฟอร์มบันทึกการโทรแยกเป็นก้อนเดียว ใช้ทั้งขั้น 01 (ครบ 5 ผล) และการ์ดนัดหมายตอนรับเงินแล้ว (ตกลงนัด · ไม่รับสาย · ขอเลื่อน)
- `OmPaymentPanel.tsx` — ข้อความหลังรับเงินชี้ไปการ์ดนัดหมายแทนขั้น 01
