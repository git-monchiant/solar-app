# ใบเสนอราคา O&M ได้สูงสุด 3 ชุดต่อใบงาน — แบบฝั่งขาย

ที่มา: ผู้ใช้ขอ 2 ต.ค. 69 "ปรับให้สร้างได้สูงสุด 3 ใบเหมือนงานขาย" ต่อจาก [20261002-01](20261002-01-om-quote-like-sales.md)

สถานะ: **เสร็จ 2 ต.ค. 69**

## ฝั่งขายทำอย่างไร

ชุด 1–3 ต่อ lead (`quotations.option_no`) · แต่ละชุดมี Revision ของตัวเอง · ส่งอนุมัติทีเดียวทุกฉบับที่ร่าง
· อนุมัติครบทุกฉบับแล้วส่งให้ทีมขาย → ลูกค้าเลือก 1 ชุดที่ขั้น Order แล้วจ่ายเงินตามชุดนั้น

## O&M ไม่มีขั้น Order — ลูกค้าเลือกที่ขั้น 02 เลย

- อนุมัติครบทุกชุดแล้ว การ์ดแต่ละชุดมีปุ่ม **"✓ ลูกค้าเลือกชุดนี้"** = ทาง `/send` เดิม (จดเวลาส่งลูกค้าที่ใบนั้น + ใบงานไปขั้นชำระเงิน)
  เดิม "ส่งใบให้ลูกค้าแล้ว" = ไปขั้นชำระเงินทันที — ตอนนี้ไปเมื่อรู้แล้วว่าลูกค้าเอาชุดไหน
- **"ใบของใบงาน"** (q_id ที่ขั้นชำระเงิน/บรรทัดสรุป/แท็บรายการใช้) = ใบที่ลูกค้าเลือก ถ้ายังไม่เลือก = ใบล่าสุดเหมือนเดิม
  ⇒ ข้อมูลเก่า (ใบเดียว ส่งแล้ว) ได้ใบเดิมทุกตัว ไม่ต้อง migrate (ใบ O&M ทุกใบในฐานเป็นชุด 1 อยู่แล้ว)
- ต้องอนุมัติครบทุกชุดก่อนให้ลูกค้าเลือก (แบบฝั่งขาย) — ไม่งั้นชุดที่ค้างรออนุมัติจะค้างในคิวผู้อนุมัติตลอดไป
  ชุดที่ร่างทิ้งไว้ ลบได้ (ปุ่มถังขยะแบบฝั่งขาย)

## ทำอะไร

| ที่ | แก้ |
|---|---|
| `POST /api/om/quotations` | รับ `option_no` 1–3 · ใบงานขั้นเสนอราคาเพิ่มชุดได้ ห้ามซ้ำชุดเดิม (ยกเว้นยกเลิกแล้ว) |
| `GET /api/om/quotations?booking_id=` (ใหม่) | ทุกใบของใบงาน — ตัวอ่านเดียวกับ `[id]` (ย้ายไป `lib/om/om-quotation.ts`) |
| `DELETE /api/om/quotations/[id]` (ใหม่) | ลบฉบับร่างของ O&M — ลงประวัติใบงาน ไม่ใช้ DELETE ฝั่งขาย (ตัวนั้นเขียน lead_activities ปนไทม์ไลน์ขาย) |
| `/send` | ใบล่าสุด**ของชุดนั้น** · ทุกชุดอนุมัติแล้ว · ป้ายประวัติ "ลูกค้าเลือกชุด N" |
| `/api/om/payments` · `[id]` latest_id | "ใบล่าสุด" นับในชุดเดียวกัน · รับเงินได้เฉพาะใบที่ลูกค้าเลือก |
| `/api/quotations/[id]/action` revise | เลข Revision ของ O&M นับในชุดเดียวกัน |
| `follow-sql` · `journey-sql` | ใบของใบงาน = ใบที่ลูกค้าเลือกก่อน แล้วค่อยใบล่าสุด |
| `OmQuotationPanel` | การ์ดชุด 1–3 + การ์ดว่าง "สร้างใบเสนอราคาชุดที่ N" · ปุ่มยาวส่งอนุมัติทุกฉบับ / รออนุมัติ a/b ฉบับ · ปุ่มลูกค้าเลือก · ลบร่าง |

## ไม่ทำ

- ไม่แตะ PDF / คิวอนุมัติ / การเติมสิทธิ์ (ทำงานรายใบอยู่แล้ว) · ไม่มี migration

## ตรวจ

- tsc · eslint · curl · ลองจริงบน solardb_v3 กับบ้านทดสอบ แล้วลบข้อมูลที่ลองทิ้ง

## บันทึกการทำ (2 ต.ค. 69)

- ทำครบตามตาราง "ทำอะไร" · เพิ่มระหว่างทาง: ป้ายประวัติ (แท็บ Timeline + Activity Log) "ออกใบเสนอราคาชุด N" / "ลูกค้าเลือกใบเสนอราคาชุด N" / "ลบใบเสนอราคาฉบับร่าง"
  — ประวัติเก่าที่ไม่มี option_no คงป้ายเดิม
- การ์ดชุดที่ลูกค้าเลือก = กรอบเขียว + ป้าย "ลูกค้าเลือก" · ชุดอื่นจางลง · กล่องเขียวใต้การ์ดบอกขั้นถัดไป
- ผลตรวจ: tsc / eslint ผ่าน · ลองจริงผ่าน API บน solardb_v3 กับบ้าน 311/77 (#16771 — ไม่เคยมีใบงาน, lead 400 ไม่ถูกแตะ) แล้วลบทิ้งหมด

  | ลอง | ผล |
  |---|---|
  | สร้างชุด 1 + ชุด 2 | ใบงานเดียวกัน (#137) |
  | สร้างชุด 2 ซ้ำ / ชุด 4 | 409 / 400 |
  | ลบชุด 2 ฉบับร่าง แล้วสร้างใหม่ | ได้ · รายการของใบถูกลบด้วย |
  | ลูกค้าเลือกตอนยังรออนุมัติ | 409 |
  | อนุมัติครบ 2 ขั้นทั้ง 2 ชุด → Revision ชุด 1 | latest_id ชุด 1 ย้ายไปใบ Revision · ชุด 2 ไม่กระทบ |
  | ลูกค้าเลือกชุด 2 ตอนชุด 1 มี Revision ร่างค้าง / เลือกใบเก่าของชุด 1 | 409 ทั้งคู่ |
  | ลบ Revision ร่าง → ลูกค้าเลือกชุด 2 | ใบงานไปขั้นชำระเงิน · q_id ของใบงาน = ชุด 2 (#111) ยอด 3,500 |
  | Revision / สร้างชุด 3 หลังลูกค้าเลือก | 409 ทั้งคู่ |

- ถ่ายจอ 4 จังหวะ (ร่าง 2 ชุด + การ์ดว่างชุด 3 · รอ Sale Manager · อนุมัติครบมีปุ่มลูกค้าเลือก · เลือกแล้วขั้น 02 DONE ไปขั้น 03) ไม่มี console error
- ลบข้อมูลทดสอบใน transaction เดียว: ใบงาน 1 · ใบเสนอราคา 2 · approval events 7 · แจ้งเตือนอนุมัติ 38 · ประวัติใบงาน 14 · ไม่มีเงิน
