# Today SLA Filter Chips

Status: done

## Goal

เปลี่ยนตัวกรอง SLA ในหน้า Today จาก dropdown ตัวเลือกเดียว เป็นชิปติ๊กได้หลายอันที่มีตัวเลขกำกับ
เพื่อให้ผู้ใช้เห็นปริมาณงานแต่ละสถานะตั้งแต่เปิดหน้า และเลือกหลายสถานะพร้อมกันได้

## Problem

ตัวกรองปัจจุบันเป็น `<select>` 6 ตัวเลือกที่ [today/page.tsx](../../src/app/(app)/today/page.tsx)

```text
"" แสดง Lead ทั้งหมด · all มีงาน SLA · breached SLA เกินกำหนด
near_due SLA ใกล้กำหนด · active SLA กำลังดำเนินการ · without ไม่มีงาน SLA
```

1. ตอนปิดอยู่ไม่บอกอะไรเลย ผู้ใช้เปิด Today มาเพื่อถามว่า "วันนี้มีอะไรต้องรีบ"
   แต่ต้องกดเปิดแล้วเลือกทีละอันถึงจะรู้ว่ามีงานเกินกำหนดกี่ Lead
   ทั้งที่ตัวเลขมีอยู่ในหน้าแล้วใน `scopedSlaData.items` แค่ไม่ได้แสดง
2. เลือกได้ทีละสถานะ — "เกินกำหนด + ใกล้กำหนด" ซึ่งเป็นคำถามที่ถามบ่อยที่สุด ทำไม่ได้
3. ตัวเลือก `all` (มีงาน SLA) ซ้ำกับการรวม 3 สถานะ
4. ปุ่ม "งานของฉัน" ข้าง ๆ เป็นวงกลม ซึ่งภาษา UI แปลว่า radio ทั้งที่เป็น toggle อิสระ

## Design

- ชิป 4 ปุ่มพร้อมจำนวน Lead: `เกินกำหนด` (แดง) · `ใกล้กำหนด` (ส้ม) · `ตามแผน` (ฟ้า) · `ไม่มีงาน SLA` (เทา)
- ติ๊กได้หลายอัน · ไม่ติ๊กอะไรเลย = แสดงทั้งหมด (แทนตัวเลือก `""` เดิม) · กดซ้ำเพื่อปลด
- ติ๊กครบ 3 สถานะ = `all` เดิม จึงตัดตัวเลือกนั้นทิ้ง เหลือ 4 ปุ่มจาก 6 ตัวเลือก
- `ไม่มีงาน SLA` ขัดกับอีก 3 สถานะโดยธรรมชาติ — ติ๊กแล้วปลดอีก 3 อัตโนมัติ และกลับกัน
  คั่นด้วยเส้นแบ่งให้เห็นว่าเป็นคนละชุด
- ตัวเลขนับจาก `filteredSlaItems` แบบไม่ซ้ำ Lead จึงขยับตามตัวกรองขั้นตอน/ผู้รับผิดชอบที่เลือกอยู่
- `?sla` รองรับหลายค่าคั่นด้วย comma · ค่าเดี่ยวแบบเดิมยังใช้ได้
- ปุ่ม "งานของฉัน" เปลี่ยนวงกลมเป็นสี่เหลี่ยมมุมมน ให้ตรงความหมายและเข้าชุดกับชิป

### ตำแหน่ง — เทียบ 3 แบบแล้วเลือก C

แถวบนของ Today ตอนนี้มีพื้นที่ว่างกลางแถวอยู่แล้ว เพราะเป็น `justify-between`
ระหว่างหัวข้อ section กับกลุ่มปุ่มด้านขวา ความกว้างข้างล่างวัดจาก mockup จริง

| แบบ | วาง | กว้างขั้นต่ำ | ผล |
| --- | --- | --- | --- |
| A | ชิปแยกลงแถวล่าง | 409px | ไม่มีอะไรหาย แต่กินความสูงเพิ่ม 1 แถวตลอดเวลา |
| B | ชิปขึ้นแถวบน ตัดปุ่มเรียงทิ้ง เอาตัวกรองย่อยมาแทน | 902px | แคบสุด แต่เสียปุ่มเรียง และผู้จัดการมีตัวกรองย่อย 3 ช่อง ใส่ครบแล้วกว้างเท่า C |
| **C** | ชิปขึ้นแถวบน ยุบตัวกรองย่อยเป็นปุ่มเดียวมี popover | 1080px | แถวเดียวจบ เก็บปุ่มเรียงครบ ตัวกรองย่อยจะกี่ช่องก็ได้ |

เลือก **C** เพราะปุ่มเรียงเป็นของที่ใช้ทุกวัน (ระบบจำค่าไว้ใน `today.sortField` / `today.sortOrder` อยู่แล้ว)
และยิ่งกรองเหลือเฉพาะงานเร่งยิ่งต้องเรียง ส่วนตัวกรองย่อยเป็นของที่ผู้จัดการใช้เป็นครั้งคราว
เอาไปซ่อนหลังปุ่มที่มีตัวเลขกำกับได้โดยไม่เสียอะไร

1080px พอดีจอ 1366 (พื้นที่เนื้อหาหลังหักเมนูซ้าย ~1126px) ถ้าแคบกว่านั้น flex-wrap
จะตกลงเป็น 2 บรรทัดเอง ซึ่งได้หน้าตาแบบ A พอดี ไม่พังกลางคัน

ปุ่ม `ตัวกรองย่อย` โผล่เฉพาะตอนติ๊กสถานะ SLA อยู่ และมีตัวเลขบอกว่ากรองอยู่กี่ชั้น

## Acceptance Criteria

1. ผู้ใช้เห็นจำนวน Lead ของทุกสถานะ SLA ทันทีที่เปิดหน้า โดยไม่ต้องกดอะไร
2. เลือก `เกินกำหนด` + `ใกล้กำหนด` พร้อมกันได้ และรายการที่แสดงตรงกับที่เลือก
3. ติ๊ก `ไม่มีงาน SLA` แล้วสถานะอื่นถูกปลดอัตโนมัติ และกลับกัน
4. ตัวเลขบนชิปขยับตามตัวกรองขั้นตอนและผู้รับผิดชอบที่เลือกอยู่ และนับ Lead แบบไม่ซ้ำ
5. ลิงก์เดิม `?sla=breached` ยังเข้าได้ และลิงก์ใหม่ `?sla=breached,near_due` ใช้งานได้
6. Desktop และ Mobile ไม่มีข้อความล้นแนวนอน
7. ปุ่มเรียง (ฟิลด์ + ทิศทาง) ยังอยู่ครบและยังจำค่าได้เหมือนเดิม

### 1. ตัวเลขบนชิปคุมสีของตัวเองตั้งแต่ยังไม่ติ๊ก

ของที่ส่งไปรอบแรกเป็นสีเทาล้วนจนกว่าจะติ๊ก ต่างจากม็อกอัพที่ตัวเลขมีสีตลอด
(`.chip[data-k="breached"] .n { color: red-600 }`) ทำให้กวาดตาแถวเดียวไม่รู้ว่าอันไหนด่วน

เพิ่มฟิลด์ `num` ใน `SLA_CHIPS` แล้วใส่ตอน `!on` — ติ๊กแล้วตัวเลขรับสีเข้ม (`-700`)
จากพื้นหลังชิปแทน ตรงกับม็อกอัพทั้งสองสถานะ

| ชิป | ยังไม่ติ๊ก | ติ๊กแล้ว |
| --- | --- | --- |
| เกินกำหนด | `text-red-600` | พื้น `red-50` ตัวอักษร `red-700` |
| ใกล้กำหนด | `text-amber-600` | พื้น `amber-50` ตัวอักษร `amber-700` |
| ตามแผน | `text-sky-700` | พื้น `sky-50` ตัวอักษร `sky-700` |
| ไม่มีงาน SLA | `text-gray-500` | พื้น `gray-100` ตัวอักษร `gray-700` |
