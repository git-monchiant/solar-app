# ขั้น 02 เสนอราคา O&M — ขนาดตัวอักษร + "บันทึกถึงฝ่ายขาย" แบบฝั่งขาย

## ขนาดตัวอักษร — วัดจริงแล้วเท่ากัน

วัด computed style ของหน้า lead 924 กับหน้า O&M ที่ viewport เดียวกัน (1472px): หัวข้อ 18px · ราง Sale/Manager 18px ·
แพ็กเกจหลัก 16px · ยอดที่ต้องชำระ 16px · การ์ดว่าง 22px · ปุ่มยาว 20px — ตรงกันทุกตัว ไม่มี zoom
ที่ดูต่างคือ **ความกว้างการ์ด** (หน้า O&M มีราง STEPS + Activity Log กินที่) และกล่องเลขใบที่เคยขยายเป็น 120px
ทำให้ราง Sale → Manager ถูกบีบ ⇒ คืนเป็น 100px เท่าฝั่งขาย · เลขใบ O&M ที่ยาวกว่าขึ้นบรรทัดใหม่ตรงขีดแทนการตัดท้าย
· ข้อความการ์ดว่างใช้ประโยคเดียวกับฝั่งขาย

## บันทึกถึงฝ่ายขาย

- ช่องใต้การ์ดแบบฝั่งขายทุกอย่าง (ป้าย · textarea 3 แถว · บันทึกอัตโนมัติเมื่อหยุดพิมพ์ 600ms)
- เก็บที่ใบงาน: คอลัมน์ใหม่ `om_bookings.quote_note` (migration `20261002-1500_om_booking_quote_note.sql`)
  - ใช้ `leads.quotation_note` ไม่ได้ — บ้านที่ใช้ lead ร่วมกับฝั่งขายจะไปทับของทีมขาย
  - ใช้ `om_bookings.note` ไม่ได้ — เป็นหมายเหตุนัด / อาการของใบงานซ่อมอยู่แล้ว
- ยังไม่มีใบงาน (ก่อนสร้างใบแรก) = ช่องปิด "บันทึกได้หลังสร้างใบเสนอราคาชุดแรก" · ลูกค้าเลือกชุดแล้ว = อ่านอย่างเดียว
- ช่อง "โน้ต" รายใบใน popup เอาออก (popup ฝั่งขายไม่มี) — ใบเก่าที่มีโน้ตยังเก็บค่าเดิมไว้ตอนแก้ และการ์ดยังโชว์
- API: `GET /api/om/quotations?booking_id=` คืน `{ quotes, quote_note }` · `PUT /api/om/bookings/[id]/quote-note` (ไม่ลงประวัติ แบบฝั่งขาย)

## migration

รันเฉพาะไฟล์นี้บน solardb_v3 ด้วยสคริปต์ชั่วคราว **ไม่ได้ใช้ deploy_migrations.mjs --yes**
