## ยกจากฝั่งขายทีละส่วน

| ฝั่งขาย | O&M |

| แถวหัว "รายการในใบเสนอราคา N หัวข้อ" + "+ เพิ่มแพ็กเกจ" + "+ งานเพิ่ม" | เหมือนกัน · "+ เพิ่มแพ็กเกจ" เปิดป๊อปอัปค้นหาแบบฝั่งขาย จัดกลุ่มตามช่วง kW (ใบ O&M มีแพ็กเกจได้ 1 ตัว — เลือกใหม่แทนตัวเดิม) |
| ว่าง: "ยังไม่มีรายการ — เริ่มด้วย …" | เหมือนกัน |
| แถวหัวข้อ: ▸ · เลขข้อ · ชื่อ · จำนวน · หน่วย · ราคา · ↑↓× | แพ็กเกจ = แถว 1 เสมอ ▸ กางดูขอบเขตงาน · งานเพิ่ม = ชื่อ/จำนวน/หน่วย/ราคาต่อหน่วย แก้ได้ เลื่อนขึ้นลงได้ |

| ล่าง: ยกเลิก · 💡 คำแนะนำ · ดูตัวอย่าง · บันทึกฉบับร่าง | เหมือนกัน — **ใหม่**: ดูตัวอย่างของ O&M ผ่าน POST /api/quotation-pdf/preview (ทางเดียวกับฝั่งขาย สร้างชุดข้อมูลแบบ buildOmQuoteSnapshot จากค่าในฟอร์ม) |

## API

- `parseOmQuoteInput` รับ `issue_date` (YYYY-MM-DD · ไม่เกินวันนี้ตามเวลาไทย) · `writeOmQuoteBody` เขียน issue_date (ไม่ส่ง = คงเดิม / วันนี้)
- `buildOmPreviewSnapshot(houseId, input, …)` — แยกตัวช่วยร่วมกับ buildOmQuoteSnapshot (แถวแพ็กเกจ + จำนวน/หน่วยต่อท้ายชื่อ · ข้อความท้ายใบ) ตัวเลขไม่เพี้ยนจากใบจริง
- `POST /api/quotation-pdf/preview` body `{ om: true, house_id, … }` → ทาง O&M (หน้า GET เข้าทาง O&M เองเพราะ om_booking_id ไม่ว่าง)

## เพิ่มเติม 2 ต.ค. 69 — ป้ายแถวส่วนลดบนใบแบบฝั่งขาย

- ผู้ใช้ส่งภาพตัวอย่าง PDF: แถวส่วนลดขึ้น "ส่วนลด" เฉย ๆ ทั้งที่กรอก "ชื่อส่วนลด" แล้ว — ฝั่งขายพิมพ์ชื่อที่กรอก (quotations.discount_label)
- `writeOmQuoteBody` / `buildOmPreviewSnapshot` เขียน discount_label = ชื่อส่วนลด (ช่องเดียวกับ discount_reason · ตัด 200 ตัวตามคอลัมน์) · ไม่มีส่วนลด = ว่าง
  · ช่อง "ชื่อส่วนลด" ใน popup จำกัด 200 ตัวแบบฝั่งขาย
- ตรวจ: ตัวอย่าง + ใบจริง (บ้าน 311/77 ลบทิ้งแล้ว) แถวส่วนลดขึ้น "ส่วนลดลูกค้าเก่า" · แก้เป็นไม่มีส่วนลด = แถวหาย
- ใบที่ส่งอนุมัติแล้วไม่เปลี่ยน (ข้อมูลเอกสารแช่ไว้ตอนส่ง) · ใบร่างเดิมได้ป้ายเมื่อกดบันทึกใหม่
