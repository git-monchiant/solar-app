# รายการโครงการ B2B แบบเห็น flow ขั้นตอน

สถานะ: **done** (16 ต.ค. 69) — ผู้ใช้ "ทำตามแนะนำ" = A + C แล้วสั่งเอากระดาน (C) ออก → **เหลือแบบ A**

mockup: [docs/mockup/20261016-06-b2b-project-list-flow/index.html](../mockup/20261016-06-b2b-project-list-flow/index.html)

## ที่มา

16 ต.ค. 69 ผู้ใช้ส่งภาพหน้า "ทั้งหมด" ของขาย B2B (`/b2b/projects?stage=sales`) — "ลอง design ใหม่ ให้ดูง่าย เป็น flow ขั้นตอนชัดเจน ทำเป็น mockup ให้เลือก"

ปัญหาของหน้าเดิม
- คอลัมน์ "ขั้น" เป็นป้ายเดียว (เช่น "ราคาประมาณการ") — ไม่บอกว่า **ต่อไปต้องทำอะไร · รอใคร · ค้างมากี่วัน**
- ไม่เห็นภาพรวมว่าแต่ละขั้นมีกี่งาน มูลค่าเท่าไร
- BOQ หลายใบที่ยังว่างขึ้น "— · 2 ตัวเลือก" อ่านไม่ออก · "อัปเดตล่าสุด" ไม่บอกว่างานค้าง

## แบบที่เสนอ (ใช้ข้อมูลชุดเดียวกันทุกแบบ)

| แบบ | หน้าตา | ใช้แทน |
|---|---|---|
| **A แถบ flow + รายการ** ⭐ | แถบ 5 ขั้นด้านบน (จำนวน · มูลค่า · ถึงตาเรา · กดกรอง) + ตารางมีรางขั้น ●●●○○ · ต่อไป · รอใคร · อยู่ขั้นนี้กี่วัน | มุมมอง "รายการ" |
| B จัดกลุ่มตามขั้น | ไล่ลง 01 → 05 · หัวกลุ่มบอกขั้นนี้ทำอะไร · แถวมีแถบขั้นย่อย (BOQ → ออกใบ → อนุมัติ x/3 → ส่งลูกค้า) | มุมมอง "รายการ" |
| C กระดาน flow | คอลัมน์ละขั้นมีลูกศร · การ์ดมีแถบขั้นย่อย + ต่อไป + รอใคร | มุมมอง "กระดาน" (คู่กับ A หรือ B ได้) |

ร่วมทุกแบบ
- ชิปกรอง **ถึงตาเรา / รออนุมัติ / รอลูกค้า / รอบัญชี** — สีตาม "คนที่ต้องทำ" ไม่ใช่ตามขั้น
- **อยู่ขั้นนี้กี่วัน** แทน "อัปเดตล่าสุด" — เกิน 7 วันแดง
- BOQ หลายขนาดแสดงช่วง "150 – 200 kWp · 2 ขนาด"

## ข้อมูลที่ต้องเพิ่มใน API รายการ (`/api/b2b/projects`)

ตอนนี้ได้ `stage · sub · survey_date · boq_count · boq_capacity_wp · boq_total_sale`
- **ต่อไป + รอใคร** — คิดจาก stage + sub (สถานะใบเสนอราคา 32x0/34x0 · นัดสำรวจ 3310/3320) + มี BOQ / มีใบหรือยัง (เพิ่มจำนวนใบในขั้น) · ขั้น 3500 ใช้สถานะงวด 1
  ใช้กติกาเดียวกับการ์ด "ต่อไป" ในหน้าโครงการ — ควรย้ายไปฟังก์ชันกลางใน `src/lib/b2b/` ให้สองหน้าตรงกัน
- **วันในขั้น** — วันที่เปลี่ยนขั้นล่าสุดจาก `b2b_project_activities` (แบบ project-view.ts)
- **ช่วง kWp** — min/max ของ BOQ Rev ล่าสุดแต่ละเลขที่ (ไม่นับใบที่ยังว่าง)
- **อนุมัติแล้วกี่ชั้น** (เฉพาะแบบ B/C ที่โชว์ "อนุมัติ 1/3") — จากใบล่าสุด

## ขอบเขต

- เฉพาะหน้า `/b2b/projects` (ทุก stage group ใช้หน้าเดียวกัน — การ์ดสำรวจ & ติดตั้ง ใช้แถบขั้น 03 + 06–09)
- ไม่แตะหน้ารายการลีด B2C

## ทำแล้ว (16 ต.ค. 69)

- API รายการ (`projectRowSelect` — หน้าโครงการใช้ด้วย): เพิ่ม `stage_since` (กติกาเดียวกับ stageEnteredAt) · `boq_capacity_min_wp / max_wp` (ไม่นับใบว่าง) — ไม่มี migration
- `src/lib/b2b/project-next.ts` ฟังก์ชันกลาง `projectNext()` → ต่อไป · รอใคร (ถึงตาเรา / รออนุมัติ / รอลูกค้า / รอบัญชี / รอจัดซื้อ) · ขั้นย่อย — คิดจาก stage + sub + จำนวน BOQ ครบ 01–09
  เป็นฉบับย่อของการ์ด "ต่อไป" ในหน้าโครงการ (หน้านั้นยังใช้โค้ดเดิม — แก้ข้อความฝั่งหนึ่งให้ดูอีกฝั่ง)
- **รายการ (A)**: แถบขั้นด้านบน (จำนวน · ราคา BOQ รวม · ถึงตาเรา · กดกรอง/กดซ้ำเลิก) · ชิปกรองรอใคร (ซ่อนชิปที่เป็น 0) · แถว: ชื่อ + เลขที่·ลูกค้า · รางขั้น · ต่อไป + แถบขั้นย่อย · รอ · BOQ ช่วง kWp + จำนวนขนาด · ราคา BOQ ล่าสุด · ผู้ดูแล · อยู่ขั้นนี้
  มือถือเป็นการ์ด · รางขั้น: การ์ดขาย 01–05 · สำรวจ & ติดตั้ง 03 + 06–09 · ทั้งหมด 9 ขั้น · ปิด/แพ้ ใช้ป้ายขั้นเดิม (ไม่มีแถบขั้น)
- **กระดาน (C)**: ลูกศรคั่นคอลัมน์ · หัวคอลัมน์มีเลขขั้น + ถึงตาเรา · การ์ดมีแถบขั้นย่อย · ต่อไป · ป้ายรอใคร · วันในขั้น · คอลัมน์แคบลง (5 คอลัมน์พอดีจอ 1440)
- ต่างจาก mockup: วันในขั้นใช้เกณฑ์เดียวกับหน้าโครงการ **เกิน 14 วัน = สีส้ม** (mockup เขียน 7 วันแดง) · ชื่อขั้นย่อยที่ซ้ำกับ "ต่อไป" ไม่แสดงซ้ำ
- ทดสอบ: tsc / eslint ผ่าน · ข้อมูลจริง 5 โครงการ (1440 / 1366 / มือถือ · ไม่ล้นจอ) · กดขั้น 04 → 2 แถว · เมนู open / site / 3200 / lost / closed เปิดได้ ·
  ข้อมูลจำลอง 8 สถานะ (puppeteer ดัก API): รออนุมัติ 1/3 · ส่งกลับแก้ (แดง) · รอลูกค้า · รอบัญชี · นัดสำรวจ อ. 20 ต.ค. · ติดตั้ง · 20 วันขึ้นสีส้ม · ไม่มี error

## ปรับต่อ (16 ต.ค. 69 · ผู้ใช้สั่ง)

- **เอามุมมองกระดานออก** — เหลือรายการแบบ A อย่างเดียว (ปุ่มสลับ + ค่าที่จำใน localStorage `b2b-projects-view` ไม่ใช้แล้ว)
- **ถ้อยคำภาษาทางการ** — ผู้ใช้เลือกชุด "รอ + ผู้รับผิดชอบ" (จาก 3 ชุด):
  ป้าย/ชิป: รอผู้ดูแลโครงการ · รอผู้ตรวจสอบอนุมัติ · รอลูกค้าตอบรับ · รอฝ่ายบัญชียืนยัน · รอฝ่ายจัดซื้อ ·
  หัวตาราง: งานถัดไป · สถานะ · ระยะเวลาในขั้น · งานถัดไปเช่น "จัดทำใบเสนอราคาประมาณการ" "รอผู้ตรวจสอบลำดับที่ 2 พิจารณาอนุมัติ"
  "แก้ไขใบเสนอราคายืนยันตามที่ผู้ตรวจสอบส่งกลับ และส่งขออนุมัติใหม่" "รอฝ่ายบัญชียืนยันการรับชำระงวดที่ 1"
- คอลัมน์ผู้ดูแลยุบไปไว้ใต้ป้าย "รอผู้ดูแลโครงการ" (ชื่อจริง) — จอ 1366 ชื่อโครงการไม่ถูกบีบ · kWp ตัดศูนย์ท้าย ("150 – 200 kWp")
- **"ใบประมาณการ" → "ใบเสนอราคาประมาณการ"** (คู่ "ใบเสนอราคายืนยัน") — ผู้ใช้ถามว่าใบประมาณการคือใบ BOQ หรือไม่ → ชื่อเต็มกันสับสน (เลือกแบบ ก. จาก 3 แบบ)
  เปลี่ยนในหน้ารายการ + หน้าโครงการ (หัวตารางใบ · สรุปขั้น · ปุ่ม "ได้งานจากใบเสนอราคาประมาณการ" · การ์ดงานถัดไป) · ชื่อขั้น "ราคาประมาณการ" และป้ายชนิดสั้น "ประมาณการ / ยืนยัน" คงเดิม
- **ใช้คำเดียวกันสองหน้า** (ผู้ใช้สั่ง) — การ์ด "ต่อไป" ในหน้าโครงการขั้น 01–05 เปลี่ยนเป็นถ้อยคำชุดเดียวกับหน้ารายการ:
  "ออกใบ…" → "จัดทำใบ…" · "ส่งใบ…ให้ผู้ตรวจสอบอนุมัติ" → "ส่งใบ…เพื่อขออนุมัติ" · "รอผู้ตรวจสอบชั้น 2 อนุมัติ…" → "รอผู้ตรวจสอบลำดับที่ 2 พิจารณาอนุมัติ…" ·
  "ผู้ตรวจสอบ 3 ชั้นอนุมัติ" → "ผู้ตรวจสอบ 3 ลำดับพิจารณาอนุมัติ" · นัด/บันทึกผลสำรวจ · สัญญา / ใบสั่งซื้อ (PO) · การรับชำระงวดที่ 1 ·
  ขั้นดำเนินโครงการ (06–09) ยังใช้ชื่อเหตุการณ์หน้างานเดิม · ใบร่าง = ขั้นย่อย "อนุมัติ 0/3" (ไม่ขึ้น "จัดทำใบ" ใต้ "ส่ง…เพื่อขออนุมัติ")
- **ยุบคอลัมน์ "สถานะ"** (ผู้ใช้เลือกแบบ ก.) — ทุกแถวขึ้น "รอผู้ดูแลโครงการ" ซ้ำกับงานถัดไป · ป้ายสีติดท้ายงานถัดไปเฉพาะตอนรอคนอื่น
  (รอผู้ตรวจสอบอนุมัติ / รอลูกค้าตอบรับ / รอฝ่ายบัญชียืนยัน / รอฝ่ายจัดซื้อ) · คืนคอลัมน์ "ผู้ดูแล" · ชิปกรองด้านบนคงเดิม · มือถือ: ป้ายเฉพาะรอคนอื่น ไม่งั้นแสดงชื่อผู้ดูแล
- **แถบขั้นด้านบนเอาป้าย "รอผู้ดูแลโครงการ N" ออก** (ผู้ใช้เลือกแบบ ก.) — เลขซ้ำกับจำนวนโครงการ + ชิปกรอง · เหลือจำนวน + มูลค่า
