# Complete Lead Timeline

Status: done

## Goal

ปรับ Timeline ของ Lead ให้แสดงเหตุการณ์ตามเวลาที่เกิดขึ้นจริงอย่างครบถ้วน ตั้งแต่ Survey, Quotation, Order, Install, Warranty, Grid-Tie และ After Sales โดยยังแสดงวันนัดและวันครบกำหนดเป็นข้อมูลประกอบ ไม่ใช้เป็นเวลาของเหตุการณ์ย้อนหลัง

## Scope

- รวบรวมเหตุการณ์จาก `lead_activities`, SLA, ใบเสนอราคา, การชำระเงิน และข้อมูล milestone บน Lead
- จัดหมวดเหตุการณ์ให้ตรงขั้นตอน พร้อมเรียงจากอดีตไปปัจจุบันภายในแต่ละขั้น
- แสดงเวลาในทุกรายการที่มี audit timestamp และแยกเวลาที่เกิดเหตุการณ์ออกจากวันนัด/วันครบกำหนด
- ครอบคลุมการนัด/เลื่อน/ยืนยันสำรวจ, ลำดับอนุมัติใบเสนอราคา, แผนและผลชำระเงิน/เช็ค/สินเชื่อ, นัดและผลติดตั้ง, ใบรับประกัน, Grid-Tie และบริการหลังการขาย
- ป้องกันรายการซ้ำระหว่าง Activity, SLA และข้อมูลสรุป พร้อม fallback สำหรับข้อมูลเก่า
- ทดสอบกับ Lead หลายสถานะและรัน typecheck/lint/tests ที่เกี่ยวข้อง

## Implementation approach

1. เพิ่มข้อมูลประกอบ Timeline ใน API รายละเอียด Lead โดยส่ง quotation/payment records ที่จำเป็นต่อการแสดงประวัติ
2. สร้างตัวแปลง Activity เป็น Timeline milestone แบบรวมศูนย์ กำหนด stage, label, detail, actual timestamp และ stable key
3. ผสาน milestone จากตารางเฉพาะและ fallback จากคอลัมน์ Lead เฉพาะเมื่อไม่มี Activity ที่ตรงกัน
4. เรียงเวลาและตัดรายการซ้ำภายในแต่ละขั้น โดยคง SLA เป็นแถวกำกับกระบวนการ
5. ตรวจผลกับข้อมูลจริงตั้งแต่ pre-survey ถึง warranty/after-sales

## Acceptance criteria

- เหตุการณ์ในแต่ละขั้นเรียงตาม timestamp ที่เกิดจริงจากเก่าไปใหม่
- วันนัด/วันครบกำหนดไม่ถูกใช้แทนเวลา Activity
- Quotation แสดง create, submit, approve, return/reject, revision และส่งลูกค้าเมื่อมีข้อมูล
- Order แสดงยืนยันคำสั่งซื้อ แผนงวด หลักฐานชำระ ผลตรวจ เช็ค และสินเชื่อเมื่อมีข้อมูล
- Install แสดงนัด เลื่อน ยืนยัน เริ่ม/เสร็จงาน และค่าใช้จ่ายเพิ่มเติมเมื่อมีข้อมูล
- Warranty/Grid-Tie/After Sales แสดงการออกเอกสาร ช่วงรับประกัน เหตุการณ์เชื่อมระบบ และกิจกรรมบริการหลังการขาย
- ข้อมูลเก่ายังมี milestone จากคอลัมน์สรุปเมื่อไม่มี audit activity

## Verification

- `npx tsc --noEmit` ผ่าน
- ESLint ไฟล์ที่แก้ไม่มี error (มี warning เดิม 3 รายการในหน้า Lead)
- `npm run test:sla` ผ่าน
- `npm run build` ผ่านครบ 96 routes
- ตรวจชนิด Activity จริงใน `solardb_dev` และตรวจหน้า `/leads/[id]` กับ API route บน Development แล้ว

## Timeline density refinement

- Timeline หลักแสดงเฉพาะ SLA, business milestone และผลลัพธ์ที่เปลี่ยนสถานะ
- ซ่อนการแนบ/ส่งสลิป, ยกเลิกส่งสลิป, การกดเตือนอนุมัติ, LINE/SMS ส่งออก, หลักฐานรับประกัน และ activity เอกสารดิบจาก Timeline แต่ยังเก็บครบใน Activity Log
- สถานะรอชำระใช้ข้อมูล payment ปัจจุบันแบบรวมหนึ่งรายการ ส่วนผลยืนยัน/ปฏิเสธ/ยกเลิกและสถานะเช็คยังคงเป็นประวัติสำคัญ
- After Sales แสดงการติดตามสำเร็จครั้งแรกเพียงรายการเดียว ไม่แสดงการติดต่อย่อยซ้ำทั้งหมด
- รวม autosave การแก้ Time Slot นัดเดียวกันภายใน 60 วินาทีให้เหลือค่าล่าสุดหนึ่งรายการ โดยรายการดิบยังอยู่ใน Activity Log
- ทำเครื่องหมาย “บันทึกย้อนหลัง” เมื่อวันนัดผ่านไปก่อนเวลาที่ Activity ถูกบันทึก
- จัด rollback ตามขั้นปลายทางจริงและระบุชื่อขั้น เช่น Install → Order แสดงในหมวด Order
