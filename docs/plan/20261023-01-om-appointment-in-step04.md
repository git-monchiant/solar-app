# ใบที่ยืนยันนัดหมายแล้วอยู่ขั้น 04 นัดหมาย (O&M)

วันที่: 23 ต.ค. 69 · branch `v3-ui-consistency`

## ปัญหา

หน้างานบริการ O&M แท็บ "ยืนยันนัดหมาย" แต่การ์ดชี้วงที่ขั้น 05 ปฏิบัติงาน — ผู้ใช้ถามว่า "ทำไมยืนยันนัดหมายไม่อยู่ในนัดหมาย"

ต้นเหตุ: ตั้งแต่ 1 ต.ค. 69 กด "ยืนยันนัดหมาย" ที่ขั้น 04 แล้วพาไปขั้น 05 (แถบนัด + Reschedule + ช่างถึงหน้างาน อยู่แท็บย่อย "นัด" ของขั้น 05)
⇒ เรื่องนัดอยู่ 2 ที่ (ขั้น 04 + แท็บย่อยนัดของขั้น 05) · ส่วนรหัส journey นับใบที่นัดแล้วเป็น 2420 ใต้ 2400 นัดหมาย อยู่แล้ว

## ผู้ใช้เลือก (23 ต.ค. 69)

- **แบบ B**: ใบที่ยืนยันนัดหมายแล้ว (และใบเก่าที่ค้าง "รอยืนยันนัด") อยู่ขั้น 04 นัดหมาย จนช่างถึงหน้างาน
- แท็บ/สถานะ `progress` = **กำลังปฏิบัติงาน** (เดิม กำลังดำเนินการ) ให้คำโยงกับขั้นปฏิบัติงาน

## ทำ

1. `jobAt` (service-view.ts) — เลิกดันใบ pending/confirmed ที่มีวันนัดไปขั้น 05 → อยู่ขั้น 04 ตาม `flowIndex`
2. การ์ดขั้น 04 (JobDetail) — หลังยืนยันแล้วแสดงแถบนัด + Reschedule + ปุ่ม "ช่างถึงหน้างาน" (ย้ายจากแท็บย่อยนัดของขั้น 05)
   Account อ่านอย่างเดียว = บรรทัด "นัด … — รอทีมช่างเข้าปฏิบัติงาน"
3. การ์ดขั้น 05 — เหลือแท็บย่อย ตรวจ · รูป·บันทึก · ส่งมอบ (เหมือนหน้าช่าง /om/field) · ถอด prop `appt` ออกจาก JobFormPanel
4. ชื่อ: แท็บ + สถานะ progress = กำลังปฏิบัติงาน · ป้ายหัวหน้าช่าง /om/field แสดงสถานะจริงของใบ (เดิม "กำลังดำเนินการ" ทุกใบที่ยังไม่ปิด)

ไม่แตะฐานข้อมูล / API / การคำนวณแท็บ

## รอบ 2 (23 ต.ค. 69) — "ให้มาที่หน้าปฏิทิน"

ผู้ใช้กดการ์ดในแท็บยืนยันนัดหมายแล้วคาดว่าจะเห็นปฏิทินแบบตอนเลือกวันครั้งแรก (เดิมต้องกดปุ่ม Reschedule ก่อน)

- การ์ดขั้น 04 ของใบที่ยืนยันแล้ว = แถบนัด (สรุป) + ปฏิทินเลื่อนนัดเปิดค้าง เลือกวัน/ช่องเดิมไว้ · ป้ายสรุปล่าง "นัดปัจจุบัน"
- ยังไม่เปลี่ยน = ท้ายการ์ดเป็นปุ่ม "ช่างถึงหน้างาน" · เปลี่ยนวัน/ช่องแล้ว = ป้าย "เลื่อนเป็น" + เหตุผล + ผลที่จะเกิด + ปุ่ม คืนวันเวลาเดิม / ยืนยันเลื่อนนัด
- OmRescheduler: prop `idle` (โหมดฝังเปิดค้าง) · `onCancel` ไม่บังคับ · เอาปุ่ม Reschedule บนแถบนัดออก

## รอบ 3 (23 ต.ค. 69) — ปุ่ม "ยืนยันรับบริการ" ขั้น 01

บ้าน 146/11 ผู้ใช้กดตกลงรับบริการแล้วไม่ขึ้นแท็บยืนยันนัดหมาย — ข้อมูลจริงไม่มีอะไรถูกบันทึก (โทร 0 · ไม่มีใบงาน)
เพราะเลือก "ตกลงรับบริการ" แล้วพาไปขั้น 04 ทันที และบันทึกจริงตอนกด "ยืนยันนัดหมาย" ที่ขั้น 04 เท่านั้น

- เลือก "ตกลงรับบริการ" = เลือกอย่างเดียว (เดิมพาไปขั้นถัดไปทันที) · ปุ่มล่างเปิดใช้และชื่อ "✓ ยืนยันรับบริการ" (เดิม "ไปเลือกวันนัด ›" / "ไปขั้น 02 เสนอราคา ›")
- กดแล้วไปขั้นถัดไปเหมือนเดิม: งานฟรีขั้น 04 · งานเสียเงินขั้น 02

## รอบ 4 (23 ต.ค. 69) — "กดยืนยัน step 1 แล้วสถานะไปแสดงที่ยืนยันนัดหมายเลย"

กลับข้อตกลง 1 ต.ค. 69 ("งานฟรีไม่บันทึกจนเลือกวันเสร็จ · ไม่มีใบตกลงแต่ไม่มีวันนัด")

- งานฟรีกด "ยืนยันรับบริการ" ขั้น 01 = บันทึกการโทรทันที → API สร้างใบ **pending ไม่มีวัน** → แท็บยืนยันนัดหมาย · ราง/การ์ดอยู่ขั้น 04
  ใช้ pending ไม่ใช่ confirmed เพราะหน้าช่าง /om/field เห็นเฉพาะ confirmed ขึ้นไป (ยังไม่มีวันไม่ต้องให้ช่างเห็น)
- ขั้น 04 ของใบไม่มีวัน = ปฏิทินเลือกวัน + "ยืนยันนัดหมาย" (หน้าตาเดิมของงานฟรี) → confirmed + วัน · อยู่ขั้น 04 ต่อ (เดิม go(4) พาไปขั้น 05 ที่ล็อก — บั๊กจากแบบ B แก้ด้วย)
- API: ตกลงซ้ำแบบไม่ส่งวันกับใบที่ตกลงแล้ว = คงสถานะเดิม (ห้ามถอย confirmed → pending)
- การ์ดหน้ารายการ: ชิปส้ม "ยังไม่มีวันนัด"
- ถอด schedNow / schedFree / การ์ด 01 แบบล็อกระหว่างเลือกวัน (21 ต.ค.) · งานเสียเงินยังไปขั้น 02 เหมือนเดิม (ไม่บันทึกที่ 01)
- ทดสอบจริงบนบ้านทดสอบ 311/77: ยืนยันรับบริการ → pending ไม่มีวัน แท็บยืนยันนัดหมาย (ติดตาม 937→936 · ยืนยันนัดหมาย 4→5) → เลือกวัน → confirmed 30 ต.ค. 13:00 → ตกลงซ้ำไม่ถอย · ลบใบ #185 + ประวัติ 3 แถวแล้ว
