## การตัดสินใจ

- **D1 เก็บรูปแบบการชำระต่อใบเสนอราคา** ใน `document_inputs_json.payment_method`
  (`cash` / `loan` / `credit_card` / `null`) — เป็น JSON อยู่แล้ว **ไม่ต้องมี migration**
  - ใช้รหัสชุดเดียวกับ `PAYMENT_INTERESTS` ([customer-questionnaire.ts:253](../../src/lib/customer-questionnaire.ts#L253))
  - ใบใหม่: ค่าเริ่มต้น = `lead.payment_interest` (คำตอบ Pre-Survey) เซลส์เปลี่ยนเองได้
    → ชุด 1 เงินสด / ชุด 2 ผ่อน ได้
  - ใบที่บันทึกแล้ว: ถ้าใน JSON **มี key** ใช้ค่านั้น (รวม `null` ที่เซลส์เลือก "ไม่ระบุ") ·
    ถ้า**ไม่มี key** (ใบเก่า) ฝั่ง server ถือเป็น `null` = แสดงครบเหมือนเดิม
    — ห้ามดึงค่าจาก lead มาเติมตอน render ไม่งั้นใบเก่าเปลี่ยนเอง
  - รายงานสำรวจแบบเดี่ยว (`/api/survey-report/[id]` ไม่มีใบเสนอราคา) ใช้ `D.payment_interest` ตรง
- **D2 `loan_enabled` ตามรูปแบบการชำระ**: `loan` → true · `cash`/`credit_card` → false ·
  `null` → true (เหมือนเดิม) — ตอนนี้ไม่มี UI ให้ปิด/เปิดอยู่แล้ว จึงให้ช่องใหม่คุมแทน
- **D3 สิ่งที่แสดงในรายงานสำรวจ**

  | ส่วน | `loan` | `cash` / `credit_card` | `null` |
  |---|---|---|---|
  | §6 ขั้นตอนลูกค้า | เดิม | ขั้น 2 → "ชำระส่วนที่เหลือ 80%" | เดิม |
  | §7 มัดจำ 20% (เงินสด / บัตร 0%) | แสดง | แสดง ตัดข้อย่อย "กรณีกู้ไม่ผ่าน" | แสดง |
  | §8 ทางเลือก 1 เงินสด | ซ่อน | แสดง | แสดง |
  | §8 ทางเลือก 2 บัตรเครดิต 10 เดือน | ซ่อน | แสดง | แสดง |
  | §8 ทางเลือก 3 ออมสิน + กรอบ "ประเมินก่อนกู้" (p13) | แสดง | ซ่อน | แสดง |
  | ตารางผ่อนสินเชื่อ (p14) | แสดง | ซ่อน | แสดง |
  | **ตารางเงินสด/บัตรเครดิต (ใหม่)** | ซ่อน | แสดง | ซ่อน |

  - เงินสดกับบัตรเครดิตแสดงเหมือนกัน (ผู้ใช้กำหนด) — "บัตรเครดิต" = ทางเลือก 2 ใน §8
  - ข้อความนำ §8 "เลือกได้ 3 รูปแบบ" → นับตามที่แสดง · เหลือทางเดียวไม่ต้องมีเลข "ทางเลือกที่ 3"
- **D4 ตารางเงินสด/บัตรเครดิต** ยกจากฝั่งขวาของ Excel BTC ใช้ตัวเลขจาก `financial.outputs` ชุดเดิม:
  มูลค่าแพ็กเกจ · kW · หน่วยผลิต/เดือน · ค่าไฟต่อหน่วย · ค่าไฟปัจจุบัน · ประหยัด/เดือน ·
  จุดคุ้มทุน · ค่าไฟรวม 25 ปีถ้าไม่ติด · ประหยัด 25 ปี · CO₂ · ต้นไม้
  + แถวบัตรเครดิต: ค่าธรรมเนียม % · ยอดผ่อน/เดือน × 10 = (ยอด 80% × (1 + %)) ÷ 10
- **D5 ค่าธรรมเนียมบัตรเครดิต**: เซลส์กรอก % ในหน้าสร้างใบเสนอราคา
  (`document_inputs_json.credit_card_fee_percent`) · ไม่กรอก = พิมพ์เส้นว่างให้เขียนมือเหมือนเดิม
  — ใช้ทั้ง §8 ทางเลือก 2 (ตอนนี้เป็นเส้นว่าง [survey-report.js:549](../../src/lib/docs/survey-report.js#L549)) และตารางใหม่
  — **ไม่บวกเข้ายอดใบเสนอราคา** ค่าธรรมเนียมจริงยังคิดที่ขั้น Order เหมือนเดิม
- **D6 จุดคุ้มทุนแยกตามรูปแบบ** (เทียบ Excel BTC แล้ว Excel ถูกกว่าเรื่องนับดอกเบี้ย)
  - เงินสด/บัตร: `ceil(ราคา ÷ ประหยัดต่อเดือน)` = `payback_months` เดิม ไม่เปลี่ยน
  - สินเชื่อ: เพิ่ม `payback_months_with_loan` = `ceil((ดาวน์ + ค่างวดรวมทั้งสัญญา) ÷ ประหยัดต่อเดือน)`
  - เพิ่ม `down_recovered_months` = `ceil(ดาวน์ ÷ (ประหยัด − ค่างวด))` เมื่อประหยัด > ค่างวด
    แสดงในตารางผ่อนเป็น "ได้เงินดาวน์คืนใน ≈ X เดือน"
  - §4 "ระยะเวลาคืนทุน" ([survey-report.js:434](../../src/lib/docs/survey-report.js#L434)) ใช้ตัวที่ตรงรูปแบบ ·
    `null` ใช้ตัวเดิม
  - bump `QUOTATION_FINANCE_FORMULA_VERSION` · snapshot เก่าไม่มีช่องใหม่ → ใช้ `payback_months` เดิม
- **D7 ไม่ทำในรอบนี้**: ดอกเบี้ยหลายขั้นแบบสินเชื่อบ้าน (ตอนนี้ 2 ขั้นพอสำหรับออมสิน) ·
  ทางเลือกสินเชื่อบ้าน/Refinance · บวกค่าธรรมเนียมบัตรเข้ายอดรวม · ช่องกรอก "ผ่อนล้านละ"
  (กรอกได้โดยไม่ผูกกับระยะกู้ = ต้นเหตุตัวเลขเพี้ยนใน Excel BTC)
