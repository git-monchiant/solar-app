# Grid-Tie Permit Checklist Redesign

## Status

done

## Goal

ปรับ Checklist ของ `ขอขนานไฟ` (Step 07) ให้ตรงกับฟอร์มกระดาษที่ทีม Permit ใช้จริง
(`File Permit : Up 20082026`) — เอกสารยื่น 14 รายการ + รายละเอียดอุปกรณ์ 5 กลุ่ม
พร้อมเพิ่มคอลัมน์ยืนยันของฝ่าย Permit และเปิดฟอร์มกรอกวันที่ขั้นตอนกับการไฟฟ้า

> **ฟอร์มกระดาษนี้เป็นของบุคคลธรรมดา** ชุดนิติบุคคลคงรายการเดิมของแอปไว้ทั้งหมด
> ทั้งรายการและหน้าตา — ดู §B

## C. โครงสร้างข้อมูล

### C.1 Key ไม่มี prefix แล้ว

```diff
- "MEA:individual:id_card"     ← สลับ MEA↔PEA แล้วตัวนับกลับไป 0

```

### C.2 รูปร่างของแต่ละแถว

`grid_document_checklist` ยังเป็น `NVARCHAR(MAX)` เดิม เปลี่ยนแค่ shape ข้างใน

```jsonc
{
  "latest_electricity_bill": {
    "received": true,               // ตรวจรับหน้างาน (ช่องเดียวร่วมกัน)
    "permit": "has",                // "has" | "none" | null — ฝ่าย Permit ยืนยัน
    "note": "",
    "fields": { "ca_no": "0201234567890", "meter_size": "15_45", "voltage": "230", "phase": "1", "wire": "2" }
  },
  "power_of_attorney": { "fields": { "intent": "sell" } },
  "panel": { "received": true, "permit": "has", "datasheet": "has",
             "fields": { "brand": "JINKO", "watt": "640", "count": "16" } },
  // `files` ยังอ่านได้เผื่อข้อมูลเก่า แต่ไม่มี UI เขียนแล้ว
  "post_solar_house_registration": { "required": true }   // ชุดนิติบุคคลเท่านั้น
}
```

`owner` ไม่เก็บใน JSON — อยู่ในนิยามรายการที่ `gridTie.ts` (ตอนนี้ไม่ได้แสดงบนหน้าจอแล้ว)

### C.3 อ่านของเก่าได้ ไม่ต้อง migrate

`parseGridTieChecklist()` แปลงตอนอ่าน

```text
ตัดหัว "MEA:individual:" ทิ้ง  →  status === "received"  →  received: true, permit: "has"
```

ของเดิมมีสถานะชั้นเดียว ถ้าเคยติ๊กว่าได้รับแล้ว แปลว่าฝ่าย Permit ก็ได้เอกสารนั้นแล้ว
ถ้าข้อมูลเก่ามีทั้ง `MEA:` และ `PEA:` ของแถวเดียวกัน จะเก็บอันที่ติ๊กแล้วไว้

**ทั้งแผนนี้ไม่มี migration แม้แต่ไฟล์เดียว · ไม่แตะ schema เลย**

## D. สถานะ 2 ชั้น

```text
ตรวจรับหน้างาน (received)  ──▶  ฝ่าย Permit ยืนยัน (permit: has)
  ได้รับแล้ว | ยังไม่ได้รับ            มี | ไม่มี
```

- **ช่องตรวจรับมีช่องเดียว** ใครหยิบงานก่อนก็ติ๊กได้ ส่วน "งานของใคร" เป็นป้ายกำกับเท่านั้น

- **ทั้งสองชั้นเป็นข้อมูลติดตามงาน ไม่บล็อกการปิดงาน** — ดู §E

## E. เกณฑ์ปิดงาน — ไม่บังคับ checklist
