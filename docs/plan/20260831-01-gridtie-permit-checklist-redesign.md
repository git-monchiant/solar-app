# Grid-Tie Permit Checklist Redesign

## Status

done

## Goal

ปรับ Checklist ของ `ขอขนานไฟ` (Step 07) ให้ตรงกับฟอร์มกระดาษที่ทีม Permit ใช้จริง
(`File Permit : Up 20082026`) — เอกสารยื่น 14 รายการ + รายละเอียดอุปกรณ์ 5 กลุ่ม
พร้อมเพิ่มคอลัมน์ยืนยันของฝ่าย Permit

> **ฟอร์มกระดาษนี้เป็นของบุคคลธรรมดา** ชุดนิติบุคคลคงรายการเดิมของแอปไว้ทั้งหมด
> ทั้งรายการและหน้าตา — ดู §B

## ปัญหาของโครงสร้างเดิม

`src/lib/gridTie.ts` เก็บ checklist แค่ 5–7 รายการ แนบไฟล์รวมได้ 2 ช่อง

| # | ขาดอะไร | ผลที่เกิด |
|---|---|---|
| 1 | ไม่มีช่อง **Permit ยืนยัน** | สถานะมีชั้นเดียว — ฝ่ายที่ยื่น MEA/PEA จริงไม่มีที่ติ๊กรับของ |
| 2 | ~~แนบไฟล์ได้แค่ 2 ช่องรวม~~ | เคยทำปุ่มแนบไฟล์รายแถวไว้ แล้ว**ถอดออกตามที่ผู้ใช้สั่ง** — กลับไปใช้ 2 ช่องรวมเหมือนเดิม |

### เงื่อนไขการไฟฟ้า

ฟอร์มเขียน `(เฉพาะ MEA)` / `(เฉพาะ PEA)` ไว้ 5 แถว — ใช้ตัดแถวที่ไม่เกี่ยวออกจากหน้าจอ

| แถว | ใช้กับ |
|---|---|
| 2 · หนังสือยินยอมโครงการภาษี | MEA |
| 3 · หนังสือแจ้งข้อมูลบัญชีธนาคาร | MEA |
| 4 · สำเนาบัญชีธนาคารโอนค่าขายไฟ | MEA |
| 12 · หนังสือรับรองไฟฟ้า + ใบ กว. | MEA |
| 13 · หนังสือสภาวิศวกร + ใบ กว. | PEA |

ผลลัพธ์: **MEA เห็น 18 แถว · PEA เห็น 15 แถว** (นิติบุคคล 7 และ 6 ตามลำดับ)
ตัวนับจึงไปถึงเต็มได้จริง ซึ่งเดิมเป็นไปไม่ได้เพราะนับแถวของทั้งสองเจ้ารวมกัน

> **ไม่ผูกกับเจตนาขายไฟ** ฟอร์มเขียนว่าแถว 3–4 เป็น *MEA-ขายไฟ* แต่ตัดสินให้ดูแค่ MEA
> (2 ก.ย. 2026) หลวมกว่าฟอร์มเล็กน้อย แลกกับไม่ต้องผูกกับช่องเจตนาในแถว 5
>
> **ข้อมูลของแถวที่ถูกซ่อนไม่หาย** — ยังอยู่ใน JSON สลับการไฟฟ้ากลับมาก็เห็นครบ
> ทำได้เพราะ key ไม่มี prefix แล้ว (ดู §C.1) การซ่อนจึงกระทบแค่การแสดงผล

Checklist จะไม่แสดงเลยจนกว่าจะเลือก **ทั้งการไฟฟ้าและประเภทผู้ยื่น**

> **id 4 ตัวจงใจใช้ของเดิมที่แอปเคยใช้** (`latest_electricity_bill`, `tax_measure_consent`,
> `power_of_attorney`, `post_solar_house_registration`) เพราะเป็นเอกสารใบเดียวกัน
> ทำให้ติ๊กของ Lead เก่าจับคู่ได้ทันที — ตอนตั้ง id ใหม่รอบแรก ติ๊กเก่าของ 4 Lead หายไปจากหน้าจอ
> จนกระทั่งเปลี่ยนกลับ **ห้ามเปลี่ยน**

### ช่องกรอกในแถว

ฟอร์มกระดาษเขียนข้อมูลลงคอลัมน์หมายเหตุแบบมีโครง จึงทำเป็น field จริง

### C.1 Key ไม่มี prefix แล้ว

```diff
- "MEA:individual:id_card"     ← สลับ MEA↔PEA แล้วตัวนับกลับไป 0
```

### C.2 รูปร่างของแต่ละแถว

`grid_document_checklist` ยังเป็น `NVARCHAR(MAX)` เดิม เปลี่ยนแค่ shape ข้างใน

```jsonc
{
  "latest_electricity_bill": {
    "received": true,               // ตรวจรับหน้างาน (ช่องเดียวร่วมกัน)
    "permit": "has",                // "has" | "none" | null — ฝ่าย Permit ยืนยัน
    "note": "",
    "fields": { "ca_no": "0201234567890", "meter_size": "15_45", "voltage": "230", "phase": "1", "wire": "2" }
  },
  "power_of_attorney": { "fields": { "intent": "sell" } },
  "panel": { "received": true, "permit": "has", "datasheet": "has",
             "fields": { "brand": "JINKO", "watt": "640", "count": "16" } },
  // `files` ยังอ่านได้เผื่อข้อมูลเก่า แต่ไม่มี UI เขียนแล้ว
  "post_solar_house_registration": { "required": true }   // ชุดนิติบุคคลเท่านั้น
}
```

`owner` ไม่เก็บใน JSON — อยู่ในนิยามรายการที่ `gridTie.ts` (ตอนนี้ไม่ได้แสดงบนหน้าจอแล้ว)

### C.3 อ่านของเก่าได้ ไม่ต้อง migrate

`parseGridTieChecklist()` แปลงตอนอ่าน

```text
ตัดหัว "MEA:individual:" ทิ้ง  →  status === "received"  →  received: true, permit: "has"
```

ของเดิมมีสถานะชั้นเดียว ถ้าเคยติ๊กว่าได้รับแล้ว แปลว่าฝ่าย Permit ก็ได้เอกสารนั้นแล้ว
ถ้าข้อมูลเก่ามีทั้ง `MEA:` และ `PEA:` ของแถวเดียวกัน จะเก็บอันที่ติ๊กแล้วไว้

**ทั้งแผนนี้ไม่มี migration แม้แต่ไฟล์เดียว · ไม่แตะ schema เลย**

## D. สถานะ 2 ชั้น

```text
ตรวจรับหน้างาน (received)  ──▶  ฝ่าย Permit ยืนยัน (permit: has)
  ได้รับแล้ว | ยังไม่ได้รับ            มี | ไม่มี
  ช่องเดียวร่วมกันทั้งเซลล์          คนที่ยื่น MEA/PEA จริงติ๊ก
  และทีมติดตั้ง
```

- **ช่องตรวจรับมีช่องเดียว** ใครหยิบงานก่อนก็ติ๊กได้ ส่วน "งานของใคร" เป็นป้ายกำกับเท่านั้น
- ป้ายนับบนหัว Checklist: `ตรวจรับ 12/19` และ `Permit 9/19`
- **ทั้งสองชั้นเป็นข้อมูลติดตามงาน ไม่บล็อกการปิดงาน** — ดู §E

## E. เกณฑ์ปิดงาน — ไม่บังคับ checklist

```text
การไฟฟ้า · เลขที่คำขอ · เอกสารยื่นขอขนานไฟ · ใบอนุญาต/PPA
```

ถ้าบังคับให้ checklist ครบทุกแถวจะปิดงานไม่ได้เลย เพราะใบ กว. (MEA) กับ ใบ กส. (PEA)
ใช้ได้ทีละอัน สิ่งที่บังคับจึงเป็นหลักฐานปลายทางที่ต้องมีจริงทุกงาน

บังคับทั้งฝั่งหน้าจอและ server (409) เหมือนเดิม

**เป็นตารางเส้นเต็มแบบฟอร์มกระดาษ** — เซลล์ยืดเต็มความสูงแถวและมีเส้นคั่นทุกคอลัมน์
เส้นจึงลากต่อเนื่องตลอด ช่องกรอกย่อยอยู่ในคอลัมน์แรกใต้ชื่อเอกสาร

> เคยลองย้ายช่องกรอกลงแถวล่างที่กินเต็มความกว้าง เพื่อให้ทุกแถวสูงเท่ากัน แต่ทำให้
> เส้นคั่นแนวตั้งขาดเป็นช่วง ๆ (มีเฉพาะแถวบน) จึงกลับมาเป็นตารางจริง ยอมให้แถวสูงไม่เท่ากัน
> แลกกับเส้นที่ต่อเนื่อง — ผู้ใช้เลือกเอง 2 ก.ย. 2026

**ตรวจรับกับ Permit อยู่บนพื้นเทาอ่อนเดียวกัน** อ่านเป็น 3 โซน (เอกสาร → สถานะ → หมายเหตุ)
ส่วน **Datasheet ของแถวอุปกรณ์ย้ายไปคอลัมน์หมายเหตุ** ตามฟอร์ม และเปลี่ยนจาก checkbox
เป็นปุ่มคู่ มี/ไม่มี เพราะ checkbox แยก "ยังไม่ได้ตรวจ" ออกจาก "ไม่มี" ไม่ได้

**ช่องกรอกใช้เส้นประใต้ช่อง** เลียนภาษาของฟอร์มกระดาษที่ทีมถืออยู่ — เส้นประคือ
"ตรงนี้เขียน" ตอนคลิกเปลี่ยนเป็นเส้นทึบสี primary · placeholder เป็นตัวอย่างค่าจริง
(`เช่น 0201234567890`) ไม่ใช่คำว่า "ระบุ" ลอย ๆ · ไม่มีกรอบเส้นประรอบกล่องแล้ว
เพราะมันทำให้ดูเหมือนช่องที่ปิดใช้งาน

### สิทธิ์ — ไม่แยกตาม role

**ใครที่เปิด Step 07 ได้ ติ๊กได้ทั้งสองคอลัมน์** (ตัดสิน 2 ก.ย. 2026)

เคยออกแบบไว้ว่าจะให้เฉพาะฝ่าย Permit ติ๊กคอลัมน์ Permit ได้ แต่ผู้ใช้ยืนยันว่า
ไม่ต้องแยก — ทีมงานเล็กและ checklist ไม่ได้บล็อกการปิดงานอยู่แล้ว
การเพิ่มด่านสิทธิ์จึงมีแต่ทำให้ทำงานติดขัดโดยไม่ได้อะไรกลับมา
