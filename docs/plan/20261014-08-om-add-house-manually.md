# O&M — เพิ่มบ้าน/ลูกค้าใหม่เองจากหน้าจอ

ที่มา: ผู้ใช้ถาม 14 ต.ค. 69 "ถ้ามีลูกค้า O&M เข้ามาใหม่ เราจะสร้าง lead เองได้ไหม" → ตอนนั้นทำไม่ได้ถ้าไม่แก้โค้ด → ผู้ใช้สั่งทำแผน แล้วเลือก "ตามแนะนำ" ทุกข้อ

สถานะ: **เสร็จ 14 ต.ค. 69** (ตรวจบน solardb_v3 · ไม่มี migration)

## ก่อนทำติดอะไร

- lead ของ O&M (`leads.om_only = 1`) ไม่มีปุ่มสร้างเอง ระบบสร้างให้ตอนออกใบเสนอราคา O&M ใบแรก (`ensureOmLead` ใน `src/lib/om/om-quotation.ts`) แต่ต้องมีบ้านในทะเบียน O&M ก่อน
- บ้านเข้าทะเบียนได้ 3 ทาง: REM (`rem-reconcile.ts`) · งานขายที่ติดตั้งเสร็จ (`sales-sweep.ts`) · คิวจับคู่ (`/om/match-queue`)
  → ลูกค้าที่ไม่ได้ซื้อโซลาร์กับเรา (ติดตั้งโดยเจ้าอื่น / นอกโครงการเสนา) เข้าระบบไม่ได้เลย
- ปุ่ม "+ เพิ่มบ้าน" หน้า `/om/houses` ถูกเอาออก 25 ก.ย. 69 (ไม่เคยผูกคำสั่ง)
- ที่ผ่านมาใช้สคริปต์ครั้งเดียว (`scripts/tools/_tmp_create_k9bk2_190_191.mjs` · 9 ก.ย.) รันบน prod ไม่ได้

## การทำงาน

1. หน้า `/om/houses` กด **+ เพิ่มบ้าน** (ช่อง `actionLabel`/`onAction` ของ `ListPageHeader` — เห็นเฉพาะ role ทีม O&M)
2. Popup `OmNewHouseModal` (โครง `NewLeadModal` · ช่องกรอกชุดเดียวกับ modal ลูกค้า/บ้าน O&M) 3 ส่วน: ลูกค้า · บ้าน · ระบบโซลาร์ที่ติดอยู่
3. ระหว่างพิมพ์เช็คซ้ำ (`GET /api/om/houses/check`) — ท้าย popup บอก "ยังขาด: …" จนกว่าจะครบ
4. บันทึก (`POST /api/om/houses`) → ไปหน้างานบริการ `/om/services/<house id>` ทันที
5. ออกใบเสนอราคาที่นั่น → `ensureOmLead` สร้าง lead `om_only` ให้ (ไม่โผล่ pipeline ขาย · ไม่มี SLA ขาย) — **ไม่ต้องสร้าง lead เอง**

## สิ่งที่เจอระหว่างทำ (ต่างจากแผนแรก)

- **สร้างแถว `om_installations` ทุกครั้ง แม้ไม่กรอกสเปก** — ตอนจ่ายค่าแพ็กเกจ `grantPurchasedRights` เติมสิทธิ์ลงระบบติดตั้ง ไม่มีแถว = ข้าม ("no_install") ลูกค้าจ่ายแล้วไม่ได้สิทธิ์ · หน้างานบริการ (`follow-sql.ts`) ก็ต้องมีระบบติดตั้งถึงจะเห็นบ้าน
- **ผู้สร้าง + ที่มารายช่อง** ใช้ `om_field_sources` (source_kind `manual` · actor_user_id) แทนการเพิ่มคอลัมน์ — การ์ดระบบขึ้นป้าย "กรอกเอง" ให้เห็นว่าค่าไหนมาจากฟอร์ม
- **เปิดใช้บ้านเดิม** (บ้านในทะเบียน is_om = 0): เติมเฉพาะช่องว่าง ค่าที่ต่างจากของเดิมไม่เขียนทับ เก็บเป็น `probable` (การ์ดขึ้น "ไม่เขียนทับ" แบบไฟล์นำเข้า) · ที่มาของบ้านไม่เปลี่ยน (ยังเป็นทะเบียน)
- ลบบ้านถาวร (admin) เดิมไม่ลบ `om_field_sources` (ไม่มี FK) → เพิ่มบรรทัดลบใน `DELETE /api/om/houses/[id]`
- ไม่มีหน้าจอแก้สเปกระบบติดตั้งภายหลัง — ข้อความเตือนในฟอร์มจึงบอกว่า "พิมพ์ในใบเสนอราคาได้" (หัวรายการใบแก้ได้ · แผน 20261014-04) ไม่ได้บอกว่าเติมทีหลังได้
- ⚠ ข้อมูลเดิม: บ้าน is_om = 0 **25 หลัง** มีบ้านคู่ที่ is_om = 1 โครงการ + บ้านเลขที่เดียวกัน (เช่น 2/199 เสนา อเวนิว 1 รังสิต #13951 กับ #13983) — ฟอร์มถือว่า "มีในระบบแล้ว" (บ้านที่ active ชนะ) ไม่สร้าง/ไม่เปิดซ้ำ · ยังไม่ได้ล้างข้อมูลคู่นี้

## กันซ้ำ (`src/lib/om/manual-house.ts` ชุดเดียว ใช้ทั้ง check และตอนบันทึก)

- เทียบกับ `om_houses` ทุกแถว รวม is_om = 0 · บ้านเลขที่ตัดช่องว่าง (กติกา rem-reconcile)
- บ้านในโครงการซ้ำ: active → บล็อก + ลิงก์ "เปิดบ้านเดิม" · ถูกซ่อน → บล็อก + ปุ่ม "เปิดบ้าน" (เอากลับเข้าระบบจาก modal เดิม) · is_om = 0 → ปุ่มบันทึกเป็น "เปิดใช้บ้านเดิม"
- เบอร์ / เลขบัตรซ้ำ → ต้องกด "ใช้ลูกค้าคนนี้" ก่อน (ไม่สร้างคนซ้ำ) · ลูกค้าเดิมได้เบอร์/เลขบัตรใหม่เพิ่มถ้าไม่ใช่ของคนอื่น
- ตอนบันทึกเช็คซ้ำอีกรอบใน transaction (UPDLOCK/HOLDLOCK) → 409 + conflicts ให้ฟอร์มแสดง

## ตัวกรอง "ที่มา" (`house-origin.ts`)

B2C (งานขาย) → **เพิ่มเอง** (`project_map_source = 'om_manual'`) → ทะเบียน / REM / นำเข้า — ลำดับชนะจากซ้ายไปขวา ทั้งบ้านและลูกค้า ตัวเลขสามกลุ่มรวมกันเท่า "ทุกที่มา" (ตรวจแล้ว 1,829 = 1,829)
